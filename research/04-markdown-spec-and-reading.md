## 0. Термины и профили

**Plain Markdown flavor** — собственный диалект приложения. Определяется как один декларативный объект `FlavorSpec`, из которого генерируются: (а) `MarkdownConfig` для `@lezer/markdown` (редактор), (б) набор micromark/remark-расширений (семантический парсер), (в) правила сериализации, (г) тест-корпус. Один источник — три потребителя.

**Профили** (пресеты `FlavorSpec`, MD-046):

| Профиль | Состав | Назначение |
|---|---|---|
| `strict` | CommonMark 0.31.2, ничего сверх | отладка, проверка совместимости |
| `github` | + GFM (tables, tasklists, strikethrough, autolinks, footnotes, disallowed raw HTML) | файлы для GitHub |
| `obsidian` | `github` + wikilinks, embeds, callouts, `==`, `%%`, `$`, tags, block ids | vault Obsidian |
| **`plain` (default)** | `obsidian` + `^sup^`/`~sub~`, definition lists, abbreviations, emoji shortcodes, GitHub Alerts как алиас callouts | режим по умолчанию |

Три режима приложения (из макетов): **Read** (рендер HTML), **Edit** (исходник + подсветка), **Rich** (CodeMirror с декорациями: маркеры скрыты, кроме активного блока).

## 1. Поддерживаемый синтаксис — спецификация Plain Markdown flavor

### 1.1 Базовый слой

**MD-001. CommonMark 0.31.2 — базис.** Всё, что не переопределено ниже, парсится строго по 0.31.2. Никаких «улучшений» базовых правил. Причина: 0.31.2 — последняя версия, у неё есть исполняемый тест-корпус (652 примера), он входит в CI (TST-001).

**MD-047. Стек парсеров.**
- Редактор (Edit/Rich): `@lezer/markdown` — инкрементальный, интегрирован с CodeMirror 6, потребляет `TreeFragment` от предыдущего разбора.
- Семантика (Read-рендер, outline, word count, разрешение ссылок, backlinks): `unified` / `remark-parse` (micromark) → mdast с позициями.
- **Инвариант DOC-014:** множество распознаваемых конструкций у обоих парсеров идентично; CI-тест сравнивает границы top-level-блоков на всём корпусе. Расхождение = баг.

**MD-002. GFM tables.** `| a | b |` + delimiter-row. Выравнивание `:---`, `:---:`, `---:`. Экранирование `|` внутри ячейки — только `\|`; **важно: по GFM `\|` работает и внутри code span**, то есть `` `a\|b` `` даёт код `a|b`, а не `a\|b`. Строка данных с меньшим числом ячеек добивается пустыми, с бо́льшим — обрезается. Заголовок обязателен и число ячеек в нём должно совпадать с delimiter-row, иначе таблица не таблица.
Read: `<table>` в скролл-контейнере (RND-009). Edit: подсветка `|` и `:` цветом `--muted-soft`. Rich: живой рендер с редактируемыми ячейками (виджет-блок).
Совместимость: Obsidian ✓, GitHub ✓, Typora ✓. Round-trip риск: **высокий** — сериализатор переформатирует ширины столбцов. Решение: `tablePipeAlign: true`, `tableCellPadding: true`, `stringLength` = функция ширины в моноширинных ячейках (учёт East-Asian Width и emoji), чтобы выравнивание в исходнике совпало с тем, что видно в Plex Mono. Пере-выравнивать таблицу только при её собственном редактировании (DOC-018). **Вкл.**

**MD-003. Task lists.** `- [ ]`, `- [x]`, `- [X]`. Расширение: `- [-]`/`- [/]` как «отменено/в работе» — распознаём, но сериализуем обратно как есть (произвольный однобуквенный маркер сохраняется). Read: чекбоксы **кликабельны** (RND-019 + DOC-016). Edit: обычный текст. Rich: кликабельны.
Obsidian ✓ (произвольные маркеры), GitHub ✓ (только ` ` и `x`), Typora ✓. Round-trip: низкий риск. **Вкл.**

**MD-004. Strikethrough.** `~~text~~`. **Одинарный `~` отключить** (`singleTilde: false`), потому что одинарная тильда занята под `~sub~` (MD-014). Это отличие от github.com (там `~x~` тоже зачёркивает), но совпадает с буквой GFM-спеки. Предупреждение в линте при `~x~`, если профиль `github`.
Obsidian ✓, GitHub ✓ (с оговоркой), Typora ✓. **Вкл.**

**MD-005. Autolinks (literal).** `www.example.com`, `https://…`, `user@host`. Правило GFM: закрывающая пунктуация `.,:;!?` и несбалансированные `)` отсекаются от конца. Read: `<a>`. Edit: подсветка URL акцентом + underline (по макету 1c). Rich: кликабельно по Ctrl+клик.
Round-trip риск: **высокий** — если Rich превратит literal-autolink в `[text](url)`, диff огромный. **Решение: Rich никогда не переписывает literal-autolink в inline-link.** **Вкл.**

**MD-006. Footnotes.** `[^id]` в тексте, `[^id]: определение` блоком. Многострочные определения через отступ 4 пробела. Идентификатор: любые символы кроме пробелов и `]`, регистрозависим (как в GitHub). **В спеке GFM 0.29 footnotes отсутствуют** — реализация выравнивается на поведение cmark-gfm/github.com и `remark-gfm`.
Read: блок `<section class="footnotes">` внизу + popover по наведению (RND-018). Edit: `[^id]` подсвечен. Rich: сноска — inline-виджет с номером.
Obsidian ✓, GitHub ✓, Typora ✓ (MultiMarkdown-стиль). **Вкл.**

**MD-007. Disallowed Raw HTML (GFM).** GFM фильтрует `<title> <textarea> <style> <xmp> <iframe> <noembed> <noframes> <script> <plaintext>`. У нас это подмножество более жёсткой санитизации (SEC-002), отдельного тумблера не нужно. **Вкл. всегда, не отключаемо.**

**MD-042. Link reference definitions.** `[label]: url "title"`. Метки нормализуются: Unicode case-fold + свёртка пробелов. Read: определения не рендерятся. Edit: подсветка. Rich: определения показываются в конце документа как бледный блок «reference definitions», не удаляются.
Round-trip риск: **очень высокий** — сериализатор любит превращать `[x][ref]` в `[x](url)`. **Решение: reference-links неприкосновенны, Rich их не разворачивает.** **Вкл.**

**MD-043. Escapes и entity references.** `\` перед ASCII-пунктуацией; `&amp;`, `&#42;`, `&#x2A;`. Read: раскрываются. Edit: `\` подсвечен `--faint`. Rich: `\` скрыт декорацией, показывается при курсоре в блоке.
Round-trip риск: **критический** — `mdast-util-to-markdown` экранирует агрессивно (`a_b` → `a\_b`). Решение — DOC-019 (политика escape).

### 1.2 Front matter и метаданные

**MD-008. YAML front matter.** Только если файл начинается **точно** с `---` + перевод строки (после опционального BOM), закрывается строкой `---` или `...`. Парсер YAML — безопасный (SEC-011): без пользовательских тегов, без `!!js/*`, `!!python/*`, лимит глубины 32 и размера 256 KB.
- Не front matter, если `---` не в самой первой строке.
- `---` в первой строке без закрывающего разделителя = thematic break (по CommonMark), не front matter. Не «съедать» документ.
- TOML `+++` и JSON `{…}` front matter — **выкл.** по умолчанию, опция.

Read: не рендерится; из него берутся title/created/modified/tags/aliases/lang (META-008, META-010). Опция «показывать properties сверху» — таблица 11px `--muted`. Edit: показывается как есть, `---` цвета `--muted` (макет 1c). Rich: сворачиваемый блок-виджет «properties» с редактируемыми парами ключ-значение; **исходный YAML сохраняется побайтово, если ни одно поле не менялось** (DOC-018).
Obsidian ✓ (properties), GitHub ✓ (рендерит как таблицу), Typora ✓. **Вкл.**

### 1.3 Математика

**MD-009. Inline math `$…$`.** Правила разрешения конфликта с валютой (заимствованы у Pandoc, ужесточены):
1. За открывающим `$` **не** следует пробел/таб/перевод строки.
2. Перед закрывающим `$` **не** стоит пробел.
3. За закрывающим `$` **не** следует цифра.
4. Содержимое **не** содержит пустой строки и `$`.
5. Длина содержимого ≤ 1000 символов (защита от «съедания» абзаца).
6. `\$` — литеральный доллар, не делимитер.
7. `$` внутри code span/code block/URL/HTML-атрибута — никогда не делимитер.
8. Дополнительно (наше): если в абзаце нечётное число кандидатов-делимитеров, ни один не считается математикой.

Проверка на реальных случаях: `$5` (нет закрывающего) — текст ✓. `Цена $5 и $10` — правило 1 срабатывает на `$5 и $`? Нет: за открывающим `$` следует `5`, за закрывающим `$` следует `1` → правило 3 запрещает ✓. `от $5 до $10.` — правило 3 (`1`) ✓. `$100 — $200` — правило 3 не спасает (`—` не цифра), но правило 2 спасает: перед вторым `$` пробел ✓. Опасный остаток: `он взял $5, отдал $7` → перед закрывающим `$` пробел ✓. Реально пробивает `цена$x$` — редко.
9. Эвристика-предохранитель: если распознанная формула не парсится KaTeX без ошибок **и** состоит только из `[0-9.,\s\-—]`, откатить в текст.

Read: KaTeX inline. Edit: подсветка содержимого `--muted`, делимитеры `--faint`. Rich: рендер, при курсоре в узле — раскрытие в исходник.
Obsidian ✓, GitHub ✓ (с 2022), Typora ✓ (требует включения в настройках). **Вкл. по умолчанию, отключаемо** (MD-011).

**MD-010. Display math `$$…$$`.**
- **Блочная** формула: `$$` стоит в начале строки (допустимо ≤3 пробела отступа). Может быть на одной строке (`$$x$$`) или многострочной.
- `$$` в середине строки → трактуется как inline display (`displayMode: true`, но `<span>`), как в Obsidian.
- Внутри `$$…$$` правила 1–3 из MD-009 **не** применяются.
Read: `<div class="math-display">`, центрирование, горизонтальный скролл при переполнении (формула не ломает колонку 560px). Edit/Rich: как MD-009.
Obsidian ✓, GitHub ✓, Typora ✓. **Вкл.**

**MD-011. Тумблер математики.** `flavor.math: 'off' | 'inline+display' | 'display-only'`. `display-only` — безопасный режим для документов, где много валюты: `$$` работает, одинарный `$` — всегда текст. Индикация в статус-баре при первом срабатывании эвристики MD-009.9.

**MD-029. Fenced `math` блок.** ```` ```math ```` — GitHub-совместимый способ писать display-формулы без `$$`. Read: как MD-010. Round-trip: нулевой риск (это обычный fenced code с info-string). **Вкл.**

### 1.4 Инлайн-расширения

**MD-012. Highlight `==text==`.** Правила: `==` не должно быть единственным содержимым строки (иначе это setext-подчёркивание H1 — MD-039 **имеет приоритет**); внутри не должно быть пустой строки; работает как обычный delimiter-run (можно вкладывать `**==x==**`).
Read: `<mark>` с фоном `--mark-bg` (RND-029), **без** изменения цвета текста. Edit: `==` цвета `--faint`. Rich: маркеры скрыты.
Obsidian ✓, GitHub ✗ (рендерит как текст), Typora ✓ (опция). Round-trip: низкий. **Вкл.**

**MD-013. Superscript `^text^`.** Внутри — без пробелов (иначе экранировать `\ `). Не срабатывает, если `^` следует сразу за `[` (это footnote-reference MD-006) или стоит в начале строки после `>`/пробелов при непустом id (это block id MD-044).
Obsidian ✗ (нужен плагин), GitHub ✗, Typora ✓ (опция), Pandoc ✓. **Вкл.**, но профиль `github` его выключает.

**MD-014. Subscript `~text~`.** Одинарная тильда. Требует `singleTilde: false` для strikethrough (MD-004). Внутри — без пробелов.
Obsidian ✗, GitHub ✗ (там `~x~` = strikethrough — **прямой конфликт**), Typora ✓ (опция), Pandoc ✓.
Round-trip риск: **средний** — файл, отредактированный в нашем приложении и открытый на GitHub, покажет `H~2~O` как `H<del>2</del>O`. Решение: линт-предупреждение «`~x~` рендерится по-разному в GitHub», опция `flavor.subSup: false` в профиле `github`. **Вкл. в `plain`, выкл. в `github`.**

**MD-024. Emoji shortcodes `:smile:`.** Словарь GitHub (~1900 имён) + Unicode CLDR-алиасы. Правила: `:` не внутри слова; имя `[a-z0-9_+-]{1,50}`; неизвестное имя — оставить как текст.
Read: подстановка Unicode-глифа. Edit: текст. Rich: замена на глиф, при курсоре — исходник.
Obsidian ✓ (частично), GitHub ✓, Typora ✓. Round-trip риск: **высокий** — если Rich запишет глиф вместо `:smile:`, исходник изменится. **Решение: подстановка — только render-time, исходник никогда не переписывается.** **Вкл.**

**MD-023. Abbreviations (PHP-Markdown-Extra).** `*[HTML]: HyperText Markup Language` — определение; все вхождения `HTML` в тексте оборачиваются в `<abbr title>`. Правила: сопоставление по точному регистру, только по границам слова, не внутри code/link/heading.
Obsidian ✗, GitHub ✗, Typora ✗. Round-trip риск: нулевой (render-time). **Выкл. по умолчанию** (низкий спрос, шумит на аббревиатурах вроде «США»); включается в настройках.

**MD-022. Definition lists (PHP-Markdown-Extra / Pandoc).**
```
Термин
: определение
: второе определение
```
Правила: строка-термин без отступа, следующая строка начинается с `:` + 1–3 пробела; допускается пустая строка между термином и `:` (loose-вариант, `<p>` внутри `<dd>`).
Read: `<dl>/<dt>/<dd>`, `dd` с `padding-left: 22px` (как ordered list), `dt` весом 500. Edit: `:` цвета `--muted-soft`. Rich: **редактируется как исходник** (не делаем виджет).
Obsidian ✗, GitHub ✗ (`: x` останется абзацем), Typora ✗. Round-trip риск: **высокий** — если наш парсер видит `<dl>`, а сериализатор его не умеет, блок исчезнет. Решение: собственный `toMarkdown` handler для `definitionList`/`definitionTerm`/`definitionDescription` + тест на идемпотентность. **Выкл. по умолчанию**, включается в настройках; при включении — линт «не отображается в Obsidian/GitHub».

### 1.5 Ссылки Obsidian-стиля

**MD-015. Wikilink `[[target]]`.** `target` = путь без расширения (или с `.md`), разрешается по правилу «shortest path that is unique» с фолбэком на относительный, затем абсолютный от корня vault. Запрещённые символы в target: `#`, `|`, `^`, `[`, `]`, `:`, `%%`. Разрешение регистронезависимое на Windows, но с предупреждением при неоднозначности.
Read: `<a class="internal">` с текстом = target (basename, если путь). Несуществующий файл → класс `unresolved`, цвет `--muted`, без underline, tooltip «файл не найден · создать». Edit: `[[`/`]]` цвета `--muted-soft`, содержимое `--fg`. Rich: маркеры скрыты, hover-preview (RND-017).
Obsidian ✓, GitHub ✗ (голый текст), Typora ✗. **Вкл.**

**MD-016. Alias `[[target|alias]]`.** Alias может содержать пробелы и Unicode, но не `]]`. **Внутри таблицы GFM `|` конфликтует** — требуется `\|` или использовать markdown-ссылку. Линт предупреждает. **Вкл.**

**MD-017. Заголовок `[[target#Heading]]`, `[[#Heading]]`, `[[target#A#B]]`.** Разрешение по **тексту заголовка**, не по slug: NFC-нормализация + case-fold + свёртка внутренних пробелов + удаление inline-разметки. Многосегментный `#A#B` = «B внутри A». **Вкл.**

**MD-018. Блок `[[target#^blockid]]`.** См. MD-044. **Вкл.**

**MD-044. Block identifiers `^id`.** `^` + `[a-zA-Z0-9-]{1,64}` в конце последней строки блока, отделён пробелом. Read: не рендерится (только как цель якоря); при hover на блоке — кнопка «copy block link». Edit: `--faint`. Rich: скрыт декорацией.
Round-trip риск: средний — сериализатор не знает про `^id`. Решение: `^id` — часть mdast-узла (`data.blockId`), собственный handler. **Вкл.**

**MD-019. Embed `![[target]]`.** Встраивание содержимого.
- `.md` → рендер документа целиком; `![[note#Heading]]` → только секция; `![[note#^id]]` → только блок.
- Изображение/PDF/аудио/видео → соответствующий элемент.
- Глубина вложенности ≤ 4, обнаружение циклов обязательно (TST-042), при цикле — плашка «circular embed».
Read: рендерится; вставленный блок помечен левой линией 1px `--border` и лейблом-источником 10.5px `--muted` (в стиле callout, без иконок). Edit: текст. Rich: сворачиваемый read-only виджет — **редактирование внутри embed запрещено** (иначе неясно, какой файл править).
Obsidian ✓, GitHub ✗, Typora ✗. **Вкл.**

**MD-020. Размер изображения `![[image.png|300]]` / `|300x200`.** `|N` = ширина в px, `|WxH` = ширина×высота. Также поддерживаем Obsidian-совместимый вариант для markdown-изображений: `![alt|300](img.png)`.
Read: `width` в px, `max-width: 100%` всегда побеждает (RND-010). **Вкл.**

### 1.6 Блочные расширения

**MD-021. Callouts (Obsidian) и Alerts (GitHub) — единая реализация.**
Синтаксис: первая строка blockquote = `[!type]` + опциональный `+`/`-` (fold) + опциональный заголовок.
```
> [!note] Свой заголовок
> тело
```
- Тип регистронезависим: `[!NOTE]` (GitHub) и `[!note]` (Obsidian) — одно и то же.
- Типы: `note, abstract|summary|tldr, info, todo, tip|hint|important, success|check|done, question|help|faq, warning|caution|attention, failure|fail|missing, danger|error, bug, example, quote|cite`. GitHub-набор `NOTE/TIP/IMPORTANT/WARNING/CAUTION` полностью покрывается алиасами.
- Неизвестный тип → стиль `note`, лейбл = сам тип.
- `+` развёрнут, `-` свёрнут; без символа — не сворачивается.
- Вложение через `>>`.

Read (по дизайн-системе — **иконок нет**): контейнер без фона, `border-left: 1px solid var(--border)`, `padding-left: 18px`; лейбл — 10.5px, uppercase, `letter-spacing: .12em`, `color: var(--muted)`, `margin-bottom: 8px`; тело — **прямой шрифт** (не italic), `color: var(--fg)`. Это визуально отделяет callout от обычной цитаты (та — italic + `border-left: 1px var(--fg)` + `--quote`). Свёрнутый: показан только лейбл + `▸`.
Edit: `[!type]` цвета `--muted`. Rich: лейбл — редактируемое поле, тип — из выпадающего списка.
Obsidian ✓, GitHub ✓ (только 5 типов, без своих заголовков и fold), Typora ✗ (обычная цитата). Round-trip риск: низкий (это blockquote). **Вкл.**

**MD-025. Теги `#tag`.** Правила:
1. `#` в начале строки, за которым **пробел** → ATX-заголовок (CommonMark), не тег. `#tag` в начале строки заголовком **не является** (CommonMark требует пробела) → это тег. Конфликта нет.
2. Перед `#` — начало строки, пробел, или один из `([{"'«—–-`.
3. Тело: `[\p{L}\p{N}_/-]+`, ≥1 символ, **обязан содержать хотя бы одну букву** (`#2026` — не тег, `#q4` — тег).
4. `/` создаёт иерархию: `#проект/дизайн`.
5. Не тег: внутри code span/code block, внутри URL (фрагмент `page#section`), внутри `[]()`-цели, внутри math, внутри HTML-атрибута, внутри front matter (там теги — отдельное поле).
6. Кириллица разрешена (`#заметки`), эмодзи — нет.
Read: `<a class="tag">` цвета `--muted`, без underline; клик = поиск по тегу. Edit: `--muted`. Rich: то же.
Obsidian ✓, GitHub ✗, Typora ✗. Round-trip: нулевой. **Вкл.**

**MD-026. Комментарии `%% … %%`.** Inline (`a %%скрыто%% b`) и блочные (многострочные). Не работают внутри code.
Read: **не рендерятся** (по умолчанию); опция «показывать комментарии» → блок `--faint` italic. Edit: `--faint`. Rich: **свёрнутая метка `%%` цвета `--faint`**, раскрывается по клику — нельзя молча прятать текст, который пользователь может потерять.
Obsidian ✓, GitHub ✗ (видны), Typora ✗. **Вкл.**

**MD-027. HTML-комментарии `<!-- -->`.** Read: не рендерятся. Edit/Rich: как MD-026. **Никогда не обрабатывать регулярками** (SEC-009). **Вкл.**

**MD-028. Fenced `mermaid`.** ```` ```mermaid ```` → диаграмма (RND-022). Ошибка парсинга mermaid → показать исходный код в code block + строка ошибки 11px `--muted`, **не ронять рендер документа**.
Obsidian ✓, GitHub ✓, Typora ✓. **Вкл.**

### 1.7 HTML

**MD-030. Inline HTML.** Разрешённые теги (пересечение с санитайзером SEC-002): `a b br code del em i img ins kbd mark q s samp small span strong sub sup u var abbr time wbr`. Всё остальное — экранируется и показывается как текст (не выбрасывается молча).
Read: рендер после санитизации. Edit: подсветка как разметки. Rich: **атомарный inline-виджет**, редактируется только как исходник при курсоре внутри.
Важно: **Obsidian не рендерит markdown внутри HTML-элементов** — воспроизводим это поведение для совместимости (иначе `<div>**bold**</div>` отображается по-разному). **Вкл.**

**MD-031. Block HTML.** Разрешённые: `div p blockquote pre ul ol li dl dt dd table thead tbody tfoot tr th td figure figcaption details summary hr h1..h6 picture source`. Запрещённые всегда: `script style iframe frame frameset object embed applet form input(кроме checkbox) button select textarea link meta base title svg math`.
Read: санитизация обязательна. Edit: подсветка. Rich: **непрозрачный блок-виджет** «HTML» — раскрывается в исходник по клику, **никогда не пересериализуется из DOM**. Это ключевое решение против round-trip-потерь.
Опция `flavor.html: 'sanitized' | 'escaped' | 'off'`; default `sanitized`. **Вкл.**

### 1.8 Переводы строк и типографика

**MD-032. Hard line breaks.** Три формы:
- Два+ пробела в конце строки (CommonMark, GitHub, Obsidian, Typora — универсально).
- `\` в конце строки (CommonMark ✓, GitHub ✓, Obsidian ✗ — **несовместимо**).
- `<br>` (везде ✓, но HTML).
Read: все три → `<br>`. Edit: **обязательная визуализация** — trailing-пробелы рендерятся глифом `⏎` цвета `--faint` (иначе они невидимы и теряются). Rich: Shift+Enter вставляет форму по настройке.
Round-trip риск: **критический** — любой «trim trailing whitespace» уничтожает hard break. **Решение: DOC-023 — автотрим trailing whitespace выключен по умолчанию и физически не может тронуть строку, оканчивающуюся ровно двумя пробелами.**
Настройка `hardBreakStyle`: `'two-spaces'` (**default** — максимальная совместимость) | `'backslash'` (видимо в исходнике, но ломает Obsidian) | `'br'`.

**MD-033. Опция «Enter = `<br>`» (мягкие переносы).** `renderSoftBreaks`: `'space'` (**default**, CommonMark: одиночный `\n` = пробел) | `'br'` (Obsidian с выключенным «strict line breaks», Typora по умолчанию).
Это **только render-time** — исходник не меняется. В статус-баре индикатор при `'br'`, потому что документ будет выглядеть иначе на GitHub. Read/Rich учитывают настройку одинаково; Edit не затрагивается.

**MD-034. Smart punctuation.** `--` → –, `---` → —, `...` → …, `"x"` → «x»/“x”, `'x'` → ‘x’, `<<`/`>>` → «».
**Решение: только render-time в Read. Исходник не переписывается никогда** — иначе (а) round-trip ломается, (б) в diff-ах git появляются невидимые изменения, (в) в кириллице «умные» кавычки зависят от языка.
Правила: не применять внутри code span/block, math, URL, HTML, autolink, front matter, wikilink-target. Язык берётся из front matter `lang`, иначе — эвристика по доле кириллицы (>30% → ru): ru → «ёлочки» внешние, „лапки“ внутренние, тире `—` с неразрывным пробелом слева; en → curly quotes, em dash без пробелов.
Default: **выкл.** (минимализм = показывать то, что написано). Опция в настройках.

**MD-035. Heading slugs.** Алгоритм, совместимый с `github-slugger`:
1. Убрать inline-разметку (`**x**` → `x`), сохранить текст.
2. Удалить эмодзи и большинство пунктуации.
3. Lowercase (Unicode, с учётом кириллицы: `Как` → `как`).
4. Пробелы → `-`.
5. **Не-ASCII сохраняются**: `## Как читать` → `как-читать`; `## Привет non-latin 你好` → `привет-non-latin-你好` (проверено по README github-slugger).
6. Дубликаты: `foo`, `foo-1`, `foo-2`.
7. При выводе в HTML `id` получает префикс `user-content-` (SEC-008); внутренняя навигация по якорям добавляет префикс сама.
Два независимых пути разрешения (MD-017): markdown-ссылка `[x](#slug)` — по slug; wikilink `[[note#Заголовок]]` — по нормализованному тексту.

### 1.9 Списки, заголовки, код

**MD-036. Таблицы: выравнивание и escape.** См. MD-002. Дополнительно: выравнивание в Read через `text-align`; в моноширинном наборе колонки **не** получают фиксированную ширину — `table-layout: auto` + `min-width: max-content` внутри скролл-контейнера (RND-009).

**MD-037. Вложенные списки и lazy continuation.** Строго по CommonMark: содержимое элемента списка выравнивается по позиции после маркера + пробел(ы); lazy continuation (продолжение абзаца без отступа) разрешено. Известная ловушка: список с маркером `-` и 1 пробелом даёт отступ содержимого 2, а `1.` + пробел — 3; смешение приводит к неожиданному вложению.
Edit: **вертикальные indent-guide линии 1px `--faint`** на каждый уровень отступа — единственный способ увидеть проблему в моно-наборе.
Round-trip: `listItemIndent` **выводится из документа** (DOC-018), не берётся из дефолта `'one'`.

**MD-038. Ordered list `start`.** `5. item` → `<ol start="5">`. Последующие номера в исходнике игнорируются CommonMark'ом, но сохраняются побайтово. `incrementListMarker` выводится из документа: если все маркеры `1.` — сериализуем `1.`; если возрастают — возрастающими. Также поддерживается `)` как разделитель (`1)`), `bulletOrdered` выводится.

**MD-039. Setext headings.** `Заголовок\n===` и `\n---`. Парсинг — **вкл.** (спека). Генерация — **никогда** (`setext: false`), **кроме** случая, когда правится существующий setext-заголовок: тогда его форма сохраняется (DOC-018). Опасность: строка `---` после абзаца = H2, а не thematic break; в Edit подсвечиваем такие `---` как заголовок (вес 600), а не как разделитель, — иначе пользователь не поймёт, что происходит.

**MD-040. Indented code blocks (4 пробела).** Парсинг — **вкл.** (обязательно по CommonMark 0.31.2; отключение сломает совместимость с чужими файлами). Генерация — **никогда** (`fences: true`).
Проблема: пользователи отбивают текст 4 пробелами «для красоты» и получают code block. Митигация: линт-подсказка в Edit «этот блок распознан как код; сделать fenced?» + однокликовая конверсия. Опция `flavor.indentedCode: false` — есть, но по умолчанию **включено**; при выключении в статус-баре постоянный индикатор «non-standard».

**MD-041. Tabs vs spaces.** Парсинг строго по CommonMark: таб продвигает до следующей позиции, кратной 4. Edit: `tab-size: 4`, таб визуализируется точкой `·` цвета `--faint` при включённой опции «show whitespace». Ввод: `Tab` вставляет по настройке (`'tab' | 2 | 4`, default `2 spaces`), но **существующие табы не конвертируются** при сохранении. Смешанные отступы — линт-предупреждение (TST-016).

## 2. Рендер для чтения (Read view)

### 2.1 Метрика моноширинного набора — расчёты

**RND-001. Ширина колонки в символах.**
Advance IBM Plex Mono = 0.6 em (измерено). При `font-size: 13.5px` → **8.1 px на символ**.
- Колонка чтения 560 px: `560 / 8.1 = 69.14` → **69 символов** (69 симв. = 558.9 px, зазор 1.1 px). Попадает в канонический диапазон 45–75 (Bringhurst) и в верхнюю треть 66-символьного идеала.
- Code block 12 px, внутренняя ширина `560 − 16·2 = 528` px, advance 7.2 px → `528 / 7.2 = 73.33` → **73 символа**. Это ровно те 72–80, к которым привыкли в коде (PEP8=79, black=88 не влезет — см. RND-013 «wrap»).
- Edit view 13 px, текстовая колонка `640 − 40 − 24 = 576` px, advance 7.8 px → `576 / 7.8 = 73.85` → **73 символа**.
- Callout/blockquote (отступ 18 px): `542 / 8.1 = 66.9` → **66 символов**.
Справочно: 66 симв. = 534.6 px, 72 симв. = 583.2 px, 80 симв. = 648 px.
**Требование:** `--measure-read: 560px` фиксировано; при ширине окна < 560 + 2·24 колонка сжимается до `calc(100vw - 48px)`.

**RND-002. Вертикальная метрика.**
Content box шрифта = `(1025 + 275) / 1000 = 1.30 em` = 17.55 px при 13.5 px. `line-height: 1.75` = **23.625 px**; half-leading = `(23.625 − 17.55) / 2 = 3.04 px` сверху и снизу. x-height = 0.516 em = **6.97 px**; cap-height = 0.698 em = **9.42 px**.
Следствие: соотношение x-height/line-height = 0.295 — очень «воздушный» набор, что для моно правильно (моно шире, нужен больший интерлиньяж). Code block: `12 × 1.6 = 19.2 px`. H1: `22 × 1.3 = 28.6 px`.
Базовая сетка 23.625 px **не** используется как жёсткий grid (это сломает отступы из макета); вместо неё — шкала интервалов RND-004.

### 2.2 Заголовки

**RND-003. Шкала h1–h6 в моноширинном наборе.** Макет задаёт только H1 (22/600) и H2 (13.5/600 muted). Достраиваем без введения новых кеглей — иерархия несётся **весом, цветом, отбивкой и трекингом**, а не размером (в моно размерные ступени читаются плохо и рвут ритм колонки).

| | size | weight | color | letter-spacing | transform | margin (top / bottom) |
|---|---|---|---|---|---|---|
| h1 | 22px | 600 | `--fg` | −0.01em | — | 0 / 26px |
| h2 | 13.5px | 600 | `--muted` | 0 | — | 30px / 14px |
| h3 | 13.5px | 600 | `--fg` | 0 | — | 26px / 10px |
| h4 | 13.5px | 500 | `--fg` | 0 | — | 22px / 8px |
| h5 | 11.5px | 600 | `--muted` | .12em | uppercase | 20px / 6px |
| h6 | 11.5px | 400 | `--muted` | .12em | uppercase | 18px / 6px |

**Известный риск:** h2 (muted) визуально «слабее» h3 (fg) — иерархия по цвету инвертирована. Обоснование: h2 отбит 30 px сверху и читается как **метка секции**, h3 стоит вплотную к своему тексту. В моно-наборе разделительное пространство — более сильный сигнал уровня, чем насыщенность.
**Митигации (обязательные):** (1) `RND-003a` — маркеры уровня в левом поле Read, как в Rich (макет 1d): `#`, `##`, `###` на `left: -40px`, ширина 24 px, right-aligned, 11 px, `--faint`, `user-select: none`; включаются опцией `showHeadingMarkers` (default **вкл.** при ширине окна ≥ 900 px). (2) Настройка `headingEmphasis: 'space' | 'contrast'`; `'contrast'` меняет h2 на `--fg` и h3 на `--muted`.

**RND-023. Heading anchor copy.** При hover на заголовке — глиф `#` в правом поле (`right: -28px`), 11 px, `--faint` → `--fg` на hover; клик копирует ссылку `[[file#Заголовок]]` (Ctrl+клик — `#slug`). Без иконок, без анимации. `aria-label` обязателен.

### 2.3 Блоки и ритм

**RND-004. Шкала интервалов** (только эти значения, взяты из макета): `6, 8, 10, 14, 18, 20, 22, 26, 30, 36`. Никаких промежуточных.

**RND-005. Параграф.** 13.5/1.75, `margin: 0 0 20px`. `overflow-wrap: anywhere` + `word-break: normal` — длинное слово/URL не расширяет колонку (TST-034). Переносы (`hyphens`) — **выкл.** (моно + hyphens = каша).

**RND-006. Списки.**
- `ul`/`ol`: `padding-left: 22px`, `margin: 0 0 20px`, между пунктами `gap: 6px` (через `li + li { margin-top: 6px }`).
- Маркер `ul`: `·` (middle dot) `--muted-soft`, **не** `•` (в моно `•` слишком тяжёлый). Уровень 2 — `–`, уровень 3 — `·` снова.
- `ol`: цифра + `.`, цвет `--muted`, `font-variant-numeric: tabular-nums` (в Plex Mono уже моно, но явно).
- Вложенность: `padding-left: 22px` на каждый уровень; отступ ровно 22 px, чтобы в моно совпасть с ~2.7 символа — визуально «ступенька».
- Tight vs loose по CommonMark: loose-список получает `p { margin-bottom: 10px }` внутри `li`.
- Task list: `li.task` — `list-style: none`, `margin-left: -22px`, чекбокс — квадрат 11×11 px, `border: 1px solid var(--muted-soft)`, без скругления; отмеченный — заливка `--fg`, галочка `--bg`. Текст выполненного пункта: `--muted`, **без** `line-through` (опция).

**RND-007. Цитаты и вложенные цитаты.**
- `blockquote`: `padding-left: 18px`, `border-left: 1px solid var(--fg)`, `font-style: italic`, `color: var(--quote)`, `margin: 0 0 20px`.
- Вложенная (`blockquote blockquote`): `border-left-color: var(--muted-soft)`, `padding-left: 18px` (накопительно), `font-style: normal` на 2-м уровне (иначе italic-in-italic нечитаем в моно), 3-й уровень — снова italic. Максимум различимых уровней — 3; глубже показываем счётчик `›4` 10 px `--faint`.
- Опция `quoteStyle: 'italic' | 'upright'` — длинные цитаты курсивом в моно тяжелы; default `italic` (по макету).

**RND-008. Callouts.** См. MD-021. CSS: `border-left: 1px solid var(--border)`, `padding-left: 18px`, `margin: 0 0 20px`; лейбл `.callout-label { font-size: 10.5px; text-transform: uppercase; letter-spacing: .12em; color: var(--muted); margin-bottom: 8px }`; тело — `--fg`, `font-style: normal`. Сворачиваемый — лейбл получает `▸`/`▾` слева (11 px, `--faint`), `cursor: pointer`, `aria-expanded`.

**RND-020. Thematic break.** `hr { border: 0; border-top: 1px solid var(--border); margin: 30px 0 }`. Без «звёздочек», без центрирования.

### 2.4 Таблицы

**RND-009. Таблицы и переполнение.**
```
.md-table-scroll { overflow-x: auto; margin: 0 0 20px; }
table { border-collapse: collapse; table-layout: auto; min-width: max-content; font-size: 12.5px; line-height: 1.6; }
th, td { padding: 7px 12px; border-bottom: 1px solid var(--border); text-align: left; vertical-align: top; }
th { font-weight: 600; color: var(--muted); font-size: 11px; text-transform: uppercase; letter-spacing: .08em; }
tbody tr:last-child td { border-bottom: 0; }
```
- **Скролл живёт внутри контейнера**, не в теле страницы (`body` никогда не скроллится горизонтально).
- Индикатор обрезки: тень-градиент справа/слева (`background-attachment: local` трюк) — но при `prefers-reduced-motion` и в минималистичной эстетике вместо тени используем **вертикальную линию 1px `--border`** на краю контейнера, появляющуюся только при наличии скролла.
- Скроллбар: `scrollbar-width: thin`, `scrollbar-color: var(--faint) transparent`.
- Выравнивание из delimiter-row применяется к `th` и `td` одного столбца.
- Опция `tableWrap: 'scroll' | 'wrap'`; `wrap` снимает `min-width: max-content` — для узких окон.

### 2.5 Изображения

**RND-010. Изображения.** `img { max-width: 100%; height: auto; display: block; margin: 0 auto 8px }`. Явные размеры из MD-020 ставятся как `width`, но `max-width: 100%` их перекрывает. Обязательны `width`/`height`-атрибуты из реальных размеров файла (через Rust-сторону) — иначе layout прыгает и ломается reading progress.
Подпись: `alt` → если пустой, `title`; рендерится в `<figcaption>` 11 px `--muted`, `text-align: center`, `margin-bottom: 20px`. Если и `alt`, и `title` пусты — подписи нет, `<figure>` не создаётся.
Битая ссылка: плашка `--surface`, высота 60 px, текст 11 px `--muted` с именем файла — не «сломанная иконка».

**RND-011. Lightbox.** Клик по изображению → полноэкранный оверлей `--bg` с `opacity`-фоном (как модал quick search: подложка `opacity .35`). Zoom колесом, pan drag, `Esc` — закрыть, `←/→` — соседние изображения документа. Без анимаций при `prefers-reduced-motion`; иначе fade 120 ms.

**RND-012. Lazy loading.** `loading="lazy"` + `decoding="async"` для всех изображений вне первого экрана. Для локальных — предзагрузка размеров, чтобы не было CLS. Внешние — см. SEC-005 (по умолчанию не грузятся вовсе).

### 2.6 Код

**RND-013. Chrome code block.**
```
.code { position: relative; background: var(--surface); padding: 14px 16px; font-size: 12px; line-height: 1.6; white-space: pre; overflow-x: auto; margin: 0 0 20px; border: 0; border-radius: 0; }
```
- **Лейбл языка**: 10 px, uppercase, `letter-spacing: .12em`, `--muted`, абсолютно позиционирован `top: 6px; right: 12px`; показывается только при hover **или** когда включена опция `alwaysShowLangLabel`. Info-string `js`, `ts`, `python` → отображается как есть, lowercase→uppercase.
- **Copy**: текстовая кнопка `copy` 10 px `--muted` рядом с лейблом, при hover → `--fg`; после нажатия текст меняется на `copied` на 1.2 с. Без иконки. Копируется исходный текст блока **без** номеров строк и без trailing newline-нормализации.
- **Номера строк**: опция (default **выкл.** в Read, **вкл.** в Edit по макету 1c). Реализация — `counter-increment` на `.line`, `::before` с `--line-number`, `user-select: none`, ширина `3ch` right-aligned, `margin-right: 16px`.
- **Wrap**: опция (default выкл.). При `wrap` — `white-space: pre-wrap; overflow-wrap: anywhere`, и перенесённые строки получают `text-indent: -2ch; padding-left: 2ch` (висячий отступ), чтобы продолжение читалось как продолжение.
- Fallback без языка / язык не поддержан: без подсветки, только `--code-fg`.
- Inline `code`: `background: var(--surface); padding: 0 4px; font-size: inherit` — **не** уменьшать кегль (в моно inline-код и текст один шрифт, разница в кегле рвёт строку).

**RND-014. Shiki-тема «plain-mono» (3 серых + акцент).** Собственная TextMate-тема с 5 цветами, генерируется из токенов; `themes: { light: 'plain-light', dark: 'plain-dark' }` + `defaultColor: false`, дальше CSS-переменные Shiki (`--shiki-dark`) переключаются классом `html[data-theme=dark]` с `!important`.

### 2.7 Ссылки

**RND-015. Ссылки.** `a { color: var(--fg); text-decoration: underline; text-decoration-color: var(--accent); text-underline-offset: 3px; text-decoration-thickness: 1px; }`. Hover: `text-decoration-thickness: 2px` (не смена цвета — акцент уже занят). `:focus-visible { outline: 1px solid var(--accent); outline-offset: 2px }`.
Контраст подчёркивания как нетекстового индикатора: light `#7c3aed` на `#f7f6f3` = **5.27:1**, dark `#a78bfa` на `#141413` = **6.77:1** — оба ≥ 3:1 ✓.

**RND-016. Внешние ссылки.** Индикатор — **не иконка**: после текста ссылки `::after { content: "↗"; font-size: .85em; color: var(--muted); margin-left: 2px; text-decoration: none }`. Только для схем `http(s)` с хостом ≠ локального. Опция `externalLinkMarker` (default вкл.). Домен показывается в статус-баре при hover (11 px `--muted`), не в tooltip.

**RND-017. Внутренние ссылки: hover preview.** Задержка 320 ms, панель 320×220 px, `--bg-elevated`, `border: 1px solid var(--border)`, без тени и скругления; внутри — заголовок 12.5 px + первые ~40 строк рендера, `mask-image: linear-gradient(to bottom, #000 70%, transparent)`. Ctrl удерживает панель. Не показывать при `prefers-reduced-motion`? — показывать, но без fade. Нерезолвнутые ссылки preview не имеют.

**RND-018. Footnotes.** Ссылка `[^1]` → `<sup><a>` 10.5 px `--accent-strong`, без underline. Определения — секция внизу, отделённая `hr`, заголовок «notes» 10 px uppercase `--muted`, текст 12.5 px. Обратная ссылка — `↩` `--muted`.
Popover: hover на `[^1]` → та же панель, что RND-017, но по содержимому сноски; 240 ms задержка. Клавиатура: `Enter` на ссылке — переход + фокус на определении.

### 2.8 Формулы и диаграммы

**RND-021. KaTeX.** v0.18.5. `throwOnError: false` (ошибка рендерится красным текстом формулы, документ не падает), `trust: false` (запрещает `\href`, `\url`, `\includegraphics` — SEC-012), `maxSize: 25`, `maxExpand: 500`, `strict: 'ignore'`, `output: 'html'` (не MathML+HTML — вдвое меньше DOM).
**Проблема совместимости шрифта:** KaTeX подставляет `KaTeX_Main`/`KaTeX_Math` (Computer Modern), которые радикально отличаются от Plex Mono по цвету полосы и x-height (CM x-height ≈ 0.43 em против 0.516 у Plex Mono). Меры:
1. `.katex { font-size: 1.06em }` — компенсация меньшего x-height, формула визуально совпадает по «росту» с окружающим текстом.
2. `.katex .mord.text, .katex .textrm` наследуют `--font-mono` — текстовые вставки `\text{…}` остаются в Plex Mono.
3. Цвет: `.katex { color: var(--fg) }` — KaTeX не задаёт цвет сам.
4. Шрифты KaTeX ставятся локально (SEC-004), `font-display: block` (штатно), директория `fonts/` рядом с `katex.min.css` обязательна.
5. Display-формула шире 560 px → `.katex-display { overflow-x: auto; overflow-y: hidden; padding: 2px 0 }`.
Альтернатива к оценке: `\usepackage`-подобная замена на `mathfont` из Plex Math — **не** делать, Plex Math не существует.

**RND-022. Mermaid.** v11.17.2. `startOnLoad: false`, ручной `mermaid.render(id, code)` для каждого блока в viewport. `securityLevel: 'strict'` (санитизация меток), **не** `'sandbox'` — sandbox использует iframe, а iframes запрещены (SEC-006). Результирующий SVG дополнительно прогоняется через DOMPurify с профилем SVG (SEC-007).
Тема — серая, через `theme: 'base'` + `themeVariables`:
```
{ background: 'transparent', primaryColor: 'var→--surface', primaryTextColor: '--fg',
  primaryBorderColor: '--muted-soft', lineColor: '--muted-soft', secondaryColor: '--surface-2',
  tertiaryColor: '--bg', fontFamily: "'IBM Plex Mono', monospace", fontSize: '12px',
  nodeBorder: '--muted-soft', clusterBkg: 'transparent', clusterBorder: '--border',
  edgeLabelBackground: '--bg', titleColor: '--fg' }
```
(значения подставляются как реальные hex при инициализации — mermaid не понимает `var()`; при смене темы — полный ре-рендер всех диаграмм).
`flowchart: { curve: 'linear' }` — прямые линии вместо безье, в духе макета. `useMaxWidth: true` + внешний `overflow-x: auto`. Ленивый импорт mermaid (≈ 500 KB gzip) — **только** если в документе есть блок `mermaid`.

### 2.9 Доступность, движение, производительность

**RND-024. `prefers-reduced-motion: reduce`.** Отключаются: fade lightbox, fade hover-preview, `scroll-behavior: smooth` (→ `auto`), blink каретки (`animation: none`, каретка статична), transition кнопки copy. Остаётся: мгновенная смена состояний.

**RND-028. Фокус.** `:focus-visible { outline: 1px solid var(--accent); outline-offset: 2px; border-radius: 0 }`. Никогда `outline: none`. Порядок табуляции — по DOM. Кликабельные чекбоксы, ссылки, кнопки copy, сворачиваемые callouts — все в табуляции.

**RND-030. Fallback-шрифты.** `--font-mono: 'IBM Plex Mono', 'Noto Sans Mono CJK SC', 'Sarasa Mono SC', 'Cascadia Mono', ui-monospace, Menlo, Consolas, monospace`. Plex Mono **не содержит CJK** — без CJK-fallback китайский/японский текст ломает моноширинность (advance 1.0 em вместо 0.6) и «съезжает» выравнивание таблиц. Emoji: `'Segoe UI Emoji'` в конце (Windows 11). `font-feature-settings: "liga" 0, "calt" 0` — в моно лигатуры отключаем (иначе `->` в тексте превращается в стрелку и ломает подсчёт колонок).

**RND-032. Переполнение.** Глобально: `.md-content { overflow-wrap: anywhere; }`; `pre`, `table`, `.katex-display`, `.mermaid` — исключения со своим `overflow-x: auto`. `body { overflow-x: hidden }` как последняя защита.

**RND-033. RTL.** Если `dir` в front matter = `rtl` или доля арабских/ивритских символов > 30% → `dir="rtl"` на контейнере, `text-align: start`, зеркалятся: `padding-left` blockquote/списков → логические свойства (`padding-inline-start`), маркеры заголовков (`inset-inline-start`), border цитаты (`border-inline-start`). **Все отступы в CSS задаются логическими свойствами** (`margin-block`, `padding-inline`) — требование ко всей таблице стилей.

**RND-035. Производительность больших документов.** Блоки верхнего уровня получают `content-visibility: auto; contain-intrinsic-size: auto 40px`. Подсветка кода, mermaid, KaTeX — только для блоков, попавших в `IntersectionObserver` с `rootMargin: 200%`. Документ > 2 MB — рендер порциями по 200 блоков через `requestIdleCallback`.

**RND-031. Печать / экспорт.** `@media print`: `--bg: #fff`, `--fg: #000`, ссылки — `a[href^="http"]::after { content: " (" attr(href) ")" }` 9 px, code block — рамка 1px вместо заливки, `break-inside: avoid` для code/table/figure/callout, `orphans: 3; widows: 3`.

### 2.11 RND-027. Аудит контрастности WCAG 2.2 — точные значения и исправления

Формула: относительная яркость sRGB (WCAG 2.x), `(L1+0.05)/(L2+0.05)`. Пороги: **1.4.3 AA** — 4.5:1 для текста < 24 px (или < 18.66 px при weight ≥ 700); **1.4.11** — 3:1 для нетекстовых индикаторов и границ компонентов.

**Проверка запрошенных пар:**

| Пара | Ratio | 3:1 | 4.5:1 |
|---|---|---|---|
| `#8a877f` на `#f7f6f3` (light muted) | **3.32:1** | ✓ | **✗** |
| `#7a776f` на `#141413` (dark muted) | **4.12:1** | ✓ | **✗** |

Обе пары порог 3:1 проходят, порог AA для основного текста — **нет**. Это критично, потому что `--muted` в макетах применён к **настоящему тексту мелким кеглем**: H2 (13.5 px/600 — не «крупный текст» по WCAG: крупный = ≥ 24 px, либо ≥ 18.66 px при bold), мета-строка над заголовком (11 px), статус-бар (10.5 px), пункты рейки (12 px), заголовки секций рейки (10 px), синтаксические маркеры в Edit. Суммарно `--muted` — это ~30 % всего текста интерфейса.

**Требуемые корректировки:**

1. **RND-027a (обязательно).** `--muted` light: `#8a877f` → **`#6b6760`** (5.20:1 на `--bg`, 4.72:1 на `--surface`). Ближайшее значение, проходящее 4.5 на **обоих** фонах, — `#6e6a60` (4.99 / 4.53); берём `#6b6760` ради запаса на субпиксельный рендеринг и низкокачественные панели.
2. **RND-027b (обязательно).** `--muted` dark: `#7a776f` → **`#8a877f`** (5.14:1 на `--bg`, 4.64:1 на `--surface`). Минимум для 4.5 на обоих — `#87847d` (4.94 / 4.46, на surface на 0.04 не дотягивает), поэтому `#8a877f`.
   Приятный побочный эффект: значение `#8a877f` теперь работает в обеих темах, только в разных ролях.
3. **RND-027c.** Ввести `--muted-soft` (light `#8a877f` = 3.32, dark `#7a776f` = 4.12) — **только** для нетекстовых элементов: маркеры списков, чекбокс-рамка, разделители-глифы, линии mermaid, номера строк. Никогда — для читаемого текста.
4. **RND-027d.** `--faint` (1.59 / 1.60) **не является допустимым цветом текста ни в одном сценарии**. В макетах он применён к: (а) плейсхолдеру Rich — заменить на `--muted-soft` (плейсхолдер несёт информацию); (б) номерам строк — вынести в `--line-number` (light `#8a877f` 3.32, dark `#6a675f` 3.26); (в) маркерам блоков `#`/`##` в поле — остаётся `--faint`, это чистый декор, дублирующий видимую иерархию заголовков (исключение 1.4.11 «decorative»).
5. **RND-027e.** Акцент как **текст** (бейдж «edited» 10 px, номера сносок, подсветка совпадений поиска) — использовать `--accent-strong`: light `#6d28d9` (6.57:1), dark `#c4b5fd` (9.99:1). `--accent` (5.27 / 6.77) формально проходит AA, но `#7c3aed` на 10 px в моно субъективно «дрожит»; `--accent-strong` решает и это.
6. **RND-027f.** `--border` (1.19) достаточен для декоративных разделителей, но **не** для границ, несущих смысл. Активное состояние вкладки задаётся `border-bottom: 1px var(--fg)` (15.92 ✓), фокус — `--accent` (5.27 ✓), рамка чекбокса — `--muted-soft` (3.32 ✓). Дополнительный токен `--border-strong` не вводим: там, где граница функциональна, применяем `--fg`/`--accent`/`--muted-soft`.
7. **RND-027g (примечание к дизайну).** Разница `--surface` / `--bg` = 1.10:1 (light) и 1.11:1 (dark) — на грани различимости на дешёвых TN-панелях и при ярком внешнем свете. Не меняем (это осознанный минимализм), но добавляем настройку `contrastBoost` → `--surface` становится `#eae7de` (1.14) / `#232220` (1.16), а `--muted` → `#5c5a54` / `#a9a69f`.
8. **RND-027h.** Настройка `a11yContrast: 'aa' | 'mockup'`; **default `aa`** (значения из блока выше). `'mockup'` возвращает исходные `#8a877f`/`#7a776f` — для тех, кто предпочтёт вид макета; при выборе `'mockup'` в настройках показывается строка «ниже WCAG AA для мелкого текста».

## 3. Метаданные документа

**META-001. Word count — алгоритм.** Вход: mdast (не сырой текст — нужно исключать блоки).
1. **Исключаются из подсчёта:** front matter, fenced/indented code blocks, `%%…%%`, HTML-комментарии, HTML-блоки, math (inline и display), URL-часть ссылок (`[текст](url)` → считается только «текст»), wikilink-target без alias (`[[a/b/c]]` → 1 слово «c»; с alias — считаются слова alias), маркеры разметки, `![[embed]]` (содержимое встроенного файла не входит в счёт хост-документа), table delimiter-row, `#tag` (считается за 1 слово), лейблы callouts.
2. **Включаются:** обычный текст, alt-текст изображений (опция, default выкл.), inline `code` (default **вкл.** — это часть предложения), содержимое таблиц, сноски, заголовки.
3. **Токенизация** (Unicode-aware, `\p{...}` с флагом `u`):
   - Латиница/кириллица/греческий и пр. буквенные: `[\p{L}\p{M}\p{N}]+(?:[’'\u2019\-/][\p{L}\p{M}\p{N}]+)*` → 1 слово. Значит `state-of-the-art` = 1, `don’t` = 1, `и/или` = 1.
   - Числа: `1,204`, `3.14`, `2026-09-05`, `12px` → 1 слово каждое.
   - **CJK**: каждый символ `\p{Script=Han}`, `\p{Script=Hiragana}`, `\p{Script=Katakana}`, `\p{Script=Hangul}` = **1 слово** (конвенция MS Word / Obsidian / Typora). Последовательность катаканы `\p{Script=Katakana}+` — тоже посимвольно, для простоты и предсказуемости.
   - Emoji (включая ZWJ-последовательности и вариационные селекторы) = **0 слов**, но считаются как 1 символ в char count через сегментацию по графемам (`Intl.Segmenter('…', {granularity:'grapheme'})`).
   - URL как autolink = 1 слово.
4. **Кириллица** дополнительных правил не требует — покрывается `\p{L}`. Единственная тонкость: `ё`/`е` не нормализуются, дефис в «кто-то» не разделяет.
5. Возвращается `{ words, chars, charsNoSpaces, cjkChars, codeWords, readingMinutes }`. `codeWords` показывается отдельно в подсказке статус-бара («612 words · +240 in code»).
6. **Инкрементальность:** счёт кэшируется по top-level-блокам (`Map<blockHash, counts>`); при правке пересчитывается только затронутый блок. Для 10 MB это разница между 400 мс и 2 мс на нажатие.

**META-002. Reading time.**
`minutes = ceil(words / wpm + cjkChars / cjkCpm + imageSeconds/60)`, где `imageSeconds = 3 с` за первое изображение, далее по 1 с (эвристика; опция `countImages: false`).
Таблица `wpm` по языку (default-набор, настраивается):

| lang | wpm | обоснование |
|---|---|---|
| `en` | **238** | Brysbaert (2019), meta-analysis: тихое чтение нон-фикшн ≈ 238 wpm (фикшн ≈ 260) |
| `ru` | **190** | пересчёт через длину слова: 238 × (5.1 / 6.4) ≈ 190. Русское слово длиннее английского примерно на четверть; инвариантом при смене языка выступает скорость в символах, а не в словах |
| `de` | 200 | средняя длина слова ≈ 6.0 |
| `fr` | 215 | ≈ 5.4 |
| `es`/`it` | 220 | ≈ 5.2 |
| CJK | **260 симв./мин** (`cjkCpm`) | иероглиф ≈ слово |

Определение языка: front matter `lang` → иначе доля скриптов в тексте (кириллица > 30 % → `ru`, Han/Kana/Hangul > 15 % → CJK-ветка, иначе `en`). Округление вверх, минимум «1 min», формат по макету — «3 min».
Косвенная опора для межъязыковых различий: IReST (Trauzettel-Klosinski & Dietz, 2012) — чтение вслух, 17 языков, 184 ± 29 wpm (863 ± 234 симв./мин), диапазон от 161 (финский) до 228 (английский); символьная скорость стабильнее словесной. Все значения — настраиваемые, приложение не должно их защищать как истину.

**META-003. Reading progress %.** **По последнему видимому блоку, не по скроллу.** Причина: изображения, диаграммы и code block имеют вес в пикселях, несопоставимый с их долей в тексте; скроллбар врёт на документах с большим кодом.
Алгоритм:
1. Каждый блок верхнего уровня несёт `data-s`/`data-e` (offset в исходнике) и предвычисленный `words`.
2. `IntersectionObserver` (`threshold: [0, .5, 1]`) отслеживает видимые блоки.
3. `progress = (сумма words всех блоков выше нижней кромки viewport + доля текущего блока) / totalWords`. Доля текущего блока = `(viewportBottom − blockTop) / blockHeight`, зажатая в [0,1].
4. Показывается округлённым до целого — «reading · 38 %» (макет 1a). Не обновлять чаще 8 раз/с; `requestAnimationFrame`-дроссель.
5. Если документ короче одного экрана — 100 %.
6. В Edit прогресс не показывается; в Rich — показывается.

**META-004. «Continue where you left off».** Сохраняется на каждый файл (в локальную БД, не в файл):
```
{ path, sizeBytes, mtimeMs, contentHash (xxhash64 первых+последних 64 KB + длина),
  anchorOffset,          // offset начала последнего видимого блока
  anchorFingerprint,     // первые 64 значащих символа блока, нормализованные
  headingSlug,           // ближайший заголовок выше
  blockIndex,            // порядковый номер top-level блока
  scrollFraction,        // запасной вариант
  updatedAt }
```
Восстановление — каскад: (1) `contentHash` совпал → `anchorOffset` точно; (2) не совпал → искать `anchorFingerprint` в новом тексте, окно поиска ±20 % длины от `anchorOffset`; (3) не нашли → `headingSlug`; (4) → `blockIndex`, зажатый в границы; (5) → `scrollFraction`. Прокрутка ставит якорь на 1/3 высоты viewport, не в самый верх.
Не восстанавливать, если запись старше 90 дней или файл изменился более чем на 50 % длины — вместо этого начало документа + тост «документ сильно изменился».

**META-005. created / modified.** Приоритет:
`created` = front matter `created` → `date` → `Created` → FS birth time → mtime.
`modified` = front matter `modified` → `updated` → `lastmod` → FS mtime.
Парсинг дат: ISO 8601 сначала, затем `YYYY-MM-DD HH:mm`, затем `DD.MM.YYYY` (RU) — с явным списком, без «умного» разбора произвольных строк. Невалидная дата → игнор + линт-предупреждение, а не крэш.
Windows/NTFS: `birthtime` достоверен (Rust `std::fs::Metadata::created()` работает). Кроссплатформенно — нет (на ext4 часто отсутствует), поэтому при отсутствии молча падаем на mtime. Копирование файла обнуляет birthtime → отсюда и приоритет front matter.
Формат отображения по макету: «4 sep 2026» (нижний регистр месяца, без нуля в дне), в library — относительное для < 7 дней («2d ago»).

**META-006. Outline.** Источник — mdast, узлы `heading` (ATX **и** setext).
Исключаются: заголовки внутри fenced/indented code (`# comment` в bash!), внутри front matter, внутри HTML-блоков, внутри `%%…%%`. **Включаются** заголовки внутри blockquote и callouts, но помечаются флагом `nested: true` (в панели — с приглушённым цветом), потому что в Obsidian они являются валидными целями ссылок.
Структура: плоский список `{ depth, text, slug, offsetStart, offsetEnd, nested }`; иерархия строится клиентом, «прыжки» уровней (h1 → h3) не нормализуются, но помечаются для линта.
Отображение (макет 1d): отступ 18 px на уровень (h2 → `padding-left: 36px` = 18 базовый + 18); текущий раздел подсвечен `--fg` + фон `--surface`. Синхронизация с прокруткой — тот же `IntersectionObserver`, что и META-003.
Текст пункта — с раскрытой inline-разметкой (`## **Важно**` → «Важно»), но с сохранением inline-кода как есть.

**META-007. Заголовок документа.** Порядок (по требованию): **первый H1 → front matter `title` → имя файла без расширения**.
Уточнения: «первый H1» = первый узел `heading` с `depth === 1`, находящийся среди первых 3 блоков документа и **не** внутри blockquote/callout/code. Если H1 дальше по документу — он не считается заголовком документа (иначе заголовок «прыгает» при добавлении раздела). Front matter `title` берётся как строка; если это список — первый элемент.
Опция `titleSource: 'h1-first' | 'frontmatter-first'` (default `h1-first`).
Имя файла: без расширения, без нормализации регистра, подчёркивания и дефисы **не** заменяются пробелами (это врёт про содержимое файла).

**META-008. Excerpt для библиотеки.** Берётся первый узел `paragraph`, идущий после заголовка документа и не являющийся: изображением-в-одиночку, callout-лейблом, таблицей, HTML, front matter. Из него: раскрыть inline-разметку, удалить сноски/теги/wikilink-скобки (оставив текст/alias), свернуть пробелы, обрезать по границе слова до 160 символов + `…`. Если абзацев нет — первые 160 символов текста любого блока. Если нет и этого — пусто, в library показывается только путь.
Кэшируется вместе с `contentHash`.

**META-009. Агрегаты библиотеки.** Футер «12 files · 9,240 words» (макет 1e) = сумма `words` по всем файлам библиотеки из кэша; пересчёт по файлу — при изменении его mtime. Формат чисел — разделитель тысяч по локали (`9,240` / `9 240`).

**META-010. Links here (backlinks).** Индекс `target → [{sourcePath, offset, contextLine}]`, строится при индексации vault. Учитываются: wikilinks, embeds, markdown-ссылки на `.md` (в т.ч. без расширения — META-011), ссылки в front matter. Обновление — инкрементально по изменённым файлам. Панель (макет 1d) показывает имя файла 12 px + строку контекста 11 px `--muted` с выделением совпадения `--accent`.

**META-011. Разрешение путей ссылок.** Порядок для `[x](target)` и `[[target]]`:
1. Точное совпадение относительно текущего файла.
2. То же + `.md`.
3. Уникальное совпадение basename по всему vault («shortest path»).
4. Совпадение с учётом регистра → без учёта регистра (Windows) + предупреждение при неоднозначности.
5. Не нашли → `unresolved`.
URL-декодирование обязательно (`%20`, `%D0%9F`), NFC-нормализация обязательна (macOS отдаёт NFD — TST-047).

## 4. Модель документа для трёх режимов

### 4.1 Инварианты

**DOC-001. Исходный текст — единственный источник истины.** В памяти живёт ровно один `Text` (структура CodeMirror 6). AST, HTML, outline, счётчики, индексы — **производные** и в любой момент могут быть выброшены и пересчитаны. Никакая операция не имеет права записать в файл результат сериализации AST, который не был получен из текущего текста через явно инициированную пользователем правку.

**DOC-002. Единица позиции.** Канонический offset = **индекс в UTF-16 code units** (совпадает с `EditorState.doc` CodeMirror и с `unist` position `offset` у micromark, который работает со строками JS). На границе с Rust (файловый ввод-вывод, поиск, индексация) — конверсия в UTF-8 байтовые смещения через предвычисленную таблицу переходов. **Никогда не смешивать** — это источник багов на кириллице (2 байта / 1 unit) и эмодзи (4 байта / 2 units).

**DOC-003. AST с позициями.** Каждый узел mdast несёт `position: { start: {line, column, offset}, end: {…} }`. Дополнительно навешиваем `data.raw` для узлов, где сериализация небезопасна (HTML, math, wikilink, callout-лейбл, block id). Для top-level-блоков строится массив `blocks: [{ start, end, type, hash, words }]` — рабочая единица для рендера, счётчиков и минимальных диффов.

**DOC-004. Три представления, один текст.**

| Режим | Движок | Что показывает |
|---|---|---|
| Edit | CodeMirror 6, `@lezer/markdown`, декорации только *подсветки* | исходник целиком, маркеры видимы, номера строк |
| Rich | тот же `EditorState`, дополнительный compartment с `Decoration.replace/widget` | маркеры скрыты; блок под курсором раскрыт в исходник |
| Read | отдельный HTML-рендер (`remark → rehype → sanitize`) из того же текста | только результат |

Переключение Edit ↔ Rich — **смена compartment внутри одного `EditorState`**: позиция курсора, выделение, история undo, состояние скролла сохраняются полностью и мгновенно. Переключение в Read — пересчёт HTML + позиционирование по DOC-011.

### 4.2 Двусторонняя связь Read ↔ исходник

**DOC-011. Sync scroll.** Каждый top-level-блок в HTML несёт `data-s` / `data-e`. Строится массив якорей `[(sourceOffset, pixelTop)]`; отображение offset↔пиксель — кусочно-линейная интерполяция между якорями. Работает в обе стороны (Read → Edit при переключении, и в split view). Точность: попадание в тот же блок гарантировано, внутри блока — пропорционально.

**DOC-016. Клик по чекбоксу в Read → правка исходника по offset.**
1. У `<input type=checkbox>` есть `data-s` — offset **символа состояния** внутри `[ ]` (не начала строки).
2. Клик → `dispatch({ changes: { from: s, to: s + 1, insert: checked ? 'x' : ' ' } })`.
3. Транзакция помечается `Transaction.userEvent: 'input.checkbox'` — попадает в общую историю undo.
4. HTML **не** перерисовывается целиком: слушатель изменений сравнивает затронутые блоки и обновляет только их (DOC-013).
5. Тот же механизм — для сворачивания callouts (`+`/`-`), нет — для сворачивания outline (это чисто UI-состояние).
Ровно 1 символ меняется в файле. Это эталон того, как в Read должны работать все правки.

### 4.3 Инкрементальность

**DOC-012. Парсинг при наборе.**
- **Редактор**: `@lezer/markdown` через `LRLanguage`/`MarkdownParser` — инкрементальность встроена (потребляет `TreeFragment`, аннотированные изменениями). Отдельного дебаунса не нужно: CM6 парсит в бюджете кадра и продолжает в `requestIdle`. Ограничение Lezer, о котором надо помнить: изменение, меняющее смысл последующего текста (открытие fenced-блока, front matter, таблицы), делает переиспользование фрагментов невозможным и вызывает переразбор «хвоста». Для 10 MB это заметно → DOC-015.
- **Семантический слой** (Read, outline, счётчики, индекс ссылок): micromark/remark, полный разбор с дебаунсом.

**DOC-015. Пороги.**

| Размер файла | Семантический парсинг | Read-рендер |
|---|---|---|
| < 256 KB | main thread, debounce **120 ms** | полный ре-рендер |
| 256 KB – 4 MB | Web Worker, debounce **400 ms**, `structuredClone` mdast | блочный диф (DOC-013) |
| > 4 MB | Worker + `idle` приоритет, debounce **800 ms**; outline/word count по блокам инкрементально | прогрессивный рендер по 200 блоков + `content-visibility: auto` |
| > 20 MB | предупреждение, режим read-only с потоковым рендером | — |

Дополнительно: при вводе внутри одного блока (нет пустых строк в изменении, нет открытия/закрытия fence) можно переразбирать **только этот блок** — micromark на подстроке; это покрывает 95 % нажатий и снимает зависимость от размера файла.

**DOC-013. Блочный диф Read.** После пересчёта `blocks[]` сравниваем последовательности `hash` старого и нового (алгоритм Myers на массиве хешей). Перерисовываются только изменённые/вставленные блоки; DOM соседей не трогается → сохраняются позиция скролла, состояние lightbox, отрендеренные mermaid/KaTeX.

### 4.4 Round-trip Rich → Markdown

**DOC-017. Принцип «минимально-инвазивная сериализация».** Правка в Rich **никогда** не сериализует документ целиком. Порядок:
1. **Текстовая операция, если возможно.** Bold/italic/strike/highlight/inline-code, вставка ссылки, изменение уровня заголовка, тоггл чекбокса, вставка/удаление символа — всё это выражается как вставка/удаление байтов в конкретных позициях, вычисленных по AST. Сериализатор не вызывается вообще. Это покрывает ≈ 85 % операций редактирования.
2. **Блочная пересериализация** — только для структурных операций (превратить абзац в список, добавить строку в таблицу, изменить выравнивание столбца, сменить тип списка). Пересериализуется **ровно один top-level-блок**, результат сплайсится по `[block.start, block.end)`. Ведущие/замыкающие пустые строки вокруг блока сохраняются побайтово.
3. **Никогда** — полный `toMarkdown(tree)` над всем документом. Такой вызов допустим только в явной команде «Format document», по кнопке, с предпросмотром диффа.

**DOC-018. Вывод стиля документа (`inferStyle`).** Перед любой пересериализации сканируем документ и вычисляем фактические предпочтения; они передаются в `mdast-util-to-markdown` вместо дефолтов:

| опция | как выводится | дефолт библиотеки (не наш!) |
|---|---|---|
| `bullet` | самый частый из `-`/`*`/`+`; при ничьей — `-` | `*` |
| `bulletOther` | второй по частоте | `-` |
| `bulletOrdered` | `.` или `)` по частоте | `.` |
| `incrementListMarker` | `false`, если ≥ 70 % ordered-списков используют `1.` везде | `true` |
| `listItemIndent` | `'one'`, если отступ содержимого = маркер+1; `'tab'`, если кратен 4 | `'one'` |
| `emphasis` | `*` или `_` по частоте | `*` |
| `strong` | `**` или `__` по частоте | `*` |
| `fence` | `~`, если в коде документа встречаются строки из ≥3 бэктиков | `` ` `` |
| `fences` | всегда `true` (не генерируем indented code — MD-040) | `true` |
| `rule` / `ruleRepetition` / `ruleSpaces` | из первого `thematicBreak` | `*` / 3 / `false` |
| `setext` | `false`, **кроме** случая, когда редактируется существующий setext-заголовок | `false` |
| `closeAtx` | `true`, если ≥ 70 % ATX-заголовков имеют закрывающие `#` | `false` |
| `tableCellPadding` / `tablePipeAlign` | из первой таблицы | `true` / `true` |
| `stringLength` | **наша функция**: ширина в ячейках Plex Mono (East-Asian Wide = 2, combining = 0, emoji-графема = 2) | `String.length` |
| `quote` | `"` или `'` из первого title у ссылки | `"` |
| `resourceLink` | `false` (не разворачивать autolink) | `false` |
| `singleTilde` | `false` (MD-004/MD-014) | `true` |
| `firstLineBlank` (footnotes) | из первого footnote-definition | `false` |

Дефолты библиотеки (`bullet: '*'`, `strong: '*'` → `**`) намеренно **не** используются: подавляющее большинство реальных vault'ов пишут `-`, и слепое применение дефолта дало бы диф на каждой строке каждого списка.

**DOC-019. Политика экранирования.** `mdast-util-to-markdown` экранирует «на всякий случай»: `a_b` → `a\_b`, `1. x` в начале строки → `1\. x`, `+ ` → `\+ `. На круге это порождает шум. Правило:
1. После пересериализации блока — **диф на уровне символов** с оригинальным блоком.
2. Каждое добавленное `\` проверяется: убираем его и заново парсим блок; если AST **не** изменился — экранирование лишнее, откатываем.
3. Обратное тоже верно: если пользователь ввёл текст, требующий экранирования (`*` в начале строки), `\` добавляется.
4. Никогда не трогать `\` внутри code span/block/math/HTML.
Реализация — постпроцессор `unescapeRedundant(original, serialized, parse)`; покрыт тестом идемпотентности (TST-055).

**DOC-020. Гарантия идемпотентности (CI-гейт).** Для каждого файла тест-корпуса и для каждого top-level-блока:
`splice(source, block, serialize(parse(blockSource), inferStyle(source))) === source`
Иначе говоря: **пересериализация нетронутого блока обязана вернуть его побайтово**. Любой блок, где это не выполняется, помечается «read-only в Rich» — на нём Rich показывает исходник и не даёт структурных операций, вместо того чтобы молча испортить файл. Это защитный клапан архитектуры.

**DOC-021. Файловые свойства сохраняются.** BOM (наличие/отсутствие), доминирующий перевод строки (CRLF/LF/CR), наличие/отсутствие завершающего перевода строки, кодировка — определяются при чтении, хранятся как свойства документа, восстанавливаются при записи. Смешанные переводы строк нормализуются в буфере к LF, но при записи применяется доминирующий — с уведомлением в статус-баре («mixed line endings → CRLF»).

**DOC-023. Никакого автоформатирования при сохранении.** Не трим trailing whitespace (MD-032), не добавлять финальный `\n`, не нормализовать заголовки/списки, не менять кавычки. Всё это — только явные команды.

**DOC-022. Внешнее изменение файла.** Watcher (Tauri fs) → если буфер не грязный, перечитать и применить как транзакцию (сохранив позицию через META-004); если грязный — модал «файл изменён снаружи»: `оставить моё` / `взять с диска` / `показать diff`. Никогда не перезаписывать молча.

### 4.5 Сравнение трёх архитектур

**DOC-024 (a). CodeMirror 6 + декорации/виджеты** (модель Obsidian Live Preview, ink-mde).
Один `EditorState` на все режимы редактирования. Rich = набор `Decoration.replace` (скрыть `**`, `[[`, `> [!note]`), `Decoration.widget` (inline-изображение, рендер формулы, чекбокс) и блочных `WidgetType` с `block: true` (таблица, mermaid, display-math, HTML-блок). Раскрытие исходника у курсора — вычисляемый набор декораций, зависящий от `state.selection`.

| + | − |
|---|---|
| **Round-trip риск структурно равен нулю**: текст и есть модель, декорации — это только отображение | «Rich» ≠ настоящий WYSIWYG: таблица и вложенные структуры требуют собственных виджетов с вложенными редакторами |
| Позиции даром: sync scroll, outline, клик по чекбоксу — тривиальны | Line-based модель: блочный виджет всегда занимает целые строки; сложные inline-макеты ограничены |
| Инкрементальный парсинг из коробки (`@lezer/markdown` + `TreeFragment`) | Drag-n-drop перестановка блоков, drag-handle — реализуются вручную |
| Виртуализация viewport → 10 MB работают | Много декораций = нагрузка; обязательно строить их только по `view.visibleRanges` |
| IME, undo, выделение, доступность, vim-режим — готовые | Кривая обучения CM6 (compartments, StateField, ViewPlugin) выше среднего |
| Один граф зависимостей, малый бандл | Тонкая настройка «что раскрывать у курсора» — это про UX-полировку, её много |

**DOC-025 (b). ProseMirror (Milkdown / Tiptap) для Rich + CodeMirror для Edit.**

| + | − |
|---|---|
| Настоящий WYSIWYG: таблицы, drag-handle, node views, slash-меню — из коробки | **Схема PM лоссовая относительно Markdown.** Всё, чего нет в схеме (wikilink, callout, `%%`, block id, HTML, front matter, definition list), надо смоделировать узлами — иначе теряется при конверсии |
| Зрелые команды списков/таблиц; y-prosemirror для collab | **Каждое переключение режима — полная пересериализация документа**. Прямое нарушение DOC-017: диф на весь файл при правке одного слова |
| Богатая экосистема, Milkdown построен на remark | Два парсера (remark у PM, Lezer у CM) должны совпадать; иначе Edit и Rich видят разные документы |
| | Минимальный диф почти недостижим: PM-узлы теряют исходный текст, если не тащить `sourcePos` в атрибутах и не держать кэш нетронутых блоков — это фактически реализация DOC-017 поверх чужой модели |
| | Бандл: PM core + view + tables + remark + CM6 |

Риск — **высокий**. Инвариант DOC-001 нарушается на каждом переключении режима. Для приложения, чья ценность — «твой файл остаётся твоим файлом», это неприемлемо.

**DOC-026 (c). Подход Typora** (contenteditable по блокам; активный блок показан как исходник). *Typora закрыт, описание — реконструкция по поведению.*

| + | − |
|---|---|
| Round-trip лучший из возможных: правится ровно один блок, остальной файл не трогается | Собственный движок редактирования на `contenteditable` — выделение через границы блоков, undo, IME, вставка из буфера, доступность, автоскролл |
| UX-эталон, ровно то ощущение, к которому идёт этот проект | Готовых реализаций нет; это годы работы, а не библиотека |
| Естественная блочная виртуализация | Каждый баг браузерного `contenteditable` — твой баг |

**DOC-027. Рекомендация: (a) с политикой (c).**

Взять **CodeMirror 6 + `@lezer/markdown` для Edit и Rich одновременно** (один `EditorState`, режим = compartment с декорациями), а Read рендерить отдельным пайплайном `remark → rehype → sanitize → HTML` из того же текста.

Почему это и есть «Typora, только без своего contenteditable»: Live-Preview-модель Obsidian даёт ровно то поведение, что в (c) — все блоки отрендерены, блок под курсором раскрыт в исходник, — но реализована поверх готового текстового редактора, а не поверх `contenteditable`. Round-trip-риск при этом структурно нулевой (DOC-024), потому что модель — сам текст.

Обязательные условия рекомендации:
1. **DOC-014** — оба парсера распознают одинаковое множество конструкций; CI сравнивает границы блоков на всём корпусе.
2. **DOC-017/018/019/020** — сериализатор вызывается только поблочно, со стилем, выведенным из документа, с постпроцессором экранирования и с CI-гейтом идемпотентности.
3. Декорации строятся **только для `view.visibleRanges`** (иначе 10 MB кладут UI).
4. Таблица в Rich — блочный виджет с сеткой из вложенных мини-редакторов; при любом сомнении в корректности — падаем в исходник (DOC-020).
5. Держать открытым путь отказа от второго парсера: обход дерева Lezer → hast даст один парсер на всё приложение. Не делать сразу — но не строить архитектуру так, чтобы это стало невозможно.

Вариант (b) допустим только как отдельный, явно вызываемый «table editor» на конкретной таблице — не как режим документа.

## 5. Edge cases и тест-корпус

Корпус лежит в `tests/corpus/`, каждый кейс — пара `input.md` + `expected.html` (или `expected.json` для метаданных), плюс инвариантные проверки (idempotence, no-crash, budget).

### 5.1 Соответствие спецификациям

- **TST-001.** Все примеры CommonMark 0.31.2 (`spec.json`, ~650 кейсов — точное число берётся из самого файла) → HTML совпадает. Допустимые расхождения фиксируются явным allowlist с обоснованием.
- **TST-002.** Примеры GFM 0.29-gfm: tables, task lists, strikethrough, autolinks, disallowed raw HTML.
- **TST-003.** GFM footnotes (нет в спеке) — корпус снимается с поведения github.com: нумерация по порядку появления, а не по порядку определения; неиспользованное определение не рендерится; ссылка на несуществующий id остаётся текстом.
- **TST-004.** `spec.json` прогоняется **обоими** парсерами (micromark и `@lezer/markdown`); сравниваются границы top-level-блоков (DOC-014).

### 5.2 Структурные ловушки

- **TST-005.** Вложенный список с fenced-кодом внутри пункта 3-го уровня, отступ 6 пробелов; код содержит ```` ``` ````, ограда из 4 бэктиков.
- **TST-006.** Список, где содержимое выровнено на 2, 3, 4 и 5 пробелов вперемешку → проверка ленивых продолжений и вложенности.
- **TST-007.** Lazy continuation: абзац внутри blockquote, продолженный строкой без `>`.
- **TST-008.** Blockquote глубины 6 с callout на 3-м уровне и таблицей на 5-м.
- **TST-009.** Ordered list `start=0`, `start=999999999`, `start` больше 9 цифр (по CommonMark не список).
- **TST-010.** Setext H2 (`---`) сразу после абзаца vs thematic break после пустой строки — обе формы в одном файле.
- **TST-011.** Таблица с `|` внутри code span (`` `a\|b` ``), с `\|` в обычном тексте, со строками разной длины, с пустым заголовком, с одной колонкой.
- **TST-012.** Таблица, где ячейки — CJK и emoji: проверка `stringLength` (DOC-018) на переформатировании.
- **TST-013.** Indented code (4 пробела) сразу после списка — принадлежит списку или нет.
- **TST-014.** Табы: `\t` как отступ списка, `\t` в середине строки, таб в fenced-коде.
- **TST-015.** Смешение табов и пробелов в одном списке.
- **TST-016.** Файл с отступами в 3 пробела повсеместно (типичный «красивый» текст, не код).
- **TST-017.** Link reference definitions: определение до и после использования, дубликаты меток, метка в другом регистре, метка с кириллицей.
- **TST-018.** Ссылка с вложенными и несбалансированными скобками в URL: `[x](https://ru.wikipedia.org/wiki/Тест_(значения))`, `[x](<url with spaces>)`.
- **TST-019.** URL с `%20`, с кириллицей в percent-encoding, с якорем на кириллический заголовок `#как-читать`.

### 5.3 Расширения и конфликты

- **TST-020.** `$` как валюта: `Цена $5`, `от $5 до $10`, `$100 — $200`, `$x$` (формула), `\$5`, `$5$` (граничный).
- **TST-021.** `$$` в начале строки, в середине строки, внутри code block, внутри таблицы.
- **TST-022.** `==` как setext-подчёркивание vs `==highlight==` в одном файле.
- **TST-023.** `~x~` (sub) vs `~~x~~` (strike) vs `~~~` (fence) в одном файле.
- **TST-024.** `^sup^` рядом с `[^1]` и с `^blockid` в конце строки.
- **TST-025.** Wikilink с `|` внутри ячейки таблицы (требует `\|`), wikilink с `#` в имени файла, wikilink на несуществующий файл, `[[../parent/note]]`.
- **TST-026.** `#tag` vs `# Заголовок` vs `#не-заголовок` в начале строки vs `#fff` внутри `` ` `` vs `page#anchor` в URL vs `#2026` (не тег).
- **TST-027.** Callout: `[!NOTE]` и `[!note]`, неизвестный тип `[!frobnicate]`, `[!tip]-` (свёрнутый), вложенный callout, callout с таблицей внутри.
- **TST-028.** `%%комментарий%%` inline, многострочный, внутри code block, незакрытый `%%` до конца файла.
- **TST-029.** HTML-комментарий, содержащий `<script>` и `-->` внутри строки; незакрытый комментарий.
- **TST-030.** Front matter: пустой, без закрывающего `---`, с `---` в значении, с многострочным значением `|`, с YAML-якорями `&a`/`*a`, с `!!python/object` (должен быть отвергнут — SEC-011).
- **TST-031.** `---` в первой строке файла без закрывающего → thematic break, не front matter (документ не должен «исчезнуть»).
- **TST-032.** Hard break: два пробела, три пробела, `\` в конце, `<br>`, все четыре в одном абзаце.
- **TST-033.** Файл, где каждая строка кончается двумя пробелами (проверка, что автотрим их не убивает — DOC-023).

### 5.4 Данные и кодировки

- **TST-034.** Строка из 5000 символов без пробелов (не должна расширить колонку — RND-032).
- **TST-035.** Строка из 200 000 символов в одной логической строке.
- **TST-036.** Файл **10 MB** (~150 000 строк): время до первого кадра < 1 с, ввод символа < 16 мс, память < 400 MB.
- **TST-037.** Файл с **5000 заголовков**: outline строится < 300 мс, панель виртуализирована; слуги уникальны (`foo`, `foo-1`, … `foo-4999`).
- **TST-038.** Файл с 10 000 сносок; 10 000 изображений (ленивая загрузка, отсутствие OOM).
- **TST-039.** Бинарный файл с расширением `.md` (PNG, ELF) → определяется по null-байтам в первых 8 KB → отказ открыть в редакторе, предложение «открыть как бинарный».
- **TST-040.** BOM: UTF-8 BOM, UTF-16LE BOM, UTF-16BE BOM. UTF-8 BOM — открыть, front matter после BOM распознать, BOM сохранить при записи (DOC-021).
- **TST-041.** CRLF-файл, LF-файл, CR-файл (классический Mac), файл со смешанными переводами строк → нормализация в буфере, восстановление доминирующего при записи.
- **TST-042.** Файл в cp1251 без BOM → эвристика (валидность UTF-8 + частотный анализ) → предложение «открыть как windows-1251», статус-бар показывает кодировку; при сохранении — предупреждение о конверсии в UTF-8.
- **TST-043.** Файл без завершающего перевода строки → не добавлять его молча.
- **TST-044.** Нулевой байт в середине текстового файла.
- **TST-045.** Некорректный UTF-8 (обрубленная последовательность) → replacement char, файл открывается read-only.
- **TST-046.** RTL: арабский абзац внутри LTR-документа, смешанный RTL/LTR в одной строке с числами (bidi), RTL внутри таблицы.
- **TST-047.** Кириллица в NFD (файл с macOS) → NFC-нормализация при разрешении ссылок; имя файла `й` в двух формах должно резолвиться в один файл.
- **TST-048.** Emoji ZWJ: `👨‍👩‍👧‍👦` (7 code points, 11 UTF-16 units) — word count = 0, char count = 1 графема, курсор перемещается через всю последовательность, ширина в таблице = 2 ячейки.
- **TST-049.** Вариационные селекторы `❤️`, флаги `🇷🇺`, skin-tone модификаторы.
- **TST-050.** Astral-символы (математические алфавиты `𝔸`) в заголовке → slug, offset (2 UTF-16 units — DOC-002).

### 5.5 Пути и ссылки (Windows)

- **TST-051.** Путь с пробелами: `![](my image.png)`, `![](<my image.png>)`, `[[my image.png]]`.
- **TST-052.** Путь с кириллицей: `![](изображения/схема.png)` и его percent-encoded форма.
- **TST-053.** `../` вверх на 1, 3 и 10 уровней; `../` выше корня vault → блокировка (SEC-010).
- **TST-054.** Абсолютный Windows-путь `C:\Users\…\img.png`, `C:/Users/…`, UNC `\\server\share\x.md`, путь с `~`.
- **TST-055.** `file:///C:/…` в ссылке и в `img src`.
- **TST-056.** Ссылка на `.md` без расширения: `[x](note)`, `[x](folder/note)`, `[[note]]`; неоднозначность (два `note.md` в разных папках).
- **TST-057.** Ссылка на файл, отличающийся только регистром (`Note.md` / `note.md`) — на Windows один файл, в vault из git может быть два.
- **TST-058.** Якорь на кириллический заголовок: `[x](#как-читать)`, `[[note#Как читать]]`, `[[note#как читать]]` (регистр), заголовок с эмодзи `## 🎯 Цели` → slug `-цели`.
- **TST-059.** Символическая ссылка / junction внутри vault (петля).
- **TST-060.** Файл, открытый другим процессом (эксклюзивная блокировка Windows) → внятная ошибка, не крэш.

### 5.6 Инварианты (проверяются на каждом файле корпуса)

- **TST-061. Idempotence.** `serialize(parse(x)) → x` поблочно (DOC-020) для 100 % блоков корпуса. Блоки-исключения перечислены явно.
- **TST-062. No-crash.** Ни один файл корпуса + 5000 сгенерированных фаззингом мутаций не роняет парсер, рендер и сериализатор.
- **TST-063. Budget.** Ни один файл корпуса не превышает: парсинг 200 мс/MB, рендер 400 мс/MB, пиковая память × 8 от размера файла.
- **TST-064. Sanitize.** Ни один файл корпуса не даёт в итоговом DOM: `script`, `iframe`, `on*`-атрибут, `javascript:`/`vbscript:`/`data:` кроме `data:image/(png|jpeg|gif|webp|avif)`.
- **TST-065. Offsets.** Для каждого узла AST `source.slice(start, end)` при повторном парсинге даёт тот же тип узла (проверка корректности позиций на кириллице и эмодзи).
- **TST-066. A11y.** axe-core на рендере каждого файла: 0 нарушений уровня serious/critical; контраст текста ≥ 4.5:1 в обеих темах (автоматизация RND-027).

## 6. Безопасность рендера

**SEC-001. Модель угроз.** Markdown-файл — **недоверенный ввод** (скачан, синхронизирован, получен в архиве, сгенерирован ИИ). Он может содержать HTML, ссылки, изображения. Webview имеет доступ к Tauri IPC. Следовательно: XSS в рендере = произвольное чтение/запись файлов и, потенциально, выполнение команд. Санитизация — не гигиена, а граница безопасности.

**SEC-002. Пайплайн санитизации.**
`remark-parse → remark-* (extensions) → remark-rehype (allowDangerousHtml: true) → rehype-raw → rehype-sanitize(schema) → [наша гидратация] → hast-to-dom`.
Схема = `defaultSchema` из `hast-util-sanitize` (GitHub-style) + минимальные дополнения. Базовые значения `defaultSchema` (проверено по исходнику `lib/schema.js`):
- `tagNames`: 58 элементов — `a b blockquote br code dd del details div dl dt em h1..h6 hr i img input ins kbd li ol p picture pre q rp rt ruby s samp section source span strike strong sub summary sup table tbody td tfoot th thead tr tt ul var`.
- `protocols`: `href: [http, https, irc, ircs, mailto, xmpp]`, `src: [http, https]`, `cite: [http, https]`, `longDesc: [http, https]`.
- `clobber: [ariaDescribedBy, ariaLabelledBy, id, name]`, `clobberPrefix: 'user-content-'`.
- `required: { input: { disabled: true, type: 'checkbox' } }`, `strip: ['script']`.

Наши изменения:
1. **Убрать** из `tagNames`: `div` (нужен только нам, генерируем сами после санитизации), `input` (чекбоксы генерируем сами, чтобы они были **не** `disabled` — MD-003/DOC-016).
2. **Добавить** в `attributes`: `code: [['className', /^language-./]]`, `span: [['className', /^(shiki|line|math|tag|katex.*)$/], 'dataS', 'dataE']`, `'*': ['dataS', 'dataE', 'dataLevel']`.
3. **Не добавлять** `style` ни для одного тега — ни для KaTeX, ни для Shiki (см. SEC-003).
4. `protocols.src`: убрать `http` (внешние изображения не грузятся — SEC-005), добавить `asset`; итог: `src: ['https', 'asset', 'blob', 'data']` + отдельная проверка `data:` (SEC-004).
5. `allowComments: false`, `allowDoctypes: false`.

Второй рубеж: **DOMPurify** (актуальная 3.x) прогоняется по итоговому DOM-фрагменту перед вставкой — defense in depth, разные баг-поверхности у двух санитайзеров. Конфиг: `ALLOWED_URI_REGEXP: /^(?:https?|mailto|asset|blob):/i` (`data:` разрешается только хуком, SEC-004), `FORBID_TAGS: ['style','script','iframe','object','embed','form','link','meta','base','svg','math']`, `FORBID_ATTR: ['style','srcset','ping','formaction']`, `SANITIZE_DOM: true`, `USE_PROFILES: { html: true }`. Дефолтный allowlist протоколов DOMPurify (`http, https, ftp, ftps, mailto, tel, callto, sms, cid, xmpp, matrix` + protocol-relative `//`) **слишком широк** — переопределяем явно.

**SEC-003. Гидратация после санитизации.** KaTeX генерирует десятки `<span style="height:0.8em;vertical-align:-0.2em">` — санитайзер их снесёт, формула развалится. Mermaid генерирует SVG с `<foreignObject>`. Решение — **никогда не пропускать сгенерированный HTML через санитайзер**:
1. До санитизации математика превращается в `<span class="math" data-math="…">` (только текст, безопасно).
2. После санитизации мы сами обходим `.math`, `.mermaid`, `.shiki-pending` и вставляем результат `katex.renderToString` / `mermaid.render` / Shiki через `innerHTML` — **но только в узлы, созданные нами, из строк, которые сгенерировали доверенные библиотеки из текста, прошедшего через них же**.
3. Дополнительно: SVG mermaid прогоняется через DOMPurify с `USE_PROFILES: { svg: true, svgFilters: false }` и `FORBID_TAGS: ['foreignObject','script','use','animate','set']` — `foreignObject` внутри SVG обходит HTML-профиль.
4. Shiki при `defaultColor: false` пишет цвета в inline `style` → та же проблема. Решение: `transformers` заменяют inline-стиль на `class="s0".."s4"` (5 ролей палитры RND-014), реальные цвета живут в нашем CSS. Побочная выгода: тема переключается мгновенно, без ре-highlight.

**SEC-004. Схемы URL.**
- **Запрещены безусловно**: `javascript:`, `vbscript:`, `livescript:`, `mocha:`, `data:` (кроме ниже), `blob:` в `href`, `about:`, `chrome:`, `ms-*:`, `search-ms:`, `ms-msdt:`.
- `data:` разрешён **только** в `img[src]` и **только** `data:image/(png|jpeg|jpg|gif|webp|avif);base64,` — регэкспом на префикс, с лимитом длины 4 MB. **`data:image/svg+xml` запрещён** — SVG исполняет скрипты.
- Проверка происходит **после** нормализации: декодирование HTML-сущностей, удаление управляющих символов и пробелов (`java\tscript:` — классический обход), приведение к нижнему регистру, разбор через `new URL()` в try/catch. Регэксп по сырой строке — недопустим.
- `mailto:`/`tel:` — разрешены, открываются системным обработчиком с подтверждением.

**SEC-005. Внешние изображения — по умолчанию не загружаются.** Приватность: удалённый хост при загрузке узнаёт IP, время открытия документа, User-Agent — это трекинг-пиксель в чистом виде.
- Default `remoteImages: 'block'`. Вместо изображения — плашка `--surface`, высота 60 px: имя хоста 11 px `--muted`, текстовая кнопка `load` и `always allow example.com`.
- Режимы: `'block'` (default) | `'ask'` | `'allow-listed'` | `'allow'`.
- При разрешении загрузка идёт **не** напрямую из webview, а через Rust-команду: `fetch_remote_image(url)` → проверка allowlist → лимиты (10 MB, 15 с, максимум 3 редиректа, только `https`, отказ на приватные диапазоны IP — SSRF) → возврат байтов → `URL.createObjectURL` → `blob:`.
  Следствие: **CSP вообще не нуждается в `https:` в `img-src`** — сеть в webview остаётся полностью закрытой. Это самое сильное решение в разделе.
- `srcset`/`ping` вырезаются всегда.

**SEC-006. Iframes и встраивание.** `iframe frame frameset object embed applet portal` — вырезаются всегда, опции нет. CSP: `frame-src 'none'; child-src 'none'; object-src 'none'`. Mermaid — `securityLevel: 'strict'`, **не** `'sandbox'` (тот использует iframe).

**SEC-007. Лимиты ресурсов (DoS).** KaTeX: `maxExpand: 500`, `maxSize: 25`, `throwOnError: false`, `trust: false`. Mermaid: вход ≤ 100 KB, таймаут рендера 3 с в try/catch. Общие: глубина вложенности блоков ≤ 100 (глубже — плоский рендер + предупреждение), число узлов рендера ≤ 500 000, число сносок ≤ 10 000, длина `data:` ≤ 4 MB, размер front matter ≤ 256 KB. Все лимиты выражены как константы в одном модуле и покрыты TST-063.

**SEC-008. DOM clobbering.** `clobberPrefix: 'user-content-'` сохраняется (сгенерированный `id="user-content-как-читать"`). Наша навигация по якорям добавляет префикс сама. Не использовать `document.getElementById(userValue)` без префикса и не полагаться на `window.<name>`.

**SEC-009. HTML-комментарии.** Только через парсер, никогда регэкспом. Классическая атака: `<!-- <script> --> ... <!-- </script> -->` — наивный «удалить всё между `<!--` и `-->`» раскрывает `<script>`. Наш пайплайн парсит HTML в hast и удаляет узлы комментариев (`allowComments: false`), поэтому уязвимости нет по построению.

**SEC-010. Локальные изображения и файлы: Tauri asset protocol.**
Конфигурация:
```json
"app": {
  "security": {
    "assetProtocol": { "enable": true, "scope": [] },
    "csp": { … },
    "dangerousDisableAssetCspModification": false
  }
}
```
- **`scope` в конфиге пуст.** Статический scope с `$HOME/**` — это доступ ко всему домашнему каталогу для любого файла в vault. Вместо этого — **динамический scope во время выполнения**: при открытии библиотеки Rust вызывает `asset_protocol_scope.allow_directory(vault_root, true)`, при закрытии — `forbid_directory`. Одна библиотека открыта = одна разрешённая директория.
- Фронтенд получает URL через `convertFileSrc(path)`; на Windows это `http://asset.localhost/<percent-encoded path>` (на других платформах — `asset://localhost/…`), поэтому в CSP нужны обе формы.
- **Проверка пути перед `allow`:** канонизация (`std::fs::canonicalize`, разрешает симлинки и `..`), затем `starts_with(vault_root_canonical)`. Отдельно отвергаются: UNC-пути `\\server\share`, пути с альтернативными потоками NTFS (`file.md:stream`), зарезервированные имена (`CON`, `NUL`, `COM1..9`, `LPT1..9`), пути длиннее `MAX_PATH` без префикса `\\?\`.
- Изображение вне vault (например, `C:\Users\me\Pictures\x.png`) → плашка «файл вне библиотеки» + кнопка «разрешить этот файл» (добавляет одиночный файл в scope, не директорию).

**SEC-011. Front matter и YAML.** Безопасный загрузчик: `JSON_SCHEMA`/`CORE_SCHEMA` (без `!!js/function`, `!!python/object`, без произвольных тегов), лимиты глубины 32 и размера 256 KB, защита от «billion laughs» (лимит на расширение якорей). Значения из front matter, попадающие в DOM (title, tags, aliases), экранируются как текст, никогда как HTML.

**SEC-012. Внешние ссылки и навигация.**
- Клик по `http(s)`-ссылке → системный браузер через Tauri `opener`. Webview **никогда** не навигирует по внешнему URL: слушатель `on_navigation` в Rust отклоняет всё, кроме `tauri://localhost` / `http://tauri.localhost` и `http://asset.localhost`.
- `file://` в документе — не открывается автоматически; клик даёт диалог с полным путём и кнопкой «открыть в проводнике» (`revealItemInDir`), а не «выполнить».
- Ссылки на исполняемые расширения (`.exe .bat .cmd .ps1 .msi .lnk .scr .vbs .js .jar .reg`) — открытие запрещено, только «показать в папке».
- Все внешние `<a>` получают `rel="noopener noreferrer nofollow"` (даже при перехвате клика — на случай средней кнопки мыши).

**SEC-013. CSP для WebView2.** Тауриевский `csp` внедряется в HTML при сборке; Tauri сам добавляет nonce/hash к локальным скриптам и стилям (`dangerousDisableAssetCspModification: false` — обязательно):
```json
"csp": {
  "default-src": "'self'",
  "script-src": "'self'",
  "style-src": "'self' 'unsafe-inline'",
  "img-src": "'self' asset: http://asset.localhost blob: data:",
  "font-src": "'self' asset: http://asset.localhost",
  "media-src": "'self' asset: http://asset.localhost blob:",
  "connect-src": "ipc: http://ipc.localhost",
  "frame-src": "'none'",
  "child-src": "'none'",
  "object-src": "'none'",
  "worker-src": "'self' blob:",
  "form-action": "'none'",
  "base-uri": "'self'",
  "manifest-src": "'none'"
}
```
Замечания:
- `style-src 'unsafe-inline'` — вынужденно (KaTeX/Shiki/CM6 ставят inline-стили). Компенсируется тем, что весь HTML проходит санитизацию с запретом атрибута `style` у контентных узлов (SEC-002.3) — inline-стили есть только у узлов, которые создали мы.
- `script-src` **без** `'unsafe-inline'` и **без** `'unsafe-eval'`. Если понадобится WebAssembly — только `'wasm-unsafe-eval'`, никогда `'unsafe-eval'`.
- Внешних CDN нет ни одного: KaTeX (шрифты + CSS), Shiki-грамматики, mermaid, IBM Plex Mono — всё бандлится локально. Это одновременно приватность, офлайн-работа и отсутствие `https:` в CSP.
- Шрифты KaTeX должны лежать в `fonts/` рядом с `katex.min.css` (относительные URL в CSS) — иначе формулы отрендерятся системным шрифтом.
- WebView2-специфика: отключить `AreDevToolsEnabled` в релизе, отключить `IsSwipeNavigationEnabled` и `AreDefaultContextMenusEnabled` (собственное контекстное меню), запретить `AllowExternalDrop` и обрабатывать drop самим.

**SEC-014. Обработка вставки из буфера.** Вставка HTML из буфера (из браузера) → конвертация в Markdown должна пройти ту же санитизацию **до** конверсии; вставка изображения из буфера сохраняется в `attachments/` внутри vault с генерированным именем (никогда — с именем из буфера).

**SEC-015. Логи и телеметрия.** Содержимое документов, пути и имена файлов не попадают в логи ошибок. Отчёты об ошибках парсера содержат только позицию и тип узла, не текст. Сетевой телеметрии нет.

## Приложение A. Незакрытые вопросы

1. **`--muted` и верность макету.** RND-027a/b меняют значения из `00-design-system`. Нужно решение дизайна: `a11yContrast: 'aa'` (рекомендуется) или `'mockup'`.
2. **Инверсия h2/h3 по цвету** (RND-003) — требует визуальной проверки на реальном тексте до фиксации.
3. **Второй парсер.** Стартуем с двух (Lezer + micromark) и CI-гейтом DOC-014; решение об уходе к одному — после первого прототипа Rich.
4. **`~sub~` vs GFM `~strike~`** — прямой конфликт с github.com; нужно решить, включён ли `subSup` в профиле `plain` по умолчанию (сейчас — да, с линтом).
5. **`wpm` для русского** (190) выведено из длины слова, а не измерено. Стоит проверить на своих текстах и вынести в настройки (уже вынесено).
6. **Редактирование таблиц в Rich** — самая дорогая часть рекомендации DOC-027; возможно, стоит начать с «таблица в Rich = исходник» и добавить редактор позже.
