# 03 · Требования к взаимодействию и нефункциональные требования

Продукт: **Plain** — минималистичный десктопный markdown reader/editor под Windows 11.
Опорные документы: `00-design-system-from-mockups.md` (дизайн-спека, приоритет выше этого файла при любом расхождении по геометрии/цвету/типографике), `01-features-competitors.md` (инвентаризация конкурентов; ссылки вида «боль #7», «A-16», «красная линия 1»).

Дата: 2026-09-05. Факты о платформе проверены по первоисточникам (список в конце).

**Легенда приоритетов:** `[MVP]` v0.1 · `[v0.2]` · `[v1.0]` · `[later]`. Сводка — раздел 10.

**Три инварианта, из которых выводится всё остальное** (из `01`, «красные линии»):

- **И-1. Файл — источник истины.** Байты, которые пользователь не редактировал, не меняются никогда: EOL, BOM, кодировка, хвостовые пробелы, финальный перевод строки, стиль маркеров списков, отступы таблиц. Ни один автоматический процесс не переписывает файл целиком.
- **И-2. Ноль сети в базовом сценарии.** Открытие, чтение, поиск, редактирование, экспорт, печать работают без интернета, без аккаунта, без телеметрии.
- **И-3. Быстрее, чем «открыть в браузере».** Холодный старт и потребление памяти — не «оптимизация», а основная фича (раздел 9).

## 1. Сценарии использования (user journeys)

Формат: **UX-NNN** — требование. Каждый сценарий — контекст, шаги, требования. Требования нумеруются сквозно.

### Сценарий 1. Двойной клик по `.md` в Проводнике (первый контакт с продуктом)

Пользователь никогда не открывал Plain. В Проводнике лежит `README.md`. Библиотеки нет, папку выбирать он не хочет (прямая формулировка запроса PowerToys #45267 → `01`, боль #1; анти-фича A-12).

Шаги: двойной клик → окно 1100×720 → режим `read` → текст виден.

- **UX-001** `[MVP]` Двойной клик по `.md` открывает файл сразу в режиме `read`. Никаких экранов приветствия, выбора библиотеки, туров, логинов, запросов «создать vault».
- **UX-002** `[MVP]` Время от `WM_CREATE` до первого кадра с читаемым текстом ≤ 400 мс (P50) для файла ≤ 200 КБ — см. NFR-001.
- **UX-003** `[MVP]` Рейка при открытии одиночного файла **свёрнута** (состояние как на макете 1c: слева над контентом лейбл «▸ files»). Библиотека не подразумевается.
- **UX-004** `[MVP]` Breadcrumbs в title bar показывают `<имя родительской папки> / <file.md>`. Корневой сегмент (жирный, 600) появляется только когда открыта библиотека.
- **UX-005** `[MVP]` Статус-бар слева: `reading · 0%`; справа: `utf-8 · 612 words · read-only`/`saved`, `◐ light`.
- **UX-006** `[MVP]` Команда «open library» доступна из quick search (`Ctrl K` → `> open library`) и из клика по первому сегменту breadcrumbs — но никогда не навязывается.
- **UX-007** `[MVP]` Второй двойной клик по другому `.md` при уже запущенном приложении **не поднимает второй процесс**: аргумент передаётся в существующий экземпляр (см. ACC-040). Настройка `window.openInNewWindow` меняет поведение на «новое окно».
- **UX-008** `[v0.2]` Если открытый одиночный файл лежит в папке, где есть ещё ≥ 2 markdown-файла, в футере рейки появляется неназойливая строка `12 files here · open as library` (11px, muted). Клик — открывает папку как библиотеку, сохранив текущий файл активным.

### Сценарий 2. Открыть папку как библиотеку

- **UX-009** `[MVP]` `Ctrl+Alt+O` / `> open library` / drag-n-drop папки на окно → стандартный системный диалог выбора папки (`IFileDialog` с `FOS_PICKFOLDERS`).
- **UX-010** `[MVP]` После выбора: рейка разворачивается в состояние `files`, breadcrumbs получают корень (имя папки, вес 600), футер рейки показывает путь в тильда-форме `~/Documents/plain`, контент показывает экран **Библиотеки** (макет 1e), а не пустоту.
- **UX-011** `[MVP]` Индексация идёт в фоне; дерево и список файлов доступны сразу после первого прохода по каталогам (без чтения содержимого). Полнотекстовый поиск помечается как «indexing… 43%» в футере рейки до готовности; UI не блокируется ни на кадр.
- **UX-012** `[MVP]` Библиотека запоминается: `%APPDATA%\Plain\vaults.json`. При следующем старте без аргументов открывается последняя библиотека и последний активный файл.
- **UX-013** `[v0.2]` Библиотека > 25 000 файлов → предупреждение с предложением сузить область (`.plainignore`), но открытие не блокируется.

### Сценарий 3. Быстро прочитать длинный README (300 КБ, 40 заголовков)

Это главный сценарий продукта (боль #1).

- **UX-014** `[MVP]` В режиме `read` контент ограничен 560px и центрирован; над H1 — мета-строка `4 sep 2026 · 612 words · 3 min` (11px muted).
- **UX-015** `[MVP]` Расчёт времени чтения: 200 слов/мин для латиницы, 180 для кириллицы, 500 знаков/мин для CJK. Подсчёт слов — через `Intl.Segmenter(locale, {granularity:'word'})`, а не `split(/\s+/)`: иначе кириллица и CJK считаются неверно.
- **UX-016** `[MVP]` `Ctrl+Shift+\` переводит рейку в состояние `outline`: заголовки с отступом по уровню (H2 → padding-left 36px), активный заголовок подсвечен фоном `--surface`. Клик — скролл к заголовку без изменения истории навигации.
- **UX-017** `[MVP]` Статус-бар слева показывает `reading · 38%` — процент прокрученной высоты документа, обновляется throttled на 100 мс.
- **UX-018** `[v0.2]` Sticky heading: при прокрутке текущий H1/H2 «прилипает» к верхней кромке области контента строкой 11px muted с border-bottom 1px `--border` (по мотивам VS Code / PowerToys Monaco preview → `01`, «что хвалят»). Отключается настройкой.
- **UX-019** `[MVP]` `Ctrl+Shift+O` — typeahead по заголовкам текущего файла в модале quick search с префиксом `@` (модель Marked 2 → `01`, «что хвалят»).
- **UX-020** `[MVP]` Заголовки в outline показываются **без литеральных `#`** (боль #26 — самая залайканная markdown-задача VS Code, открыта с 2018).
- **UX-021** `[MVP]` `Ctrl+=` / `Ctrl+-` / `Ctrl+0` меняют масштаб контента (не UI-хрома) шагами 10%: 80–200%. Масштаб сохраняется на окно и переживает перезапуск.
- **UX-022** `[v0.2]` `serifReading` — опциональная смена шрифта **только контента** на серифный (кандидат из макета «Try next»); UI остаётся IBM Plex Mono.

### Сценарий 4. Править и сохранить

- **UX-023** `[MVP]` `Ctrl+/` переключает режимы циклом `read → edit → rich → read`; `Ctrl+Shift+/` — в обратную сторону; `Ctrl+Alt+1/2/3` — прямой переход.
- **UX-024** `[MVP]` При переключении режима сохраняются: позиция каретки (по смещению в символах), выделение, позиция скролла (по якорю, не по пикселям), **вся история undo** (EDT-060).
- **UX-025** `[MVP]` Первое изменение помечает файл: `•` accent в breadcrumbs после имени, `●` accent справа от имени в рейке, статус-бар `unsaved`, в списке библиотеки бейдж `edited` (10px accent).
- **UX-026** `[MVP]` `Ctrl+S` — сохранение атомарной записью (REL-010). После успеха статус меняется на `saved just now`, далее относительное время `saved 2m ago`, обновляемое раз в 30 с.
- **UX-027** `[MVP]` Сохранение **никогда не переформатирует документ**. Trailing whitespace, финальный перевод строки, стиль маркеров, нумерация списков, отступы таблиц остаются как есть (И-1; боль #3, A-10 — единственная причина, по которой MarkText считают ненадёжным).
- **UX-028** `[MVP]` Ошибка записи (read-only, нет прав, сетевой диск отвалился) показывается **баннером**, а не молчаливо (боль #51: Ghostwriter теряет данные на сетевой папке без сообщения). Баннер: `couldn't save — <причина> · retry · save as…`. Черновик при этом уже лежит в журнале (REL-030).

### Сценарий 5. Найти по всей библиотеке

- **UX-029** `[MVP]` `Ctrl+K` — quick search (модал 520px, top 120px, макет 1f): секции `files` (fuzzy по имени с путём) / `in text` (первые 5 полнотекстовых) / `actions`.
- **UX-030** `[MVP]` `Ctrl+Shift+F` — полноэкранный global search в области контента, в стиле экрана библиотеки (заголовок 22px/600, список с border-top 1px).
- **UX-031** `[MVP]` Первые результаты появляются ≤ 100 мс после остановки ввода (debounce 120 мс), остальные — потоково.
- **UX-032** `[v0.2]` `Ctrl+Shift+H` — replace across files **с обязательным предпросмотром** и откатом одной командой (боль #4 у Obsidian с 2020 и боль #46 у Notable, 168 👍 — фича, которой нет ни у кого).

### Сценарий 6. Переименовать файл с обновлением ссылок

- **UX-033** `[MVP]` `F2` на строке дерева/списка → inline-переименование в той же строке (input 12px, тот же шрифт), выделено базовое имя без расширения.
- **UX-034** `[MVP]` После подтверждения приложение ищет входящие ссылки (`[](rel)`, `![](rel)`, `[[wikilink]]`, reference-definitions, `<a href>`/`<img src>` в inline-HTML) и показывает диалог `update 14 links in 6 files? · update · skip`. Дефолт — **prompt** (как VS Code `markdown.updateLinksOnFileMove.enabled`, у которого дефолт `never`; мы считаем `prompt` правильнее, но не `always`).
- **UX-035** `[MVP]` Обновление ссылок — одна транзакция: перед записью создаётся снапшот каждого затронутого файла; отмена — одна команда `> undo link update`. Прямой ответ на боль #8 (Obsidian: «relative image and attachment paths get broken (critical!)»).
- **UX-036** `[MVP]` Стиль ссылки сохраняется: если исходная была `%20`-кодирована — остаётся кодированной; если была в угловых скобках `<path with space>` — остаётся; относительная не превращается в абсолютную.
- **UX-037** `[v0.2]` Переименование **заголовка** (каретка в заголовке, `F2`) обновляет все ссылки на якорь `#anchor` в библиотеке — как VS Code Rename Symbol (`01`, «что хвалят»).

### Сценарий 7. Вставить скриншот из буфера

- **UX-038** `[MVP]` `Ctrl+V` с растровым изображением в буфере (в `edit`/`rich`): файл сохраняется в `<папка файла>/assets/` (настройка `library.attachmentFolder`), в текст вставляется `![](assets/<имя>)`.
- **UX-039** `[MVP]` Имя по шаблону `library.attachmentNameTemplate`, дефолт `{filename}-{yyyyMMdd-HHmmss}.png` (боль #29: VS Code, 52 👍 — все вставки называются одинаково и захламляют папку).
- **UX-040** `[MVP]` PNG сохраняется без перекодирования, если буфер содержит PNG; иначе кодируется в PNG. Никакой загрузки на внешний хостинг (A-17).
- **UX-041** `[MVP]` Если папка `assets/` не существует — создаётся молча. Если файл с таким именем есть — суффикс ` 2`, ` 3`.
- **UX-042** `[v0.2]` После вставки статус-бар на 3 с показывает `saved assets/shot-20260905-141233.png · reveal`, клик — открывает Проводник с выделенным файлом.

### Сценарий 8. Экспортировать в PDF

- **UX-043** `[v0.2]` `> export to pdf` открывает системный диалог сохранения, затем рендерит через WebView2 `PrintToPdfStream` с настройками `ICoreWebView2PrintSettings`.
- **UX-044** `[v0.2]` Дефолты: A4, поля 20 мм, `ShouldPrintBackgrounds = true` (иначе фон код-блоков `--surface` теряется), `ShouldPrintHeaderAndFooter = false`, масштаб 100%.
- **UX-045** `[v0.2]` Шрифт PDF — тот же IBM Plex Mono, **вшитый в приложение**, не системный: боль #10 (Obsidian молча подменяет шрифт и теряет CJK). Если в документе есть CJK/кириллица — используется подмножество с нужными блоками, а не fallback.
- **UX-046** `[v1.0]` Управление разрывами страниц: поддержка `<div style="page-break-after: always">` и синтаксиса `\pagebreak` в отдельной строке; в настройках экспорта — «не разрывать заголовок от следующего абзаца», «не разрывать код-блок» (боль #9: три отдельных треда с 2021 года, ни один не закрыт).
- **UX-047** `[v0.2]` Экспорт — не блокирующая операция: прогресс в статус-баре, окно остаётся отзывчивым.
- **UX-048** `[v0.2]` `> export to html` — один самодостаточный файл: CSS инлайн, изображения в `data:`-URI (настройка `export.html.embedAssets`).

### Сценарий 9. Работать с двумя файлами рядом

- **UX-049** `[v0.2]` `Ctrl+Alt+→` — открыть текущий (или выбранный в quick search по `Shift+Enter`) файл в правой половине окна. Split — вертикальный, 50/50, перетаскиваемый разделитель 1px `--border`, минимальная ширина панели 320px.
- **UX-050** `[v0.2]` Каждая половина имеет собственный переключатель `read · edit · rich` и собственную позицию скролла. Статус-бар показывает состояние **активной** половины.
- **UX-051** `[v0.2]` Один и тот же файл можно открыть слева в `read`, справа в `edit` (кандидат «Try next» из макета). Оба вида смотрят в **один буфер**: правка справа мгновенно видна слева, undo общий.
- **UX-052** `[MVP]` Альтернатива для MVP: `Ctrl+Shift+N` — второе окно. Окна независимы, но разделяют один watcher и один индекс библиотеки (боль #39: Joplin вынуждает поднимать второй процесс).
- **UX-053** `[v0.2]` Синхронизация скролла между половинами — **выключена по умолчанию** и включается явно (боль #54: у PanWriter сломанная scroll-sync — топ-issue проекта с 2022).

### Сценарий 10. Восстановиться после сбоя

- **UX-054** `[MVP]` При старте, если в `%APPDATA%\Plain\drafts\` есть несохранённые черновики, вместо обычного экрана показывается список в стиле библиотеки: `unsaved work found`, строки `имя файла · путь · 3 минуты назад · 1,204 w`, действия `restore · compare · discard`.
- **UX-055** `[MVP]` `restore` открывает файл с содержимым черновика в состоянии «unsaved»; исходный файл на диске не трогается до явного `Ctrl+S`.
- **UX-056** `[MVP]` `compare` показывает diff черновика и файла на диске в двухколоночном виде.
- **UX-057** `[MVP]` `discard` требует подтверждения и уносит черновик в системную корзину, а не удаляет (боль #14, #47 — потеря данных без истории; A-21).

### Сценарий 11. Внешнее изменение файла (git pull, AI-агент, второй редактор)

Ключевой сценарий 2026 года: файл правит агент, пока он открыт (боль #7, #53).

- **UX-058** `[MVP]` Watcher отслеживает открытые файлы и дерево библиотеки. Изменение подхватывается **без перезапуска приложения и без переоткрытия вкладки** (боль #53 у Zettlr — именно это не работает).
- **UX-059** `[MVP]` Нет локальных несохранённых правок → файл тихо перезагружается. Позиция чтения восстанавливается **по якорю** (ближайший заголовок + смещение в символах внутри него), а не по пикселям: после `git pull` пиксельная позиция бессмысленна. Статус-бар 3 с показывает `reloaded from disk`.
- **UX-060** `[MVP]` Есть локальные правки → **баннер** под title bar (высота 36px, фон `--surface`, border-bottom 1px `--border`, текст 11.5px): `file changed on disk · reload · keep mine · compare`. Баннер немодальный, не крадёт фокус, не прерывает ввод. `Esc` — свернуть до маркера в статус-баре.
- **UX-061** `[MVP]` `keep mine` не пишет на диск немедленно — только снимает баннер; при следующем `Ctrl+S` показывается подтверждение `overwrite newer version on disk?`.
- **UX-062** `[MVP]` Событие watcher’а игнорируется, если **хэш содержимого не изменился**. Это обязательно: боль #52 — OneDrive «трогает» файл, MarkText предлагает перезагрузку, перезагрузка стирает правки.
- **UX-063** `[MVP]` Собственные записи не порождают баннер: после атомарной записи путь помечается write-token’ом (путь + размер + mtime + хэш) на 2 с.
- **UX-064** `[v0.2]` Автоскролл к месту внешней правки после тихой перезагрузки, если правка находится вне видимой области (модель Marked 2 → `01`, «что хвалят»).
- **UX-065** `[MVP]` Файл удалён извне → буфер остаётся в памяти, статус `deleted on disk`, строка в дереве серая курсивом, `Ctrl+S` пересоздаёт файл. Никакого автоматического закрытия вкладки.
- **UX-066** `[MVP]` Файл переименован/перемещён извне (watcher видит пару rename) → путь и breadcrumbs обновляются молча, уведомление 3 с `moved to projects/`.

### Сценарий 12. Работа без библиотеки (одиночный файл)

- **UX-067** `[MVP]` Все функции, кроме global search, backlinks, tags и дерева, работают без библиотеки: чтение, редактирование, find/replace в файле, outline, экспорт, печать, история версий.
- **UX-068** `[MVP]` Quick search без библиотеки показывает секции `recent` (глобальный список из 20) и `actions`. Секция `files` скрыта, а не пуста.
- **UX-069** `[MVP]` `> open library` доступна всегда; после её вызова текущий файл остаётся открытым, даже если он вне выбранной библиотеки (breadcrumbs тогда показывают абсолютный путь курсивом).

### Сценарий 13. Drag-n-drop на окно

- **UX-070** `[MVP]` Оверлей при dragover: подложка `--bg` с opacity .92 поверх контента, рамка 1px `--accent` по периметру области контента, текст 13.5px по центру. Без иконок, без анимации кроме fade 120 мс.
- **UX-071** `[MVP]` Текст оверлея зависит от груза и режима: `.md` → `drop to open`; изображение в `edit`/`rich` → `drop to insert image`; изображение в `read` → `drop to open library`? нет — `switch to edit to insert`; папка → `drop to open as library`; несколько файлов → `drop to open 4 files`.
- **UX-072** `[MVP]` Изображение, брошенное в `edit`/`rich`, копируется в `assets/` и вставляется **относительной** ссылкой (модель Zettlr #335 → `01`, «что хвалят»; боль #37 у MarkText — относительной папки нет вовсе).
- **UX-073** `[MVP]` Файл, брошенный из библиотеки в текст, вставляется относительной markdown-ссылкой, а не абсолютным путём.

## 2. Спецификация горячих клавиш

### 2.1 Принципы

- **KEY-001** `[MVP]` База — конвенции VS Code (это самый вероятный «второй редактор» аудитории). Расхождения Typora/Obsidian закрываются **пресетами раскладки**, а не компромиссами: `keymap.preset ∈ {plain, vscode, typora, obsidian}`, дефолт `plain`. Попытка сделать одну раскладку «привычной всем» невозможна — доказательство в KEY-002.
- **KEY-002** `[MVP]` Документированные непримиримые конфликты между эталонами (проверено по support.typora.io):

  | Комбинация | Typora | VS Code | Наше решение |
  |---|---|---|---|
  | `Ctrl+[` / `Ctrl+]` | **outdent / indent** (инверсно) | indent / outdent | VS Code: `]` — увеличить отступ |
  | `Ctrl+=` / `Ctrl+-` | уровень заголовка ±1 | zoom | zoom (ожидание Windows) |
  | `Ctrl+0` | обычный текст (снять заголовок) | zoom reset | zoom reset; «обычный текст» → `Ctrl+Alt+0` |
  | `Ctrl+Shift+K` | code fence | delete line | вставка ссылки (см. KEY-003); delete line → `Ctrl+Shift+X` |
  | `Ctrl+D` | select word | add next occurrence | VS Code |
  | `Ctrl+Shift+C` | copy as markdown | open external terminal | copy path; copy as markdown → `Ctrl+Alt+C` |
  | `Ctrl+Shift+L` | toggle sidebar | select all occurrences | цикл типа списка; рейка → `Ctrl+\` |
  | `Ctrl+\` | clear format | split editor | toggle рейки; clear format → `Ctrl+Alt+\` |
  | `Ctrl+E` | select cell in table | go to file | inline code |
  | `Ctrl+Shift+V` | paste as plain text | open markdown preview | paste as plain text (Typora) |

- **KEY-003** `[MVP]` **Конфликт `Ctrl+K`.** Макет 1f фиксирует `Ctrl K` как quick search (хинт в строке поиска рейки и подпись экрана). Typora/VS Code используют `Ctrl+K` для вставки ссылки. Решение: `Ctrl+K` — quick search (неизменяемо, это часть дизайна); вставка ссылки — `Ctrl+Shift+K` (сохраняется мнемоника буквы K). В пресете `vscode` — наоборот.
- **KEY-004** `[MVP]` **Привязка по физической клавише.** Все сочетания резолвятся по `KeyboardEvent.code` (`KeyB`, `Digit1`, `BracketRight`), а не по `.key`. При активной русской раскладке `.key` для физической `B` равен `«и»`, и наивная привязка `key === 'b'` ломает `Ctrl+B` для всей русскоязычной аудитории. Fallback на `.key` — только для клавиш, не имеющих стабильного `code` (символы на не-QWERTY раскладках).
- **KEY-005** `[MVP]` **Windows переключает раскладку по `Ctrl+Shift` (press-release без третьей клавиши)** — стандартная настройка у пользователей с двумя языками. Поэтому: ни одно действие не вешается на «`Ctrl+Shift` без клавиши»; все `Ctrl+Shift+X` срабатывают на `keydown` третьей клавиши, что раскладку не переключает. `Alt+Shift` — по той же причине не используется вовсе (кроме `Alt+Shift+5`, который де-факто стандарт для strikethrough).
- **KEY-006** `[MVP]` **Никогда не перехватываются**: `Alt+F4`, `Alt+Tab`, `Ctrl+Alt+Del`, `Ctrl+Shift+Esc`, `Win+*` (включая `Win+Z` — snap layouts), `PrtScn`, `Ctrl+Alt+<любая>` при активном IME с собственной привязкой.
- **KEY-007** `[MVP]` Во время композиции IME (`compositionstart` → `compositionend`) все аккорды, кроме `Esc`, передаются IME и не обрабатываются приложением. Иначе `Ctrl+B` во время набора японского/китайского ломает ввод.
- **KEY-008** `[MVP]` Полная таблица раскладки доступна из приложения: `> keyboard shortcuts` открывает экран в стиле библиотеки (список, без вкладок), с поиском и колонкой «изменено».
- **KEY-009** `[v1.0]` Пользовательские переопределения: `keymap.overrides` в `settings.json`, конфликт подсвечивается прямо в списке (боль #41 у Zettlr — кастомных хоткеев нет уже годы).

### 2.2 Разрешение конфликтов с WebView2

WebView2 перехватывает часть комбинаций до того, как их увидит приложение. Проверено по `CoreWebView2Settings`.

- **KEY-010** `[MVP]` `Settings.AreBrowserAcceleratorKeysEnabled = false`. По документации это отключает **разом**: `Ctrl+F` и `F3` (Find on Page), `Ctrl+P` (Print), `Ctrl+R` и `F5` (Reload), `Ctrl+Plus`/`Ctrl+Minus` (zoom), `Ctrl+Shift+C` и `F12` (DevTools), а также клавиши Back/Forward/Search. **Не отключает** `Home/End/PageUp/PageDown`, `Ctrl+X/C/V`, `Ctrl+A`, `Ctrl+Z` — эти остаются рабочими всегда.
- **KEY-011** `[MVP]` Следствие KEY-010, которое легко упустить: отключается и **встроенный зум**. Значит `Ctrl+=` / `Ctrl+-` / `Ctrl+0` приложение обязано реализовать само (через CSS-переменную масштаба контента или `Controller.ZoomFactor`). Дополнительно `Settings.IsZoomControlEnabled = false`, чтобы `Ctrl+колесо` не масштабировало весь UI неконтролируемо.
- **KEY-012** `[MVP]` `Settings.AreDevToolsEnabled = false` в релизных сборках — освобождает `F12` и `Ctrl+Shift+I` (последний нужен под «вставить изображение», как в Typora).
- **KEY-013** `[MVP]` `Settings.AreDefaultContextMenusEnabled = false` — иначе поверх наших контекстных меню всплывает меню Edge («Сохранить как», «Просмотр кода»).
- **KEY-014** `[MVP]` `Settings.IsSwipeNavigationEnabled = false` и `IsPinchZoomEnabled = false` — на тачскринах свайп назад выкидывает из документа.
- **KEY-015** `[MVP]` `AcceleratorKeyPressed` (на `CoreWebView2Controller`) **срабатывает для всех клавиш независимо от `AreBrowserAcceleratorKeysEnabled`** — это единственная надёжная точка перехвата на стороне хоста для глобальных действий уровня окна (`F11`, `Ctrl+Shift+A`, `Alt+F4`-подтверждение).
- **KEY-016** `[MVP]` `Alt+←` / `Alt+→`: приложение — SPA без навигации, история WebView2 пуста, но комбинация всё равно перехватывается на уровне документа (`preventDefault`) и маппится на навигацию по истории **файлов**.
- **KEY-017** `[MVP]` `Settings.IsPasswordAutosaveEnabled = false`, `IsGeneralAutofillEnabled = false`, `IsStatusBarEnabled = false` (иначе при наведении на ссылку внизу появляется чужая плашка Edge поверх нашего статус-бара 30px), `IsReputationCheckingRequired = false` (SmartScreen отправляет URL наружу — нарушение И-2).
- **KEY-018** `[MVP]` `Settings.IsNonClientRegionSupportEnabled = true` — включает CSS `app-region: drag`, без которого кастомный title bar 36px нельзя перетаскивать; попутно даёт системное меню по правому клику и разворачивание по двойному клику. **Не даёт** Snap Layouts на кнопке максимизации — см. ACC-031.

## 3. Спецификация поведения редактора

### 3.1 Общая модель

- **EDT-001** `[MVP]` Единственный источник истины — **текст документа**. `read`, `edit` и `rich` — три набора декораций над одним и тем же `EditorState`, а не три документа. Переключение режима меняет только `Compartment` с расширениями; `EditorState.doc` и история не пересоздаются.
- **EDT-002** `[MVP]` Ни один режим не «сериализует документ». Все правки — точечные транзакции над диапазонами текста. Из этого следует физическая невозможность боли #3 (молчаливое переписывание файла) и соблюдение A-10.
- **EDT-003** `[MVP]` Любая команда форматирования, которую нельзя выразить точечной правкой (например, применение жирного внутри raw-блока), не выполняется молча: статус-бар показывает `can't format inside a raw block` на 2 с.

### 3.2 Автопродолжение и списки

- **EDT-010** `[MVP]` `Enter` в конце пункта списка создаёт новый пункт того же типа с тем же отступом и тем же маркером (`-`, `*`, `+`, `1.`, `1)`). Маркер **берётся из документа**, а не из настройки: если файл написан через `*`, мы не переводим его на `-`.
- **EDT-011** `[MVP]` Нумерация: следующий пункт получает `N+1`. Существующие номера ниже по списку **не перенумеровываются** (боль #3). Опция `format.renumberOrderedLists` (дефолт `false`) включает перенумерацию, но только для явной команды `> renumber list`, никогда при сохранении.
- **EDT-012** `[MVP]` `Enter` на **пустом** пункте: снимает один уровень вложенности; на верхнем уровне — удаляет маркер и превращает строку в обычный абзац. Стандартное поведение Typora/Obsidian/VS Code.
- **EDT-013** `[MVP]` `Enter` в чекбоксе `- [x] текст` создаёт `- [ ]` (незавершённый), а не копирует состояние.
- **EDT-014** `[MVP]` `Enter` в цитате продолжает `> `; на пустой строке цитаты — выходит из цитаты (удаляет `> `).
- **EDT-015** `[MVP]` `Tab` в начале пункта списка (каретка перед текстом или в отступе) увеличивает вложенность; `Shift+Tab` уменьшает. `Tab` **в середине текста** вставляет отступ по `format.indentUnit` — не переключает вложенность.
- **EDT-016** `[MVP]` Единица отступа определяется по документу: если в файле уже есть вложенные списки — используется их отступ; иначе `format.indentUnit` (дефолт — 2 пробела). Табы в файле остаются табами.
- **EDT-017** `[MVP]` Производительность автопродолжения — приоритет: боль #25 (VS Code MAIO, лаги `Enter`/`Backspace` в списках). Обработчик `Enter` не должен парсить документ целиком; работает по строке и её отступу, бюджет ≤ 2 мс.
- **EDT-018** `[v0.2]` `Backspace` в начале пункта списка снимает маркер, оставляя текст (не склеивает со строкой выше).

### 3.3 Ввод и автозамены

- **EDT-020** `[MVP]` Автопары: `(` `[` `{` `` ` `` `"` `'` `*` `_` `$`. Правила: не вставлять пару, если справа буква/цифра; ввод закрывающего символа поверх автоматически вставленного «проскакивает»; `Backspace` между пустой парой удаляет обе.
- **EDT-021** `[MVP]` **Обёртка выделения**: при непустом выделении ввод `*`, `_`, `` ` ``, `"`, `(`, `[` оборачивает выделение, а не заменяет его.
- **EDT-022** `[MVP]` Умные кавычки — **выключены по умолчанию** (`format.smartQuotes = false`). В markdown они ломают код и front matter и создают невидимую разницу в git-diff. Если включены — не применяются внутри code span, code fence, front matter, URL, HTML.
- **EDT-023** `[MVP]` Автозавершение `[[` — всплывающий список файлов библиотеки (fuzzy), `Enter` вставляет `[[имя]]`, `Shift+Enter` — `[[имя|алиас]]`. Не появляется, если библиотека не открыта.
- **EDT-024** `[MVP]` Автозавершение `](` — список файлов и изображений библиотеки с относительными путями от текущего файла; `Tab` дополняет сегмент пути.
- **EDT-025** `[MVP]` Автозавершение `#` в начале слова — список существующих тегов (обе формы: инлайн и из front matter).
- **EDT-026** `[MVP]` **Вставка URL поверх выделения** → `[выделение](url)`. Определение URL: `^(https?|ftp|mailto|file)://` либо строка без пробелов с точкой и TLD. Одна из самых хвалимых мелочей (`01`, «что хвалят», Markdown All in One #20).
- **EDT-027** `[v0.2]` Вставка HTML из буфера (`text/html` во clipboard) конвертируется в markdown с сохранением ссылок, списков, таблиц, кода. `Ctrl+Shift+V` — вставить как есть, без конверсии.
- **EDT-028** `[MVP]` Вставка многострочного текста внутрь пункта списка выравнивает продолжения по отступу пункта.
- **EDT-029** `[v0.2]` `/` в начале пустой строки (`rich`) открывает slash-меню блоков: `heading 1–3 · list · numbered · task · quote · code · table · divider · image · math`. Плейсхолдер из макета: `Type / for a block, or just keep writing.`
- **EDT-030** `[MVP]` **IME и кириллица**: во время композиции никаких автопар, автозамен, автопродолжения и подсветки-перепарсинга. Все правки применяются на `compositionend` одной транзакцией, иначе undo рвётся на каждый слог.

### 3.4 Таблицы

- **EDT-040** `[MVP]` `Tab` в ячейке переходит к следующей; в последней ячейке строки — к первой ячейке следующей; в последней ячейке таблицы — создаёт новую строку. `Shift+Tab` — назад.
- **EDT-041** `[MVP]` Выравнивание pipe-таблицы (добавление пробелов для ровных колонок) выполняется **только по явной команде** `> format table` или при `format.autoFormatTables = true` **и только для таблицы под кареткой**, никогда для документа целиком и никогда при сохранении (И-1, A-10).
- **EDT-042** `[MVP]` Ширина колонок считается по **графемам с учётом восточноазиатской ширины** (`East_Asian_Width = W/F` → 2 колонки), а не по `string.length`. Боль #24: форматтер MAIO разъезжается на emoji, комбинирующих символах и не-BMP.
- **EDT-043** `[v0.2]` В `rich` таблица — сетка: клик по ячейке ставит каретку, `Ctrl+Enter` — новая строка ниже, панель над таблицей (в стиле плавающего тулбара, 30px, тёмная): `+row +col · del row · del col · ← ↔ →` (выравнивание). Ответ на боль #23 (открыта у Typora с 2016, люди платят $18 за TableFlip).
- **EDT-044** `[v0.2]` Вставка табличных данных из буфера (TSV/CSV/`text/html` с `<table>`) в пустую строку создаёт markdown-таблицу.
- **EDT-045** `[MVP]` Выделение ячейки/строки/столбца — `Ctrl+E` не используется (занят inline-кодом); вместо этого `Shift+↑↓←→` по ячейкам в `rich`.

### 3.5 Код, формулы, изображения

- **EDT-050** `[MVP]` Код-блок: подсветка по языку из инфо-строки; **word-wrap внутри код-блока настраивается** и по умолчанию выключен, с горизонтальной прокруткой (боль #36 — у MarkText нет ни того, ни другого).
- **EDT-051** `[MVP]` Кнопка `copy` в правом верхнем углу код-блока в `read`/`rich`: текст 10px muted, появляется на hover, при клике меняется на `copied` на 1.5 с (боль #38 у Joplin — долгий запрос).
- **EDT-052** `[MVP]` Язык блока показывается справа сверху, 10px muted, кликом переключается на редактируемое поле (в `rich`).
- **EDT-053** `[v0.2]` Формулы `$…$` и `$$…$$` → KaTeX. При каретке внутри — под превью показывается исходник моноширинно (двухслойное представление), при уходе каретки — только превью.
- **EDT-054** `[v0.2]` Mermaid — **единственный** движок диаграмм (A-9: Typora явно отклонила PlantUML в пользу одного Mermaid). Рендер в изолированном контексте, при ошибке — исходный код блока с однострочным сообщением, без «мерцания» (боль #32).
- **EDT-055** `[MVP]` Изображения: `![alt](path)` в `read`/`rich` рендерится с `max-width: 100%`. Локальные пути резолвятся относительно файла. Внешние URL **не загружаются** по умолчанию (`security.allowRemoteImages = false`, И-2): вместо картинки — плашка `remote image · load` (11px muted, рамка 1px `--border`).
- **EDT-056** `[MVP]` Изменение файла изображения на диске перерисовывает превью (боль #44 у VS Code — нужно вручную обновлять).
- **EDT-057** `[v0.2]` В `rich` клик по изображению выделяет виджет (рамка 1px `--accent`), `Enter`/`F2` — инлайн-редактирование `alt` и пути. Изменение размера мышью **не поддерживается**: это невыразимо в чистом markdown без HTML (A-11); при `security.allowInlineHtml = raw` доступно через явную команду `> set image width`.

### 3.6 Модель `rich` (Typora-like)

- **EDT-060** `[MVP]` **Раскрытие синтаксиса у каретки.** Синтаксические токены (`**`, `_`, `` ` ``, `[`, `](`, `)`, `#`, `>`, `- `) скрыты декорацией `Decoration.replace`. Декорация снимается, если каретка или любой конец выделения попадает **внутрь диапазона конструкции, включая её границы**.
- **EDT-061** `[MVP]` Граничное правило: каретка непосредственно **справа** от закрывающего `**` считается внутри конструкции. Иначе нельзя дописать текст в конец жирного фрагмента — классический баг всех наивных реализаций.
- **EDT-062** `[MVP]` Гранулярность раскрытия: **инлайн-конструкции** раскрываются по своему диапазону (`rich.revealSyntax = "caret-token"`); **блочные** (таблица, код-фенс, формульный блок, front matter, raw-блок) — целиком по блоку. Альтернатива `"caret-line"` — раскрывать всю строку — доступна настройкой.
- **EDT-063** `[MVP]` Маркеры блоков (`#`, `##`, `>`) в левом поле: цвет `--faint`, 11px, `left: -40px`, ширина 24px, выравнивание по правому краю, `user-select: none` — как в макете 1d. Они **дублируют** структуру, а не заменяют её: при `forced-colors` теряются, и это допустимо.
- **EDT-064** `[MVP]` Смена высоты строки при раскрытии/скрытии токенов запрещена: скрытые токены рендерятся нулевой ширины, но не меняют line-height. Иначе текст «прыгает» при каждом движении каретки.
- **EDT-065** `[MVP]` **Не-round-trip элементы → raw-блок.** Конструкции, которые нельзя показать в WYSIWYG без потери байтов, отображаются как **raw block**: моноширинный блок 12px на фоне `--surface`, слева бледная метка 10px uppercase muted (`raw html`, `unknown`, `front matter`, `mdx`). Содержимое редактируется как обычный текст и **никогда не парсится и не переписывается**.
- **EDT-066** `[MVP]` В raw-блок попадают: блочный HTML, `<script>`/`<style>` (всегда, независимо от настроек), шаблонные конструкции (`{{ }}`, `{% %}`, `<%= %>`), JSX в `.mdx`, любые незакрытые/некорректные конструкции, любые расширения, которых мы не понимаем. Принцип: **непонятное показываем как есть, а не пытаемся угадать**.
- **EDT-067** `[MVP]` Front matter в `rich` свёрнут в одну строку `--- 4 keys ---` (11px muted); клик разворачивает в raw-редактор YAML. Три вида отображения front matter (скрыть / таблица / код) — как в VS Code 1.121 (`01`, «что хвалят»), таблица — `[v1.0]`.
- **EDT-068** `[MVP]` Инлайн-HTML (`<br>`, `<u>`, `<kbd>`, `<sup>`) при `security.allowInlineHtml = "sanitized"` рендерится; при каретке рядом — показывается исходный тег.
- **EDT-069** `[MVP]` Плавающий тулбар выделения (макет 1d): появляется при непустом выделении в `rich`, `top: -38px` относительно верха выделения, высота 30px, фон `--toolbar-bg`, кнопки `B I S \` | link quote` (11.5px). Скрывается при движении каретки, скролле, `Esc`. В `read` — свой мини-тулбар (EDT-082).
- **EDT-070** `[v0.2]` В `rich` статус-бар слева показывает `rich · 3 chars selected` (макет 1d), в `edit` — `ln 9, col 118 · markdown`.

### 3.7 Отображение и навигация в редакторе

- **EDT-075** `[MVP]` Soft wrap включён по умолчанию во всех режимах. **Перенос учитывает структуру markdown**: продолжение перенесённой строки списка выравнивается по отступу текста пункта, а не по нулевой колонке (боль #28 у VS Code, 65 👍).
- **EDT-076** `[MVP]` Номера строк — только в `edit`; grid `40px | 24px gap | текст`, выравнивание вправо, цвет `--faint`, `user-select: none` (макет 1c). Переключаются `Ctrl+Shift+9`.
- **EDT-077** `[MVP]` Невидимые символы (`Ctrl+Shift+8`): пробел `·`, таб `→`, конец строки `¬`, неразрывный пробел `␣` c подсветкой (важно: NBSP из вставленного текста ломает markdown-парсинг и его нужно уметь увидеть), нулевой ширины символы `∅`.
- **EDT-078** `[MVP]` Code folding по заголовкам: сворачивается заголовок вместе со всем содержимым до следующего заголовка того же или высшего уровня. Маркер сворачивания — глиф `▸`/`▾` 10px `--faint` в левом поле, появляется на hover.
- **EDT-079** `[MVP]` Множественные курсоры: `Ctrl+Alt+↑/↓`, `Ctrl+D`, `Alt+клик`, `Ctrl+Shift+L`? — нет, последняя занята списками; «выделить все совпадения» → `Ctrl+Shift+Alt+L`.
- **EDT-080** `[MVP]` Каретка: 1.5px × 15px, цвет `--accent`, мигание `1.1s steps(1)`. Частота мигания берётся из системной настройки Windows (`SPI_GETKEYBOARDDELAY`/cursor blink rate); при `prefers-reduced-motion: reduce` мигание отключается совсем.

### 3.8 Чтение (`read`)

- **EDT-081** `[MVP]` `Ctrl+C` в `read` кладёт в буфер три представления: `text/html` (оформленный), `text/plain` (видимый текст без разметки) и **`text/markdown` (исходный markdown выделенного фрагмента)**. Приложение-приёмник выбирает подходящее; редакторы markdown получат markdown, Word получит форматирование.
- **EDT-082** `[MVP]` Мини-тулбар выделения в `read`: `copy · copy as markdown`. Кнопка `highlight` (запись `==текст==` в файл) **скрыта по умолчанию** — она нарушает контракт «read = только чтение» (A-16); включается `read.allowAnnotations`.
- **EDT-083** `[MVP]` Ссылки в `read`: цвет `--fg`, `text-decoration: underline`, `text-underline-offset: 3px`, `text-decoration-color: var(--accent)`. Клик по внешней ссылке — см. NFR-032; по внутренней — навигация внутри библиотеки с записью в историю (`Alt+←` возвращает).
- **EDT-084** `[MVP]` Наведение на внутреннюю ссылку показывает целевой путь в статус-баре слева (не всплывающая подсказка Edge — она отключена `IsStatusBarEnabled = false`).
- **EDT-085** `[v1.0]` `Ctrl`+наведение на внутреннюю ссылку — превью первых 6 строк целевого файла во всплывающей карточке 320px.

### 3.9 История правок

- **EDT-090** `[MVP]` История undo привязана к **буферу файла**, а не к режиму или окну. Переключение `read`/`edit`/`rich`, сворачивание рейки, смена темы, поиск — не создают точек истории и не сбрасывают её.
- **EDT-091** `[MVP]` Границы шагов undo: пауза ввода > 500 мс, смена типа операции (ввод → удаление), перемещение каретки на другую строку, любая структурная команда (заголовок, список, таблица), вставка. Ввод серии символов подряд — один шаг.
- **EDT-092** `[MVP]` Внешняя перезагрузка файла (UX-059) добавляет **одну** точку истории с подписью `reloaded from disk`, а не очищает историю. `Ctrl+Z` после неё возвращает пользовательский вариант.
- **EDT-093** `[MVP]` Глубина истории — не менее 1000 шагов или 50 МБ дельт, что меньше; при исчерпании отбрасываются самые старые.

### 4.4 Создание, переименование, перемещение

- **LIB-030** `[MVP]` `+ new` создаёт `Untitled.md`. Файл **не создаётся на диске сразу**: строка сразу переходит в inline-переименование, файл появляется после `Enter` или после первого введённого символа содержимого. Иначе папка засоряется пустыми `Untitled` при каждом случайном нажатии.
- **LIB-031** `[MVP]` Коллизии: `Untitled.md` → `Untitled 2.md` → `Untitled 3.md` (пробел, а не дефис — конвенция Windows).
- **LIB-032** `[MVP]` `library.newFileLocation ∈ {vaultRoot, sameFolder, specified}`, дефолт `sameFolder` (папка текущего файла или выбранная в дереве).
- **LIB-033** `[MVP]` Валидация имени: запрещены `\ / : * ? " < > |`, управляющие символы, имена `CON PRN AUX NUL COM1–9 LPT1–9` (с любым расширением), точка и пробел в конце. Нарушение — поле подчёркивается 1px `--accent` и справа 10px muted `invalid name`, `Enter` не срабатывает.
- **LIB-034** `[MVP]` Имя, отличающееся от существующего только регистром, на NTFS считается конфликтом; переименование `note.md` → `Note.md` выполняется через промежуточное имя.
- **LIB-035** `[MVP]` Unicode-имена (кириллица, CJK, эмодзи) поддерживаются полностью. Сравнение имён — по NFC-нормализованной форме, но на диск пишется ровно то, что ввёл пользователь (Windows не нормализует имена, и мы тоже не должны).
- **LIB-036** `[MVP]` Drag-n-drop в дереве перемещает файл/папку. Перетаскивание **только в папку**; изменение порядка внутри папки не поддерживается (порядок задаёт сортировка). Индикация цели — фон `--surface` у папки-приёмника.
- **LIB-037** `[MVP]` Перемещение запускает тот же механизм обновления ссылок, что и переименование (UX-034…UX-036). Массовое перемещение (например, 500 картинок) обрабатывается одной транзакцией с одним диалогом — прямой ответ на боль #8.
- **LIB-038** `[v0.2]` Шаблоны: `<vault>/.plain/templates/*.md`. Плейсхолдеры: `{{title}}`, `{{date:YYYY-MM-DD}}`, `{{time:HH:mm}}`, `{{uuid}}`, `{{cursor}}` (позиция каретки после создания).
- **LIB-039** `[MVP]` Удаление — в **системную корзину** через `IFileOperation` с `FOF_ALLOWUNDO`. Настройка `library.trashMode ∈ {system, vault, permanent}`; на сетевых дисках, где корзины нет, автоматически используется `vault` (`.plain/trash/<дата>/`).
- **LIB-040** `[MVP]` Удаление открытого файла: буфер остаётся открытым в состоянии «unsaved», чтобы правки не пропали.

### 4.5 Метаданные и связи

- **LIB-050** `[MVP]` Теги: инлайн `#tag` (не внутри code span, code fence, URL, ссылки, HTML-атрибута) и front matter (`tags: [a, b]`, `tags:\n  - a`, а также `tag:` в единственном числе). Обе формы в одном индексе.
- **LIB-051** `[MVP]` Вложенные теги `#work/2026/q3` образуют иерархию; поиск по `#work` находит все вложенные.
- **LIB-052** `[MVP]` Регистр тегов сохраняется как введён, сравнивается регистронезависимо; в списке показывается самый частый вариант написания.
- **LIB-053** `[MVP]` Секция `tags` в рейке (состояние `library`, макет 1e): до 12 самых частых тегов, 12px, счётчик 11px muted справа, `> all tags` открывает полный список.
- **LIB-054** `[v0.2]` **Backlinks** (`links here`, макет 1d): файлы, содержащие ссылку на текущий (относительный путь, wikilink, reference-definition). Группировка по файлу, до 3 строк контекста на файл. Боль #58: backlinks просят везде (VNote 6+ лет, Zettlr с 2020) и почти нигде не делают.
- **LIB-055** `[v1.0]` **Unlinked mentions**: вхождения имени текущего файла (без расширения) как отдельного слова, не являющиеся ссылкой. Отдельная сворачиваемая подсекция; на строке кнопка `link` 10px, превращающая упоминание в ссылку (пишет в чужой файл — требует подтверждения).
- **LIB-056** `[MVP]` **Определение «created».** По умолчанию — NTFS creation time (в отличие от Linux, на Windows он реален). Но копирование, распаковка, `git clone` и OneDrive его сбрасывают, поэтому: если во front matter есть `created:` или `date:` — приоритет у неё; `library.createdDateSource ∈ {fs, frontmatter, filename}`; вариант `filename` парсит `YYYY-MM-DD` в начале имени. Дополнительно: `ReplaceFileW` при сохранении **сохраняет** creation time (документировано) — то есть наша собственная запись дату создания не сбивает.
- **LIB-057** `[MVP]` `modified` — NTFS last-write time. Относительный формат до 7 дней (`2m ago`, `3h ago`, `yesterday`), далее абсолютный (`4 sep`, `12 mar 2025`).

### 4.6 Наблюдение за файловой системой

- **LIB-060** `[MVP]` Watcher — `ReadDirectoryChangesW` с `FILE_NOTIFY_CHANGE_FILE_NAME | DIR_NAME | LAST_WRITE | SIZE`, рекурсивно по корню библиотеки. Debounce 150 мс, слияние событий по пути.
- **LIB-061** `[MVP]` **Ограничения, которые нужно обработать явно**: (а) на сетевых дисках (`DRIVE_REMOTE`, SMB) уведомления теряются или не приходят вовсе; (б) OneDrive Files On-Demand генерирует события гидратации без изменения содержимого; (в) при переполнении внутреннего буфера драйвера приходит `ERROR_NOTIFY_ENUM_DIR` — все события за период потеряны.
- **LIB-062** `[MVP]` Реакция: при `DRIVE_REMOTE` или reparse-теге `IO_REPARSE_TAG_CLOUD` — переход на polling (открытые файлы каждые 3 с, дерево каждые 30 с). При переполнении буфера — полная переиндексация каталога в фоне.
- **LIB-063** `[MVP]` Любое событие проверяется по хэшу содержимого перед тем, как повлиять на UI (UX-062).
- **LIB-064** `[MVP]` Watcher **не следит** за игнорируемыми директориями (LIB-004) — иначе `node_modules` и `.git` съедают весь бюджет событий.

### 4.7 Несколько библиотек

- **LIB-070** `[v0.2]` Список библиотек — `%APPDATA%\Plain\vaults.json`: путь, отображаемое имя, время последнего открытия, id (хэш пути).
- **LIB-071** `[v0.2]` Переключение: клик по корневому сегменту breadcrumbs или `> switch library`. Каждая библиотека — своё окно (`window.libraryPerWindow = true`) либо замена в текущем.
- **LIB-072** `[v0.2]` Индекс, история версий и workspace хранятся по id библиотеки и переживают переключение.
- **LIB-073** `[MVP]` Приложение **не требует** библиотеки для работы (A-12, UX-067).

- **SRCH-011** `[MVP]` Состав строки: `⌕ [поле]  Aa  W  .*   3 / 17   ↑ ↓   ✕`. Тумблеры — текстовые глифы (`Aa` регистр, `W` слово целиком, `.*` regex), активный — цвет `--fg` + `border-bottom: 1px --accent`, неактивный — muted. Иконок нет.
- **SRCH-012** `[MVP]` При открытии в поле подставляется текущее выделение (если оно однострочное) или последний запрос.
- **SRCH-013** `[MVP]` Все совпадения подсвечиваются `rgba(accent, .18)`, текущее — `rgba(accent, .35)`. Подсветка ограничена видимой областью + буфер ±200 строк (иначе на файле 1 МБ подсветка стоит секунды).
- **SRCH-014** `[MVP]` Счётчик `3 / 17`; свыше 5000 совпадений — `5000+`. `Enter` / `Shift+Enter` — следующее/предыдущее с закольцовыванием; `Esc` — закрыть и вернуть каретку туда, где она была до открытия панели.
- **SRCH-015** `[MVP]` Regex — JavaScript-диалект, флаги `gm` (+`i` от тумблера `Aa`, +`u` всегда). Ошибка выражения: поле подчёркивается, счётчик показывает `invalid`, поиск не выполняется.
- **SRCH-016** `[MVP]` `Ctrl+H` добавляет вторую строку: поле замены, `replace` / `all`. В regex-режиме поддерживаются `$1…$9`, `$&`, `$$`.
- **SRCH-017** `[MVP]` Замена — одна транзакция undo целиком (`replace all` откатывается одним `Ctrl+Z`).
- **SRCH-018** `[v0.2]` Поиск только в выделении (`⌕` в тумблерах → `sel`).

### 5.3 Поиск по библиотеке (`Ctrl+Shift+F`)

### 5.5 Индексация и производительность

- **SRCH-040** `[MVP]` Индекс инкрементальный: на событие watcher’а переиндексируется один файл (≤ 50 мс для 100 КБ).
- **SRCH-041** `[MVP]` Кэш на диске: `%APPDATA%\Plain\index\<vault-id>\`. Схема версионирована; несовпадение версии → полная переиндексация в фоне без блокировки UI.
- **SRCH-042** `[MVP]` При старте кэш используется немедленно (поиск доступен через ≤ 200 мс), валидация по `mtime + size` идёт фоном; расхождения досчитываются.
- **SRCH-043** `[MVP]` Индексирование и поиск выполняются вне UI-потока (Rust-сторона). UI никогда не блокируется дольше 16 мс на операциях поиска.
- **SRCH-044** `[MVP]` Файлы > `files.largeFileThresholdMb` в полнотекстовый индекс не попадают; помечаются в результатах как `not indexed` и ищутся линейно по требованию.
- **SRCH-045** `[MVP]` Индекс хранит нормализованную форму (NFC + casefold) для регистронезависимого и диакритико-независимого поиска кириллицы/латиницы; исходные смещения сохраняются для точной подсветки.

## 6. Надёжность и данные

### 6.1 Сохранение

- **REL-001** `[MVP]` `files.autosave.mode ∈ {off, afterDelay, onFocusChange, onWindowChange}`, дефолт `afterDelay`, `files.autosave.delayMs = 1500`.
- **REL-002** `[MVP]` Autosave **никогда не пишет** при: активной композиции IME, наличии внешнего конфликта (баннер UX-060), файле только для чтения, отсутствии прав.
- **REL-003** `[MVP]` Индикатор состояния — единственный в статус-баре справа: `unsaved` → `saving…` → `saved just now` → `saved 2m ago`. Никаких всплывающих уведомлений об успешном сохранении.
- **REL-004** `[MVP]` При `autosave.mode = off` закрытие файла/окна с несохранёнными правками показывает диалог `save · don't save · cancel`; `files.saveOnClose ∈ {always, ask, never}`.
- **REL-005** `[MVP]` При закрытии приложения с несколькими несохранёнными файлами — один диалог со списком, а не N диалогов подряд.

### 6.2 Атомарная запись

- **REL-010** `[MVP]` Алгоритм записи: (1) записать во временный файл `.<имя>.tmp-<pid>-<rand>` **в той же директории**, что и целевой (требование `ReplaceFileW`: backup, replaced и replacement должны быть на одном томе; `%TEMP%` этого не гарантирует); (2) `FlushFileBuffers`; (3) `ReplaceFileW(target, tmp, NULL, REPLACEFILE_IGNORE_MERGE_ERRORS | REPLACEFILE_IGNORE_ACL_ERRORS)`.
- **REL-011** `[MVP]` `ReplaceFileW` документированно **сохраняет от заменяемого файла**: creation time, короткое имя, object identifier, DACL, security resource attributes, шифрование, сжатие и именованные потоки (ADS). Это и есть причина использовать именно его, а не `MoveFileEx`.
- **REL-012** `[MVP]` **Побочный эффект, который надо знать**: «The resulting file has the same file ID as the replacement file» — идентификатор файла меняется. Следствия: рвутся жёсткие ссылки на файл; часть sync-клиентов трактует это как удаление+создание и плодит конфликтные копии. Поэтому `files.writeMode = "inPlace"` (truncate + write) автоматически включается на `DRIVE_REMOTE` и в папках OneDrive (UX-107).
- **REL-013** `[MVP]` Если целевого файла нет — `MoveFileExW(tmp, target, MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`.
- **REL-014** `[MVP]` Любой отказ записи обрабатывается кодами `ERROR_UNABLE_TO_MOVE_REPLACEMENT` (1176), `..._2` (1177), `ERROR_UNABLE_TO_REMOVE_REPLACED` (1175) с разными сообщениями: в первых двух случаях данные пользователя уже на диске под временным именем, и сообщение обязано это сказать.
- **REL-015** `[MVP]` Временные файлы `.tmp-*` исключены из дерева, индекса и watcher’а.

### 6.3 Кодировки и байты

- **REL-020** `[MVP]` Определение кодировки: BOM (`EF BB BF` → UTF-8, `FF FE` / `FE FF` → UTF-16 LE/BE) — решающий признак. Без BOM: валидация как UTF-8; при неуспехе — эвристика для CP1251/CP866/CP1252 с показом кодировки в статус-баре.
- **REL-021** `[MVP]` `utf-8` в статус-баре **кликабельно**: меню `reopen with encoding ▸` / `save with encoding ▸`. Изменение кодировки при сохранении — только явное действие.
- **REL-022** `[MVP]` BOM сохраняется как был. Приложение **никогда не добавляет BOM** к файлу, у которого его не было, и никогда не удаляет у того, у кого был.
- **REL-023** `[MVP]` EOL: определяется доминирующий стиль; сохраняется как был (`files.eol = "preserve"`). Смешанные окончания **сохраняются посимвольно как есть**, статус-бар показывает `mixed eol`. Новые строки, вставленные пользователем, используют доминирующий стиль файла (для нового файла — `crlf` на Windows, настраивается).
- **REL-024** `[MVP]` `files.trimTrailingWhitespaceOnSave = false` и `files.insertFinalNewlineOnSave = false` — оба по умолчанию **выключены**. В markdown два хвостовых пробела — значимый синтаксис (hard break); их автоудаление меняет документ (А-10).
- **REL-025** `[MVP]` Файл только для чтения (`FILE_ATTRIBUTE_READONLY` или отказ ACL): открывается нормально, режимы `edit`/`rich` доступны, но `Ctrl+S` показывает `read-only · save as… · make writable`. В статус-баре — `read-only`.
- **REL-026** `[MVP]` Длинные пути: манифест приложения содержит `<ws2:longPathAware>true</ws2:longPathAware>`, а на машине должен быть `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled = 1` (REG_DWORD). **Оба условия обязательны**. Значение реестра кэшируется процессом при первом файловом вызове и не перечитывается — значит, проверить его нужно на старте. Дополнительно: относительные пути **всегда** ограничены `MAX_PATH` независимо от опций, поэтому внутри приложения все пути хранятся абсолютными и передаются в API с префиксом `\\?\` там, где длина > 240.
- **REL-027** `[MVP]` Путь длиннее лимита при создании файла → сообщение `path too long (<N> chars)` с показом, на сколько нужно сократить.

## 8. Доступность, локализация, Windows-специфика

### 8.1 Контраст: расчёт и правки

Расчёт по WCAG 2.x (относительная яркость, sRGB, формула `(L1+0.05)/(L2+0.05)`).

- **ACC-001** `[MVP]` **Измеренные значения токенов из `00`:**

  | Пара | Контраст | 3:1 (UI/крупный) | 4.5:1 (обычный текст) |
  |---|---|---|---|
  | `--muted` `#8a877f` на `--bg` `#f7f6f3` (light) | **3.32:1** | ✅ | ❌ |
  | `--muted` `#7a776f` на `--bg` `#141413` (dark) | **4.12:1** | ✅ | ❌ |
  | `--fg` `#1c1b19` на `#f7f6f3` | 15.92:1 | ✅ | ✅ |
  | `--fg` `#e8e6e1` на `#141413` | 14.78:1 | ✅ | ✅ |
  | `--faint` `#c9c5bb` на `#f7f6f3` | **1.59:1** | ❌ | ❌ |
  | `--faint` `#3a3936` на `#141413` | **1.60:1** | ❌ | ❌ |
  | `--accent` `#7c3aed` на `#f7f6f3` | 5.27:1 | ✅ | ✅ |
  | `--accent` `#a78bfa` на `#141413` | 6.77:1 | ✅ | ✅ |
  | `--quote` `#5c5a54` на `#f7f6f3` | 6.38:1 | ✅ | ✅ |
  | `--quote` (предл.) `#a9a69f` на `#141413` | 7.59:1 | ✅ | ✅ |
  | `--border` `#e6e3dc` на `#f7f6f3` | 1.19:1 | ❌ | — |
  | `--border` `#262523` на `#141413` | 1.20:1 | ❌ | — |
  | modal `#a9a69f` на `#1c1b19` | 7.08:1 | ✅ | ✅ |

- **ACC-002** `[MVP]` **`--muted` не проходит 4.5:1 ни в одной теме**, а используется для настоящего информационного текста размером 10–12px: статус-бар (10.5px), заголовки секций рейки (10px), breadcrumbs (11px), пути файлов и даты в библиотеке (11px), контекст в результатах поиска. Это не «декоративный» текст, исключение WCAG 1.4.3 к нему не применяется.
- **ACC-003** `[MVP]` **Правка (минимальная, сохраняющая тёплую нейтральную гамму):**
  - light: `--muted` `#8a877f` → **`#6f6d66`** (4.79:1) — минимум; рекомендуемый запас **`#6b685f`** (5.15:1).
  - dark: `--muted` `#7a776f` → **`#8a877f`** (5.14:1) — приятная симметрия: светлое значение muted становится тёмным.
  - Оба варианта сохраняют оттенок (тот же hue/сдвиг ~4–6% по светлоте) и не ломают визуальную иерархию, т.к. `--fg` остаётся на 15:1.
- **ACC-004** `[MVP]` `--faint` (1.59:1 / 1.60:1) допустим **только** для чисто декоративных элементов, дублирующих видимую структуру: маркеры блоков в левом поле `rich` (EDT-063), плейсхолдер набора. Но **номера строк — это информационный текст**, и на `--faint` они нечитаемы. Вводится отдельный токен:
  - `--line-number`: light **`#9a978f`** (3.10:1), dark **`#6a675e`** — минимум 3:1, чтобы номера были различимы, но не спорили с текстом. При `appearance.highContrast` — поднимается до 4.5:1.
- **ACC-005** `[MVP]` `--border` при 1.19:1 не проходит требование 3:1 к нетекстовому контрасту (WCAG 1.4.11) для границ, **несущих смысл**. Разделители списка и рейки смысла не несут (структура читается по расстоянию) — их можно оставить. Но границы **интерактивных** элементов (поле поиска, поле inline-переименования, рамка модала, границы контекстного меню) обязаны быть ≥ 3:1: вводится `--border-strong`: light `#b5b1a6` (2.2:1)… недостаточно → **light `#8a877f`** (3.32:1), **dark `#5a5852`** (2.59:1) → недостаточно → **dark `#6a675e`** (3.14:1).
- **ACC-006** `[MVP]` Выделение текста `rgba(124,58,237,.18)` над `--bg` даёт итоговый фон ≈ `#e3dcf2`; контраст `--fg` на нём — 13.6:1 ✅. Подсветка совпадений поиска на том же фоне читается.
- **ACC-007** `[MVP]` Правило «только один акцент» сохраняется: правки касаются исключительно нейтральных серых.
- **ACC-008** `[MVP]` В CI — автоматическая проверка контраста всех пар токенов; сборка падает, если пара, помеченная как текстовая, опускается ниже 4.5:1.

### 8.2 Клавиатура и скринридеры

- **ACC-010** `[MVP]` Полная навигация с клавиатуры (UX-089…UX-091). Порядок обхода зон — визуальный: title bar → рейка → переключатель режимов → find-панель (если открыта) → контент → статус-бар.
- **ACC-011** `[MVP]` Видимый фокус: `outline: 1px solid var(--accent); outline-offset: 2px`. В `forced-colors` — `outline: 2px solid Highlight`. Макеты фокус-состояний не содержат; это обязательная добавка.
- **ACC-012** `[MVP]` Семантика: дерево — `role="tree"`/`treeitem` с `aria-level`, `aria-expanded`, `aria-selected`; переключатель режимов — `role="tablist"`/`tab` с `aria-selected`; список библиотеки — `role="list"`; модал — `role="dialog" aria-modal="true"` с `aria-labelledby`; статус-бар — `role="status" aria-live="polite"`.
- **ACC-013** `[MVP]` Область контента в `read` — семантический документ: настоящие `h1…h6`, `ul/ol/li`, `blockquote`, `table/th/td` со `scope`, `pre/code`, `a`. Скринридер должен уметь навигацию по заголовкам (`H` в NVDA) и по ссылкам.
- **ACC-014** `[MVP]` Боль #19 (Obsidian: «ссылки и embed'ы обрывают чтение», «blank вместо текста», «озвучка знаков препинания вместо слов») возникает из-за виджетов, разрывающих текстовый поток. Требование: **все декорации в `rich` реализуются так, чтобы текстовый поток для accessibility tree оставался непрерывным**; скрытые синтаксические токены получают `aria-hidden="true"`, а не удаляются из DOM с потерей контекста.
- **ACC-015** `[MVP]` Редактор — `role="textbox" aria-multiline="true"` с `aria-label` = имя файла; при перемещении каретки в `aria-live="polite"`-регион (визуально скрытый) выводится текущая строка.
- **ACC-016** `[MVP]` Изменения состояния объявляются: `saved`, `unsaved`, `file changed on disk`, `17 results` — через `aria-live="polite"`; ошибки — `assertive`.
- **ACC-017** `[MVP]` Все интерактивные элементы имеют доступное имя. Глифы-лейблы (`⌕`, `◐`, `▸`, `●`) сопровождаются визуально скрытым текстом (`search`, `toggle theme`, `expand`, `unsaved changes`) — иначе скринридер зачитывает символ или молчит.
- **ACC-018** `[MVP]` Целевая проверка: NVDA + Narrator на Windows 11; сценарии UX-001, UX-004, UX-029, UX-033 проходятся полностью.

### 8.3 Системные предпочтения

- **ACC-020** `[MVP]` `prefers-reduced-motion: reduce` (Windows: Параметры → Специальные возможности → Визуальные эффекты → Эффекты анимации) отключает: fade оверлея DnD, переход темы, анимацию focus mode, мигание каретки, любые transitions длиннее 0 мс.
- **ACC-021** `[MVP]` `prefers-color-scheme` следует режиму приложений Windows при `appearance.theme = "system"`; смена подхватывается без перезапуска.
- **ACC-022** `[MVP]` `forced-colors: active` (Windows Contrast Themes). **Критично для нашего дизайна**: в этом режиме браузер принудительно переопределяет `color`, `background-color`, `border-color`, `text-decoration-color`, а `box-shadow` и `text-shadow` становятся `none`. У нас **единственный** способ показать активную строку — заливка `--surface`, и она исчезнет. Требование: в `@media (forced-colors: active)` активная строка получает `background: Highlight; color: HighlightText`, а активная вкладка режима — `border-bottom: 2px solid Highlight`.
- **ACC-023** `[MVP]` В forced-colors: `--accent` заменяется на `Highlight`/`AccentColor`; ссылки — `LinkText`; неактивный текст — `GrayText`; границы — `CanvasText`. `forced-color-adjust: none` **не применяется нигде**, кроме превью изображений.
- **ACC-024** `[MVP]` Каретка в forced-colors — `CanvasText` шириной 2px (1.5px на высококонтрастном фоне теряется).
- **ACC-025** `[v0.2]` `prefers-contrast: more` включает набор токенов повышенного контраста (muted → 7:1, border → 4.5:1) без перехода в forced-colors.

### 8.4 DPI, окно, мониторы

- **ACC-030** `[MVP]` Минимальный размер окна — **480×400 DIP**. Обоснование: Microsoft требует для Snap Layouts минимальную ширину «at most 500 epx» и рекомендует «330 epx or less». Предложенные 640×420 **не пройдут** — окно не сможет встать в узкие зоны трёхколоночного макета на широком экране, и Snap Layouts частично сломается. При ширине < `window.railAutoHideWidth` (900) рейка автоматически сворачивается; при < 560 скрывается полоса переключателя режимов (остаётся `Ctrl+/`); при < 500 статус-бар показывает только левую группу.
- **ACC-031** `[MVP]` **Snap Layouts на кастомной кнопке максимизации.** Кастомный title bar их ломает. Требование: оконная процедура хоста обрабатывает `WM_NCHITTEST` и возвращает `HTMAXBUTTON`, когда точка (переведённая `MapWindowPoints` в клиентские координаты) попадает в прямоугольник кнопки `▢` (46×36). Дополнительно обрабатываются `WM_NCMOUSEMOVE`/`WM_NCMOUSELEAVE` для hover-состояния и `WM_NCLBUTTONDOWN`/`WM_NCLBUTTONUP` для клика — иначе кнопка перестанет нажиматься, отдав ввод системе. Координаты кнопки передаются из веб-слоя в хост при каждом ресайзе и изменении DPI. `IsNonClientRegionSupportEnabled` + `app-region: drag` этого **не решают** — они дают только перетаскивание и системное меню.
- **ACC-032** `[MVP]` Per-Monitor DPI Awareness V2 в манифесте. При переносе окна между мониторами с разным масштабом (`WM_DPICHANGED`) окно перестраивается по предложенному системой прямоугольнику.
- **ACC-033** `[MVP]` Положение окна сохраняется через `GetWindowPlacement` (нормальный прямоугольник + состояние). При восстановлении проверяется, что прямоугольник пересекается хотя бы с одним текущим монитором минимум на 80×80 px; иначе окно центрируется на основном. Боль #20: при 150% на основном и 100% на втором окно Obsidian резко уменьшается при перезапуске.
- **ACC-034** `[MVP]` **Mica — не использовать.** Дизайн-система задаёт плоские непрозрачные `#f7f6f3` / `#141413` и строит всю иерархию на 1px-границах. Mica вводит просвечивающий фон обоев, из-за которого (а) фактический контраст текста становится непредсказуемым и наши расчёты ACC-001 перестают быть верными, (б) исчезает граница между окном и фоном рабочего стола. `window.mica` оставлен как выключенная опция.
- **ACC-035** `[MVP]` Скругление углов окна — системное (`DWMWA_WINDOW_CORNER_PREFERENCE = DWMWCP_DEFAULT`). Правило «скругления 0» из `00` относится к внутренним элементам, не к рамке окна: квадратное окно в Windows 11 выглядит как сломанное.
- **ACC-036** `[MVP]` Кнопки окна — 3×46px, высота 36px, hover: `—` и `▢` — фон `--surface`, `✕` — фон `#c42b1c` с белым глифом (системная конвенция Windows 11; единственное допустимое отступление от «одного акцента», т.к. это системный сигнал).
- **ACC-037** `[MVP]` 1px-границы при DPI 125/150/175% рисуются как `1px` физический через `calc(1px / var(--dpr))` либо `0.5px`-трюк; иначе на 150% часть границ исчезает, а часть удваивается.
- **ACC-038** `[MVP]` Каретка 1.5px × 15px на 200% DPI масштабируется до 3px × 30px — проверить, что не выглядит блоком; при DPI ≥ 200% использовать 2px в CSS-пикселях.

### 8.5 Интеграция с Windows

- **ACC-040** `[MVP]` **Single instance**: именованный mutex `Global\Plain.SingleInstance.<user-sid>`; второй процесс передаёт argv первому (`WM_COPYDATA` или именованный канал) и завершается с кодом 0. Первое окно поднимается через `SetForegroundWindow` с обходом ограничения фокуса (`AllowSetForegroundWindow` от запускающего процесса).
- **ACC-041** `[MVP]` **Ассоциация файлов.** Регистрация: ProgID `Plain.Markdown` в `HKCU\Software\Classes` (per-user, без прав администратора) с `DefaultIcon`, `shell\open\command "…\plain.exe" "%1"`; `HKCU\Software\Classes\.md\OpenWithProgids\Plain.Markdown`; `Capabilities` с `ApplicationName`, `ApplicationDescription` (обязателен, иначе приложение не появится в списке) и `FileAssociations`; путь к `Capabilities` прописывается в `RegisteredApplications`. После записи — `SHChangeNotify(SHCNE_ASSOCCHANGED, SHCNF_DWORD | SHCNF_FLUSH, …)`.
- **ACC-042** `[MVP]` **Приложение не может назначить себя обработчиком по умолчанию.** `IApplicationAssociationRegistration::SetAppAsDefaultAll` объявлен устаревшим в Windows 8, а страница Default Programs прямо помечена «This topic does not apply for Windows 10». Формулировка Microsoft: «The choice of default should be user driven. An application should never reclaim a default without asking the user.» Требование: в настройках — строка `open .md files with Plain · set…`, которая вызывает `SHOpenWithDialog` (для конкретного расширения) либо открывает `ms-settings:defaultapps`. Никаких трюков с прямой записью `UserChoice` (там хэш, привязанный к SID, и Windows его инвалидирует).
- **ACC-043** `[v0.2]` Иконка `.md`: 16/20/24/32/40/48/64/256 px, ICO с PNG-сжатием для крупных размеров. Дизайн — в стиле продукта: без цвета, монохромный глиф на прозрачном фоне, читаемый на 16px.
- **ACC-044** `[v0.2]` **Контекстное меню Проводника.** В Windows 11 неупакованные приложения попадают только в «Показать дополнительные параметры» (legacy-меню). Современный пункт первого уровня требует MSIX-пакета с `IExplorerCommand`-обработчиком. Решение: MVP — legacy-verb `HKCU\Software\Classes\*\shell\Plain` (только для `.md` через ProgID); `[v1.0]` — опциональная MSIX-сборка для современного меню. Это честнее, чем обещать невозможное.
- **ACC-045** `[v0.2]` **Jump List**: `ICustomDestinationList` с категорией «Recent» (последние 10 файлов) и категорией «Tasks»: `new file`, `open library`, `new window`. Требует стабильного `AppUserModelID`, установленного через `SetCurrentProcessExplicitAppUserModelID` **до** создания первого окна, и совпадающего с `System.AppUserModel.ID` в ярлыке.
- **ACC-046** `[v1.0]` Protocol handler `plain://` с валидацией пути (UX-105).
- **ACC-047** `[v0.2]` Трей — **выключен по умолчанию** (`window.tray = false`). При включении: одна иконка, меню `open · recent ▸ · new file · quit`, закрытие окна сворачивает в трей вместо выхода.
- **ACC-048** `[MVP]` Автообновление (боль #40 у Joplin — «приходится качать инсталлятор руками»): проверка при старте (`updates.check = "startup"`), скачивание — только по явному согласию, установка — при следующем запуске. Проверка обновлений — **единственный** сетевой запрос приложения, и его можно выключить полностью.
- **ACC-049** `[MVP]` Установщик — обычный MSI/NSIS per-user (без прав администратора) + портативный ZIP. WebView2 Runtime — через evergreen-бутстраппер, с корректной обработкой ситуации «рантайм отсутствует и нет интернета».

### 8.6 Локализация

- **ACC-050** `[v0.2]` Языки MVP-набора: `en`, `ru`. Все строки — во внешних JSON-каталогах, ни одной строки в коде.
- **ACC-051** `[MVP]` Микрокопия в макетах — **строчными латиницей** (`read · edit · rich`, `reading · 38%`, `+ new`, `12 files · synced`). Это осознанная часть стиля. Русская локализация сохраняет тот же регистр: `чтение · правка · вид`, `12 файлов · синхр.` — строчными.
- **ACC-052** `[MVP]` Форматы даты/времени/чисел — через `Intl` с системной локалью, независимо от языка интерфейса (пользователь может хотеть английский UI и русские даты).
- **ACC-053** `[MVP]` Подсчёт слов — `Intl.Segmenter` (UX-015). Для CJK показывается число символов, а не слов, с соответствующей подписью.
- **ACC-054** `[MVP]` Кириллица в путях, именах файлов, тегах и wikilinks поддерживается полностью, включая сортировку по локали (`Intl.Collator`).
- **ACC-055** `[v1.0]` RTL не поддерживается; заявлять поддержку арабского/иврита нельзя (A-19: честнее не обещать).

## 9. Нефункциональные требования

Измерения — на референсной машине: Windows 11 24H2, Ryzen 5 5600 / i5-12400, 16 ГБ, NVMe SSD, 1920×1080 @100%. P50/P95 по 20 прогонам.

### 9.1 Скорость

- **NFR-001** `[MVP]` Холодный старт (процесс не в кэше, WebView2 Runtime прогрет): до первого кадра с текстом файла ≤ 200 КБ — **P50 ≤ 400 мс, P95 ≤ 700 мс**. Первый в жизни запуск (создание user data folder WebView2) — ≤ 1500 мс.
- **NFR-002** `[MVP]` Тёплый старт (single instance, открытие второго файла) — ≤ 120 мс до отрисовки.
- **NFR-003** `[MVP]` Открытие файла 1 МБ: `read` — первый кадр ≤ 300 мс, полный рендер ≤ 800 мс; `edit` — ≤ 250 мс; `rich` — ≤ 900 мс.
- **NFR-004** `[MVP]` Открытие файла 10 МБ (large file mode) ≤ 1.5 с; 50 МБ ≤ 4 с.
- **NFR-005** `[MVP]` **Задержка ввода** (нажатие → глиф на экране): P95 ≤ 16 мс на файлах ≤ 200 КБ, ≤ 33 мс на 1 МБ, ≤ 50 мс на 5 МБ. Боли #6 и #59: у Typora лаги начинаются с 10 000 слов, у Markdown Monster превью тормозит после 2 000 строк — это то, что мы обязаны не повторить.
- **NFR-006** `[MVP]` Прокрутка — устойчивые 60 fps, доля пропущенных кадров < 2% на файле 1 МБ.
- **NFR-007** `[MVP]` Переключение режима `read ↔ edit ↔ rich` ≤ 80 мс без мигания и без сдвига скролла.
- **NFR-008** `[MVP]` Переключение файла (из quick search) ≤ 100 мс до отрисовки.
- **NFR-009** `[MVP]` Открытие quick search ≤ 30 мс; первый список результатов ≤ 30 мс (P95) на библиотеке 10 000 файлов.
- **NFR-010** `[MVP]` Сохранение файла 200 КБ ≤ 20 мс (не считая ожидания ФС); UI не блокируется ни на кадр.

### 9.2 Память и объём

- **NFR-015** `[MVP]` RSS в покое (окно открыто, файл 200 КБ, библиотека 1 000 файлов) — **≤ 150 МБ**. Это прямое требование из «красной линии 3»: выше этого продукт теряет преимущество перед VS Code и Obsidian.
- **NFR-016** `[MVP]` RSS при библиотеке 10 000 файлов и открытом файле 5 МБ — ≤ 300 МБ.
- **NFR-017** `[MVP]` Индекс на диске ≤ 15% от объёма индексируемого текста.
- **NFR-018** `[MVP]` Утечек нет: после 100 циклов «открыть файл → закрыть» RSS возвращается в пределы +10% от базового.
- **NFR-019** `[MVP]` Установщик ≤ 12 МБ (без WebView2 Runtime); размер установленного приложения ≤ 35 МБ. Ориентир — MDHero (~8 МБ на Tauri).
- **NFR-020** `[MVP]` В покое (окно свёрнуто/неактивно, нет ввода) — 0% CPU: никаких таймеров, кроме watcher’а и обновления относительного времени раз в 30 с.

### 9.3 Индексация и поиск

- **NFR-025** `[MVP]` Первичная индексация 10 000 файлов (~120 МБ текста): **≤ 25 с в фоне**, при этом UI полностью отзывчив, дерево доступно с первой секунды.
- **NFR-026** `[MVP]` Инкрементальная переиндексация одного файла 100 КБ ≤ 50 мс.
- **NFR-027** `[MVP]` Global search по 10 000 файлам: первые результаты ≤ 100 мс, полный набор (до 500) ≤ 400 мс (P95).
- **NFR-028** `[MVP]` Find in file на 1 МБ: подсветка видимой области ≤ 30 мс, счётчик всех совпадений ≤ 120 мс.
- **NFR-029** `[MVP]` Replace across files: 500 файлов, 5 000 замен — предпросмотр ≤ 2 с, применение ≤ 5 с.

### 9.4 Офлайн, приватность, безопасность

- **NFR-030** `[MVP]` **Ноль сетевых соединений** за всю сессию, кроме: (а) явной проверки обновлений, (б) открытия внешней ссылки в браузере (это делает браузер, не мы). Проверяется тестом: запуск, открытие библиотеки, чтение, правка, поиск, экспорт — при заблокированном сетевом доступе всё работает; счётчик исходящих соединений процесса = 0.
- **NFR-031** `[MVP]` Телеметрии нет. Аккаунта нет. Никаких «анонимных метрик использования». Отсутствие телеметрии — заявляемая фича (модель Zettlr/MDHero).
- **NFR-032** `[MVP]` Внешние ссылки открываются во внешнем браузере через `ShellExecuteEx`, никогда внутри WebView2. При `security.openExternalLinks = "ask"` (дефолт) показывается подтверждение с полным URL — защита от `[текст](https://фишинг)` в чужом файле.
- **NFR-033** `[MVP]` Схемы `javascript:`, `data:`, `vbscript:`, `file:` в markdown-ссылках блокируются полностью; `plain:` разрешён только на внутренние цели.
- **NFR-034** `[MVP]` HTML в markdown санитизируется по allow-list (теги и атрибуты), а не по deny-list. `<script>`, `<style>`, `<iframe>`, `<object>`, `<embed>`, `<form>`, обработчики `on*`, `srcdoc` вырезаются всегда, независимо от `security.allowInlineHtml`. При `"raw"` расширяется набор разрешённых тегов, но не снимается запрет на исполняемое.
- **NFR-035** `[MVP]` CSP страницы приложения:
  `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: <custom-file-scheme>:; font-src 'self'; connect-src 'self'; media-src 'self' <custom-file-scheme>:; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`.
- **NFR-036** `[MVP]` Локальные файлы (изображения, вложения) отдаются через **собственную custom-схему** с проверкой, что путь лежит внутри открытой библиотеки или рядом с открытым файлом. Прямой `file://` доступ из WebView2 запрещён.
- **NFR-037** `[MVP]` DevTools отключены в релизе (KEY-012), SmartScreen отключён (KEY-017), автозаполнение форм и паролей отключено (KEY-017).
- **NFR-038** `[MVP]` **Системы плагинов нет** (A-1). Соответственно нет и класса уязвимостей «плагин с неограниченным доступом к ФС и сети», признанного самим Obsidian.
- **NFR-039** `[v0.2]` Сборка воспроизводима, релизы подписаны, публикуется SBOM. Зависимости обновляются; поставка EOL-версии рантайма недопустима (боль #18 у Logseq).

### 9.5 Стабильность

- **NFR-040** `[MVP]` Доля сессий без падений ≥ 99.5%.
- **NFR-041** `[MVP]` **Никакое падение не приводит к потере несохранённого текста** — гарантия REL-041 (≤ 1 с до диска).
- **NFR-042** `[MVP]` Приложение не вешает ОС ни при каких входных данных (боль #5: фриз всей системы у Typora на 4 МБ).
- **NFR-043** `[MVP]` Некорректный markdown, битые UTF-8-последовательности, файлы с нулевыми байтами, символические циклы, файлы размером 0 — обрабатываются без исключений; отображается то, что удалось прочитать, с явной пометкой.
- **NFR-044** `[MVP]` Открытая проблема кода не блокирует данные: любая ошибка рендера показывает raw-текст документа, а не пустой экран.
