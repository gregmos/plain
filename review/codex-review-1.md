## 1. Внутренние противоречия

1. **[ТЗ §6.3 / строка 226]** — Rich запрещён для файлов больше 512 КБ, но §19, строка 534, требует открытия **1 МБ в Rich** за ≤900 мс. Дополнительно §12.7, строка 362, запрещает редактирование после 50 МБ, а §17, строка 501, — после 20 МБ. — **Правка:** «Единые пороги: Rich ≤512 КиБ; large-file mode >5 МиБ; только просмотр >50 МиБ». Сослаться на эту таблицу из остальных разделов; тест Rich выполнять на 512 КиБ.

2. **[ТЗ §12.5 / строка 356]** — Debounce черновика 2 секунды для файлов >1 МБ несовместим с гарантией записи за ≤1 секунду здесь же и в §19, строка 548. Обычный debounce также бесконечно откладывает запись при непрерывном вводе. — **Правка:** «Черновики записываются с debounce 400 мс и максимальной задержкой, обеспечивающей ≤1 с до завершения записи; непрерывный ввод не сбрасывает предельный срок». Для больших файлов либо обеспечить тот же предел, либо явно установить отдельную гарантию.

3. **[ТЗ §1.4 / строка 29]** — Разрешена только **явная** проверка обновлений; §15.1, строка 398, включает проверку при старте, скачивание обновлений, а §11, строка 333, — загрузку изображений. NFR-030 в строке 547 эти исключения не учитывает. — **Правка:** «По умолчанию сетевых запросов нет, `updates.check = manual`. Разрешены запросы проверки/скачивания обновления и загрузки изображения по действию пользователя либо сохранённому разрешению». Сетевой тест разделить на базовый сценарий и разрешённые операции.

4. **[ТЗ §11 / строка 333]** — Используется `security.allowRemoteImages`, хотя §13, строка 369, и OQ-19 прямо отменяют этот ключ в пользу `security.remoteImages`. — **Правка:** заменить ключ в §11 на `security.remoteImages`; старое имя разрешить только как вход миграции настроек.

5. **[ТЗ §2 / строка 43]** — Focus и контекстное меню Проводника целиком отнесены к v0.2, но скрытие панелей по F8 — MVP в строке 209, а legacy-меню — MVP в строке 392. — **Правка:** в таблице релизов разделить «скрытие панелей — MVP / затемнение абзаца и typewriter — v0.2» и «legacy-меню — MVP / современное меню — отдельный последующий этап».

6. **[ТЗ §4.3 / строка 113]** — Фиксированный модал поиска 520px шире разрешённого окна 480px. Split требует минимум 640px только для панелей (§6.4, строка 230), а reading window 420px (§15.1, строка 394) меньше общего минимума 480px. — **Правка:** задать модалу `width: min(520px, calc(100% - 32px))` и ограничение высоты; при недостаточной ширине закрывать split или запрещать его включение; отдельно определить минимум reading window.

7. **[ТЗ §15.2 / строка 404]** — Скрытые токены Rich требуется сохранять в DOM, однако §6.3, строка 216, предписывает скрывать их через `Decoration.replace`; CM6 также виртуализирует документ. — **Правка:** «Исходник полностью сохраняется в модели CM6; постоянное присутствие скрытых токенов в DOM не требуется. Доступность Rich проверяется сценариями скринридера; при необходимости предоставляется доступный Edit». [Документация CodeMirror](https://codemirror.net/docs/guide/).

8. **[ТЗ §13 / строка 369]** — Список настроек `03 §7.3` принимается целиком, включая `security.allowInlineHtml = raw`, тогда как §§9 и 18 требуют безусловной санитизации. Одновременно добавляется второй переключатель `flavor.html`. — **Правка:** удалить режим `raw`, оставить один канонический ключ с вариантами `off | sanitized`; определить миграцию второго имени и запрет обхода санитизации через настройки.

## 3. Пробелы

1. **[ТЗ §12.3 / строка 350; §17 / строка 498]** — Не описано, как сохранять индивидуальные EOL после вставок, удаления строк, undo и восстановления черновика. Одного свойства `EOL` недостаточно; позиции CM6 считают любой перевод строки одной единицей. — **Правка:** добавить карту исходных разделителей строк, обновляемую транзакциями и undo; сохранять её в черновике. Семантический парсер должен получать текст с LF; преобразования к смещениям дискового представления должны учитывать EOL и исходную кодировку. [Модель позиций CM6](https://codemirror.net/docs/ref/#text.Text).

2. **[ТЗ §12.2 / строка 347; §12.4 / строка 353]** — Защита от внешних изменений зависит от асинхронного watcher. Не определены запись поверх изменения, ещё не замеченного watcher, и поступление новых правок во время выполняющегося сохранения. — **Правка:** «Rust сериализует записи по документу. Запрос содержит ревизию буфера и базовую версию дискового файла; перед заменой проверяется актуальность базы. Подтверждение сохранения снимает dirty только с сохранённой ревизии. Изменение базы переводит документ в конфликт». Отдельно определить поведение при гонке между проверкой и заменой.

3. **[ТЗ §12.5 / строка 356]** — Черновик перезаписывается полным текстом без протокола атомарности. Сбой во время записи может испортить единственную восстановительную копию. Лимит 200 МБ не решает случай, когда всё место занято несохранёнными документами: REL-044 разрешает удалять только уже сохранённые. — **Правка:** хранить последнюю подтверждённую версию черновика до атомарного завершения следующей; при исчерпании места не удалять несохранённые данные, показывать постоянную ошибку и предлагать Save As.

4. **[ТЗ §6.4 / строка 230; §15.1 / строка 390]** — Несколько окон входят в MVP, но единый `EditorState` описан только внутри JS-контекста. Не определены владение одним файлом в двух WebView, общий undo, порядок autosave и конфликт черновиков. — **Правка:** для MVP назначить файлу единственное окно-владелец редактирования; повторное открытие фокусирует владельца, дополнительные просмотры получают его ревизии. Либо отдельно спроектировать синхронизацию буферов между окнами.

5. **[ТЗ §7.3 / строка 249; §11 / строка 330]** — Создание `Untitled.md` предполагает папку назначения, но приложение может работать без библиотеки и без открытого файла. Для такого документа также отсутствует база относительного пути `assets/`. — **Правка:** «Без доступной папки создаётся виртуальный Untitled с устойчивым ID черновика; первый Save или вставка вложения запрашивает Save As. Отмена сохраняет буфер и не создаёт вложение».

6. **[ТЗ §7.3 / строки 250–251]** — «Одна транзакция» переименования с изменением нескольких файлов не определяет частичный отказ, завершение процесса посередине и файлы с несохранёнными правками. Снапшоты нужны уже в MVP, тогда как их хранилище описано только для v1.0. — **Правка:** выделить журнал массовой операции в MVP: список файлов, исходные версии и резервные копии, стадии выполнения, восстановление после сбоя. До старта исключать конфликтующие dirty-файлы либо запрашивать их сохранение; откат не должен перезаписывать последующие чужие изменения.

7. **[ТЗ §8.3 / строки 284–285; §16.1 / строка 424]** — Семантика находится в JS/mdast, индексатор — в Rust, но не определён путь получения тегов, задач, блоков и разделов для **неоткрытых** файлов библиотеки. Не описано и преобразование Obsidian-подобного запроса в операции Tantivy. — **Правка:** зафиксировать фоновый JS Worker для семантического разбора и версионированный IPC-пакет `{fileId, revision, blocks, headings, tags, tasks, links}`; Rust управляет очередью и индексом. Описать отдельный парсер запросов и проверку точных совпадений по исходнику. Штатный [QueryParser Tantivy](https://docs.rs/tantivy/latest/tantivy/query/struct.QueryParser.html) этот контракт не заменяет.

8. **[ТЗ §6.1 / строка 191; §8.2 / строка 279]** — Блочных `data-s/data-e` недостаточно для точного копирования Markdown и замены найденного текста: `&amp;`, скрытые маркеры, code spans и сноски меняют соответствие DOM и исходника. Не определена замена в Read. — **Правка:** добавить отображение диапазонов текстовых DOM-узлов в исходник с ревизией документа; определить поведение для сгенерированных и встроенных элементов. В MVP `Ctrl+H` из Read должен переключать в Edit с перенесённым диапазоном.

9. **[ТЗ §12.7 / строка 362]** — Позиция чтения хранится только в `.plain/workspace.json`; для одиночного файла и библиотеки без прав записи место хранения не определено. — **Правка:** «Позиции всех документов по умолчанию хранятся в каталоге данных приложения по устойчивому ID; `.plain/workspace.json` — явная опция. Чтение файла не создаёт служебные каталоги рядом с ним».

10. **[ТЗ §18 / строки 511–520]** — Описан asset scope, но не права файловых IPC-команд, `http` и `opener`. Ограничение изображений не ограничивает чтение/запись через остальные команды. — **Правка:** определить capabilities по окнам и перечень разрешённых команд; файловые команды принимают зарегистрированный документ или проверенный путь, сетевые — проходят единый Rust-контроль. Ввести отрицательные тесты доступа за пределы выданных разрешений. [Capabilities Tauri](https://tauri.app/security/capabilities/).

11. **[ТЗ §6.2 / строка 208; §18 / строка 516]** — Для JS-regex и трёхсекундного лимита Mermaid не определён механизм прерывания вычисления. Лимит времени без возможности остановки не защищает UI от зависания. — **Правка:** выполнять потенциально неограниченный поиск в завершаемом Worker; отдельно подтвердить прерываемую реализацию Mermaid. По превышении бюджета отменять вычисление, сохранять работоспособность UI и показывать исходник/ошибку.

12. **[ТЗ §15.1 / строка 398; §23 / строка 622]** — Автообновление входит в MVP, но описана только отложенная Authenticode-подпись. Не заданы подпись обновлений Tauri, источник манифеста и действие при невозможности сохранить конфликтующий/read-only документ перед установкой. — **Правка:** отдельно определить ключ подписи обновлений, публичный ключ приложения и endpoint; при неуспешном сохранении/фиксации черновиков установку отменять. Для portable ZIP явно определить поддерживаемый способ обновления. [Подпись обновлений Tauri обязательна](https://v2.tauri.app/plugin/updater/).

13. **[ТЗ §19 / строки 528–548]** — Для приёмки недостаточно размера файлов и числа документов: не заданы состав корпуса, суммарный объём библиотеки, версии WebView2, границы измерения старта и учёт дочерних процессов в RSS. «0% CPU» и 99,5% сессий без падений не имеют окна наблюдения и выборки. — **Правка:** закрепить версионированный корпус и протокол измерений, включая все процессы приложения/WebView2, состояние кэшей, начало/конец каждой метрики; CPU измерять средним за заданный интервал с ненулевым допуском, crash-free — на явно заданной тестовой выборке.

## 4. Технические ошибки и сомнительные утверждения

1. **[ТЗ §17 / строка 501]** — «При вводе внутри блока — переразбор только этого блока» неверно как общее правило Markdown. Изменение reference-definition меняет ссылки в других блоках; fence, setext и контейнеры меняют границы последующего текста. Хэш исходника блока также не отражает изменение внешней зависимости. — **Правка:** полный семантический разбор считать корректной базовой реализацией; локальный разрешать только при доказанном отсутствии межблочных зависимостей. Рендер инвалидировать также по версиям definitions, embeds и профиля. [Ограничения разбора micromark](https://github.com/micromark/micromark).

2. **[ТЗ §6.3 / строка 217]** — Правило «декорации только для `view.visibleRanges`» распространено на блочные виджеты и замены переводов строк. Такие декорации влияют на расчёт viewport и должны предоставляться напрямую, до его вычисления. — **Правка:** блочные декорации хранить в `StateField` и передавать напрямую в `EditorView.decorations`; ограничение `visibleRanges` оставить для декораций, не меняющих вертикальную структуру. [Ограничение CodeMirror](https://codemirror.net/examples/decoration/).

3. **[ТЗ §11 / строка 331; §16.2 / строка 455]** — Выбраны одновременно `dragDropEnabled: true` и Pragmatic Drag and Drop, использующий HTML5 DnD. Tauri документирует необходимость отключения своего обработчика для HTML5 DnD на Windows. — **Правка:** оставить нативный Tauri DnD для внешних файлов, а внутреннее перемещение дерева реализовать через Pointer Events; Pragmatic исключить либо принять другую, проверенную спайком архитектуру. [Tauri](https://v2.tauri.app/reference/config/#windowconfig), [Atlassian](https://atlassian.design/components/pragmatic-drag-and-drop/web-platform-design-constraints/).

4. **[ТЗ §4.1 / строка 82; §6.2 / строка 201; §6.3 / строка 218]** — Номерам строк назначен контраст около 3:1; синтаксическим символам и placeholder — `--muted-soft`/`--faint`. Это значимый мелкий текст, а не автоматически освобождённый от требований декор. Заявленный текстовый порог 4,5:1 не выполняется. — **Правка:** для номеров строк, placeholder и значимых символов исходника использовать текстовые токены ≥4,5:1; `--faint` оставить только для дублирующих декоративных элементов. CI проверяет фактические пары и состояния; режим `mockup` отдельно исключается из заявления AA. [WCAG 1.4.3](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum).

5. **[ТЗ §12.3 / строка 350; §16.1 / строка 428]** — `encoding_rs` не предоставляет кодировщики **в UTF-16LE/BE**, хотя через REL-020 ТЗ принимает эти входные кодировки и обещает сохранение исходной кодировки. Также стандартные варианты кодирования с заменой могут записать HTML character references вместо непредставимых символов. — **Правка:** явно реализовать запись UTF-16LE/BE; для legacy-кодировок использовать кодирование без замены, при непредставимом символе отменять сохранение и предлагать UTF-8. [Документация encoding_rs](https://docs.rs/encoding_rs/latest/encoding_rs/).

6. **[ТЗ §9 / строка 297; §20 / строка 556]** — Footnotes названы частью базового GFM, хотя нормативная GFM-спецификация их не содержит. Кроме того, CommonMark-корпус нельзя безусловно сравнивать с итоговым HTML профиля Plain: расширения и санитизация намеренно меняют результат. — **Правка:** разделить CommonMark, GFM и расширения github.com; CommonMark-тесты запускать на чистом парсере без расширений/санитизации, а профиль Plain и безопасный DOM проверять отдельными эталонами. [Спецификация GFM](https://github.github.com/gfm/).

7. **[ТЗ §19 / строка 542]** — Безусловный предел индекса ≤15% исходного текста невыполним для произвольного корпуса: у индекса есть фиксированные накладные расходы, а словарь уникальных терминов и позиции могут занимать больше этого лимита. — **Правка:** заменить универсальную гарантию измеряемым бюджетом на закреплённом корпусе; отдельно учитывать фиксированный размер, позиции, служебные данные и временное место при слиянии сегментов.

8. **[ТЗ §15.1 / строка 392]** — Утверждение «современный пункт первого уровня — только MSIX» слишком категорично: неупакованное приложение может получить package identity через sparse package. — **Правка:** «Современное меню требует `IExplorerCommand` и package identity; допустимы MSIX либо sparse package для NSIS-установки». [Документация Microsoft](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer).

9. **[ТЗ §16 / строка 415; §16.3 / строка 465]** — Оценка «1000–1500 строк связующего кода плюс Rich» не включает обязательные собственные подсистемы из ТЗ: язык поисковых запросов, сохранение смешанных EOL, журнал массовых операций, межоконное владение и точное отображение DOM-диапазонов в исходник. — **Правка:** убрать суммарную оценку строк как основание плана; добавить эти подсистемы в перечень работ и оценить их после отдельных прототипов с критериями завершения.

## 5. Неоднозначные формулировки

1. **[ТЗ §13 / строка 369; §9 / строка 303]** — Для новых ключей не дан полный контракт типов, дефолтов и приоритетов. В частности, неясно, профиль перекрывает индивидуальные тумблеры или наоборот; что означает выключение `flavor.indentedCode`, если строка 299 требует парсить его всегда. — **Правка:** дать единую таблицу `ключ → тип → default → релиз → область действия`; установить порядок «дефолты → профиль → явные переопределения», а отключение базового indented code запретить.

2. **[ТЗ §11 / строка 333]** — Режим `block` уже показывает кнопку `load`, поэтому отличие от `ask` не определено. Неясен срок действия разового разрешения и область списка хостов. — **Правка:** например: «`block` запрещает загрузку; `ask` разрешает её после разового подтверждения; `allow-listed` автоматически загружает с разрешённых хостов; `allow` — со всех допустимых HTTPS-хостов. Разовое разрешение действует до закрытия документа; список хостов глобальный».

3. **[ТЗ §6.1 / строка 188]** — Принятые META-001…003 не определяют корректный результат для документа без учитываемых слов. Кроме того, META-001 включает CJK в `words`, а формула META-002 отдельно добавляет `cjkChars / cjkCpm`, создавая риск двойного подсчёта. — **Правка:** разделить `nonCjkWords` и `cjkChars`; считать время как сумму непересекающихся частей. При `totalWords = 0` использовать долю скролла, для документа в один экран — 100%.

4. **[ТЗ §11 / строка 330]** — «PNG без перекодирования» имеет разный смысл для PNG-байтов и растрового изображения из системного буфера: во втором случае PNG ещё нужно создать. — **Правка:** «Если доступен PNG-поток — сохранить исходные байты; если доступен только растр — один раз закодировать lossless PNG с сохранением альфы». Проверки различить на байтовую идентичность и идентичность пикселей.

5. **[ТЗ §20 / строка 558]** — Единый пункт «Playwright через CDP» включает действия вне WebView: Проводник, Win+Shift+S, DPI и аварийное завершение процесса. Неясно, что автоматизирует Playwright и кто выполняет системную часть. — **Правка:** разделить DOM-сценарии Playwright, Windows-сценарии отдельного harness/ручного прогона и принудительное завершение процесса из внешнего тестового процесса; для каждого назвать исполнителя и проверяемый результат.

## 6. Приоритизация

1. **[ТЗ §2 / строка 42; §21 / строка 588]** — Обязательный Rich делает выпуск ридера зависимым от самой дорогой и рискованной редакторской подсистемы, хотя Read + Edit уже обеспечивают чтение и точечную правку. — **Правка:** перенести Rich в v0.2 либо выпускать в MVP как экспериментальный режим, не блокирующий приёмку Read/Edit; сохранность файлов и доступность обязательны независимо от его готовности.

2. **[ТЗ §8.3 / строка 284]** — Полный язык поиска с `section:`, `block:` и семейством `task:` создаёт в MVP отдельный структурный поисковик. Для поиска README и заметок достаточно существенно меньшего набора. — **Правка:** оставить в MVP текст, точную фразу, регистр, `path:`, `file:` и `tag:`; структурные операторы перенести в v0.2 вместе с их индексной схемой.

3. **[ТЗ §21 / строки 585–586]** — Рабочая веха с autosave появляется раньше обработки внешних конфликтов. Такое промежуточное приложение уже может перезаписывать изменения другого редактора. — **Правка:** объединить сохранение, черновики, watcher открытого файла и разрешение конфликтов в одну обязательную веху; до её завершения запись на диск не включать.
