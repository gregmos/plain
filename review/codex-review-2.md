## Новые проблемы

Включены новые ошибки и остаточные расхождения между исправленными и неизменёнными требованиями.

1. **[§12.2 / строка 373]** — Утверждение, что окно гонки «закрывается» возвращённым хэшем и watcher, противоречит следующему признанию потери чужих байтов. Если внешняя запись произошла после проверки и до замены, последующее чтение может видеть уже только результат Plain. — **Правка:** определить протокол защиты либо сохранения вытесняемой версии; отдельно описать допустимые ограничения. Добавить детерминированный тест внешней записи между проверкой и заменой.

2. **[§17 / строка 558]** — `Text` объявлен единственным источником истины, а остальные данные — выбрасываемыми. Из LF-текста невозможно восстановить исходные смешанные EOL, BOM и кодировку, введённые §12.3. — **Правка:** считать первичным состоянием текст вместе с файловыми метаданными и `eolMap`; отделить от них действительно пересоздаваемые AST и кэши.

3. **[§7.3 / строка 255]** — Новый журнал допускает сбой после изменения файла, но до записи стадии. Не заданы атомарность манифеста, восстановление самого переименования, проверка изменившейся базы при `finish`; ретенция «7 дней или 50 операций» не исключает незавершённые операции. — **Правка:** определить состояния и восстановление по исходному/результирующему хэшу и путям; сделать манифест атомарным, запретить автоматическое удаление незавершённых операций.

4. **[§6.1 / строка 195]** — Новая карта расширяет выделение до целых текстовых узлов: выделение одного слова в обычном абзаце может скопировать весь абзац. Для совпадения внутри `&amp;` или code span одних `[s,e)` также недостаточно. — **Правка:** хранить отображение смещений внутри узлов, определить правила для раскрытых сущностей, скрытой разметки и embeds; переносить в Edit точный диапазон текущей ревизии.

5. **[§6.1 / строка 192]** — Формула времени чтения теперь прибавляет `images` прямо к минутам. В META-002 используется `imageSeconds/60`; если `images` — число картинок, каждая добавит минуту. — **Правка:** вернуть `imageSeconds/60` и определить расчёт секунд и настройку отключения этого вклада.

6. **[§11 / строка 358]** — В режиме `block` кнопка `allow this host` добавляет хост в список, который автоматически действует лишь при `allow-listed`. Результат нажатия не определён. — **Правка:** явно задать переход режима либо приоритет разрешения хоста над `block`; согласовать с отрицательным тестом §20, строки 629.

7. **[§18 / строка 577; §23 / строка 719]** — Обязательная прерываемость Mermaid заменяется фолбэком «100 КБ без таймаута». Ограничение размера не обеспечивает заявленный временной бюджет. При этом S-1 и S-6 в §21, строках 640, 645 не содержат проверки Mermaid, а веха Read уже требует Worker. — **Правка:** добавить явный результат спайка по прерываемому рендеру; при его отсутствии показывать исходник либо использовать проверенную изоляцию с возможностью завершения.

8. **[§20 / строки 626–630]** — Общий гейт NFR включает обязательную скорость Rich и replace across files из v0.2. Проверка «все режимы на каждом файле» невозможна для файлов свыше 512 КиБ, а сохранение — для read-only свыше 50 МиБ. Это расходится с §§2, 6.3, 12.7 и OQ-26. — **Правка:** задать матрицу «релиз × режим × размер × обязательный тест», исключить необязательные функции из гейта MVP; целостность и IME проверять для поставляемого Rich.

9. **[§19 / строки 593–611]** — Протокол определяет память как Private Working Set, таблица продолжает называть её RSS. В корпусе отсутствует 512 КиБ для NFR-003; для NFR-004 не указано, измеряется первый кадр или полный рендер и в каком режиме. Состав корпуса предписано зафиксировать, но сами доли не заданы. — **Правка:** унифицировать название метрики, дополнить спецификацию корпуса и определить начало/конец каждой операции.

10. **[§20 / строка 627]** — Тест «сеть заблокирована — всё работает, соединений 0» не задаёт настройки и не проверяет разрешённые операции, описанные в §19, строке 612. Блокировка сети сама по себе не доказывает отсутствие попыток обращения. — **Правка:** отдельно проверять отсутствие запросов в базовом сценарии и разрешённые запросы при согласии пользователя, с наблюдением попыток соединения.

11. **[§6.2 / строка 207]** — Значимый маркер hard break `⏎` остаётся `--faint`, хотя §4.1, строка 99 разрешает этот токен только для дублирующего декора. — **Правка:** использовать читаемый текстовый токен и включить состояние в проверку контраста.

12. **[§13 / строки 411–426]** — Миграция объявлена общей, но преобразования `allowRemoteImages: bool` в четырёхзначный enum и `allowInlineHtml = raw` в `off|sanitized` не заданы. У `updates.check` отсутствует значение до ответа на первом запуске. — **Правка:** добавить таблицу преобразований, приоритет при наличии обоих имён и безопасное поведение до ответа; дополнить схему `rich.enabled`.

13. **[§5.6 / строка 164]** — `Alt+Enter open to the side` и `Shift+Enter новое окно` указаны внутри MVP без оговорок, хотя split и межоконный read-only-просмотр перенесены в v0.2 (§6.0, строка 185; §6.4, строка 232). — **Правка:** определить MVP-поведение этих команд, включая повторное открытие уже принадлежащего другому окну файла.

14. **[§20 / строка 623]** — После выделения Windows-harness осталась команда `kill -9`; критерий результата аварийного завершения сформулирован только как «восстановление черновика». — **Правка:** указать Windows-механизм принудительного завершения, целевые процессы и проверяемую последнюю гарантированно сохранённую ревизию.

15. **[§16.2 / строка 512; Приложение A / строки 727–785]** — В трёхступенчатой цепочке буфера обязателен кандидат CrossCopy `tauri-plugin-clipboard`, но в списке пакетов его нет. В §16.3, строке 524 упомянут `remark-wiki-link`, также отсутствующий в списке. — **Правка:** добавить условные зависимости для соответствующих спайков либо явно обозначить их только как изучаемые примеры, не требующие установки.

16. **[§16.1 / строка 484; Приложение A / строка 734]** — Архитектурная схема называет `@tanstack/virtual`, а таблица компонентов и приложение — `@tanstack/react-virtual`. — **Правка:** унифицировать точное имя пакета.

17. **[Приложение A / строки 744–757]** — Общий runtime-список смешивает обязательные зависимости, кандидата `@atomic-editor/editor` и альтернативный DOCX-стек. `docx` отдельно в тексте не обоснован; §2 выбирает внешний Pandoc, §10 оставляет `mdast2docx` альтернативой. — **Правка:** разделить обязательные пакеты, зависимости спайков и альтернативы будущих релизов; определить основание установки `docx`. Явно отклонённых Milkdown, Tiptap, markdown-it и Pragmatic DnD среди устанавливаемых пакетов нет; `rehype-raw` не является запрещённым режимом обхода санитизации.

## Итог

ТЗ пригодно для начала изолированных спайков, но не как окончательный контракт реализации и приёмки MVP.  
До проверки сохранности нужно устранить ложную гарантию закрытия гонки и уточнить первичное состояние документа и журнал операций.  
Для первой недели необходимо явно включить спайк прерываемого Mermaid и согласовать зависимости кандидатов.  
Матрицу приёмки следует привести к экспериментальному статусу Rich, релизам функций и ограничениям размеров.
