Ты ревьюишь волну 3 («Edit без записи») проекта Plain — личного Markdown reader/editor для Windows (Tauri 2 + React 19 + TS + Vite + CodeMirror 6). Ничего не правь — только читай и пиши отзыв.

Контекст: личный проект для одного человека; норма — `ТЗ-Plain.md` (особенно §1.3, §5.0, §5.2, §10, §12, §16), дизайн — `research/00-design-system-from-mockups.md`, макет edit-view — экран 1c в `mockups/Markdown Editor.dc.html`. Код волны: `src/editor/**`, `src/ui/editor.css`, правки в `src/ui/StatusBar.tsx`, `src/app/store.ts` (поле `large`), `src/app/keys.ts` (`Ctrl+Shift+9`). Волна 1 (`src/app`, `src/ui`) уже принята — на неё смотри только как на контекст. Параллельно другой агент пишет `src/read/**` — его не ревьюй.

Ключевые решения агента, которые нужно проверить критически:
- Буферы `EditorState` живут вне React в Map по doc.id (`buffers.ts`); текст в zustand-стор синхронизируется через `requestIdleCallback`, каретка через rAF (`sync.ts`); `flushText` при уходе из edit. Волна 4 (сохранность: Ctrl+S, черновики, конфликт) будет брать текст для записи — нет ли окна, где store.text устарел относительно буфера (например Ctrl+S сразу после ввода)?
- Хоткеи по `KeyboardEvent.code` через capture-слушатель на `view.dom` (`keymap.ts`), в обход `defaultPrevented`, который ставит глобальный SWALLOW из `keys.ts`.
- `dirty` = сравнение полного текста с `savedText` на каждое изменение — стоимость на 1 МБ?
- Слушатель `plain:goto-line` на уровне модуля.

Что ищем, по приоритету:

Баги: команды форматирования (toggle-семантика, мультивыделение, границы строк, CRLF в документе — CM6 нормализует переводы строк в буфере, но `state.doc.toString()` вернёт LF: как это стыкуется с §1.3 «байты не меняются»? Это должна решить волна 4, но отметь, если модель делает это невозможным), продолжение списков, Tab, потеря событий, утечки (слушатели, буферы закрытых документов), гонки sync.
2. Несоответствия ТЗ §5.2/§12 (хоткеи, поведение) и макету 1c.
3. Оверинжиниринг — критерий «окупится ли за месяц использования одним человеком».
4. Производительность на 1 МБ: что на горячем пути ввода.

Формат: список находок, каждая — файл:строка, суть, почему важно, предложение. Раздели на «критично / стоит поправить / вкусовщина». Не пересказывай код, не хвали. По-русски, термины по-английски.
