Ты ревьюишь волну 1 («Оболочка») проекта Plain — личного Markdown reader/editor для Windows (Tauri 2 + React 19 + TS + Vite). Ничего не правь — только читай и пиши отзыв.

Контекст: это личный проект для одного человека; ТЗ — файл `ТЗ-Plain.md` (норма), дизайн-токены — `research/00-design-system-from-mockups.md`. Волна 1 по §17 п.1: скаффолд, токены/тема/шрифт, полоса режимов, статус-бар, рейка, стор, хоткеи по KeyboardEvent.code, settings.json, single-instance, аргумент-путь. Код волны: `src/`, `src-tauri/` (без icons), `package.json`, `vite.config.ts`, `tsconfig.json`, `index.html`. Rust ещё НЕ компилировался (на машине не было MSVC) — на Rust-код смотри особенно внимательно: сверяй с API tauri 2.11 (исходники плагинов лежат в ~/.cargo/registry).

Что ищем, по приоритету:
1. Баги и несоответствия ТЗ (§3, §4, §10, §12, §13, §14, §15): неверная геометрия/токены, хоткеи, которые не сработают в русской раскладке, ошибки в capabilities/permissions Tauri, CSP, неправильное использование API плагинов, ошибки в Rust (single-instance, emit, fs scope).
2. Оверинжиниринг — абстракции «на будущее», лишние слои, лишние зависимости. Критерий: «окупится ли за месяц использования одним человеком».
3. То, что затруднит следующие волны (read-пайплайн, CM6-редактор, сохранность на Rust): модель стора, границы модулей.
4. Качество вёрстки относительно макета: `mockups/Markdown Editor.dc.html` (экраны 1a/1b/1c).

Формат ответа: список находок, каждая — файл:строка, суть, почему важно, предложение. Раздели на «критично / стоит поправить / вкусовщина». Не пересказывай код. Не хвали. Отвечай по-русски, термины по-английски.
