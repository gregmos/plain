## 1. Суть

**1.1.** Читалка и редактор `.md`-файлов из обычной папки. Три вида одного документа: **read** (рендер), **edit** (исходник) и **rich** (исходник со скрытыми маркерами, как Typora; делается последним, волна 7). Библиотека = папка. Ни базы, ни сети, ни аккаунта.

**1.2. Зачем.** На Windows нет лёгкой читалки markdown: VS Code тяжёл, Typora платный и лагает, Obsidian навязывает vault. Хочется: двойной клик — читаешь; поправил — файл остался твоим байт в байт.

**1.3. Три правила.**
1. **Файл — источник истины.** Байты, которых пользователь не касался, не меняются: маркеры списков, отступы, trailing spaces, BOM, финальный перевод строки. `Ctrl+S` без изменений не пишет на диск вообще. Два исключения, действующие только при реальном сохранении правок и сопровождаемые сообщением в статус-баре: смешанные переводы строк приводятся к доминирующему стилю; файл в legacy-кодировке (cp1251 и т.п.) сохраняется в UTF-8 после явного подтверждения.
2. **Ноль сети.** Единственный сетевой запрос — внешняя картинка после клика по ней.
3. **Комфортно.** Открыть и поправить свои документы без ожидания. Ориентиры: старт около полсекунды, набор без лагов на файле 1 МБ, памяти меньше, чем у VS Code. Проверяется Task Manager, не тестами.

**1.4. Дизайн** (из макетов): IBM Plex Mono везде; один фиолетовый акцент — каретка, выделение, точка «изменено», активный элемент; без иконок (глифы `⌕ ◐ ◑ ● ▸`); без скруглений и теней внутри окна; иерархия расстоянием и 1px-линиями; микрокопия строчными латиницей.

**1.5. Не делаем**: плагины, синхронизацию, БД, граф, блочный DnD, AI, коллаборацию, тулбар, второй движок диаграмм, автоформатирование, свой диалект, обязательный vault, телеметрию, автообновление, локализацию, пресеты клавиш, полнотекстовый индекс, DOCX, jump list, трей, протокол, MSIX, поддержку скринридеров, порталы для 10 000 файлов. Полный разбор — `review/overengineering-pass.md`.

## 2a. v0.2 — уточнения `[v0.2]`

Принцип тот же: минимальная первая итерация каждого пункта, в стиле библиотеки, без новых подсистем.

- **Картинки из буфера и DnD.** В edit/rich `Ctrl+V` с картинкой в буфере (plugin-clipboard-manager `readImage`) или DnD файла-картинки на редактор → PNG сохраняется в `assets/` рядом с документом (создать при необходимости; имя `YYYY-MM-DD-HHmmss.png` или исходное имя файла при DnD, коллизии — суффикс), в текст вставляется `![](assets/<имя>)`. Безымянный буфер — сначала Save As. Папка `assets` добавляется в asset-scope.
- **Автосохранение.** Настройка `files.autosave: 0 | 1…60` секунд (0 = выключено, дефолт 0). При ненулевом значении через N секунд после последнего изменения вызывается обычный `save()`; конфликты/ошибки — как при ручном. Статус `saved` без сообщений. Ручной `Ctrl+S` продолжает работать.
- **Snapshots и история версий.** При успешном `Ctrl+S`/автосохранении, если с прошлого снимка прошло ≥ 5 минут — копия **записанных байтов** в `%APPDATA%\Plain\history\<id>\<ISO-время>.md`; хранение 30 дней (чистка при старте). `file → version history…` / `> version history`: экран в стиле библиотеки — список снимков (дата, размер, первые слова отличия не нужны), `restore` (с подтверждением; текущий текст перед восстановлением тоже сохраняется снимком), `open` (открыть снимок как read-only документ), `delete`. Diff между снимком и текущим — тем же экраном, что конфликт (ниже).
- **Diff при конфликте.** В баннере конфликта третье действие `compare`: экран в стиле библиотеки с построчным diff (`diff` npm, `diffLines`), удалённые строки — `--muted` с зачёркиванием, добавленные — фон `--selection`; сверху `disk · buffer`, действия `keep mine · take disk · close`. Тот же экран для `compare` в истории версий.
- **Экран библиотеки** (макет 1e). `view → library` / `Ctrl+Shift+L`? — нет, `Ctrl+Shift+L` занят списком; используется `Ctrl+Alt+L`. Заголовок `library`, список всех файлов дерева: имя + относительный путь, дата изменения, слова; сортировка `modified · name · created` (mtime/ctime — из `read_tree`, расширить), слова — считаются лениво для видимых строк и кэшируются на сессию (`countWords` по тексту файла через `read_file`), `+ new`, футер `N files · M words` (M — только для посчитанных). Клик — открыть. Фильтр по тегу (ниже). Без индекса на диске.
- **Теги.** Настройка `library.tags: bool` (дефолт `true`); секция `tags` в рейке и теги в мета-строке показываются только когда в библиотеке/документе теги реально есть — пустая секция не рисуется. `#тег` в тексте (не в code, не в URL, не заголовок `# `: только `#` + буква без пробела) распознаются read-пайплайном (micromark-расширение или пост-проход по text-узлам) и рендерятся `--muted` кликабельно → фильтр библиотеки. Список тегов документа — в мета-строке read после времени чтения. Секция `tags` в рейке (макет 1e) — теги открытых документов + библиотеки (сбор по библиотеке — через Rust `search_folder` regex `(^|\s)#[\p{L}\d_-]+`, один проход при открытии библиотеки и по `tree-changed` с debounce 2 с).
- **Backlinks.** Секция `links here` в рейке (режим outline, макет 1d): файлы библиотеки, ссылающиеся на текущий (`[[имя]]`, `[[имя|…]]`, `[[имя#…]]`, относительные `](…имя.md)`), через Rust `search_folder` по regex с именем файла; пересчёт при смене активного документа, кэш на сессию по имени. Клик — открыть.
- **Фокус-режим** `F8`: скрыть меню, рейку, полосу режимов и статус-бар; остаётся колонка текста; `F8`/`Esc` возвращает. Состояние не сохраняется.
- **Кастомный title bar** — **закрыт 2026-09-05**: спайк `tauri-plugin-decorum` 1.1.1 провалился по правилу одного дня — перетаскивание и maximize работают, но snap layouts плагин имитирует нажатием Win+Z через enigo, и на Windows 11 25H2 это не срабатывает (настоящий snap требует `WM_NCHITTEST`/`HTMAXBUTTON`, отдельная работа). Системный title bar остаётся навсегда.
- **Portable-режим.** Если рядом с `plain.exe` есть папка `data\` — `settings.json`, `drafts\`, `state.json`, `history\` живут в ней вместо `%APPDATA%\Plain`. Ничего больше.
- **Split view.** `view → split` / `Ctrl+Shift+\`: контент делится на две колонки (`react-resizable-panels`, разделитель 1px `--border`, перетаскивается): слева edit (или rich), справа read того же документа, read обновляется по idle-flush текста (debounce 300 мс) и держит скролл у того же заголовка, что каретка слева. Полоса режимов показывает `split` подчёркнутым; `Ctrl+/` в split — выход в read. Ширина колонок — в сессии. Две колонки с разными документами — не делаем.
- **Экспорт HTML.** `file → export ▸ html…`: один самодостаточный `.html` (UTF-8): рендер read + инлайн CSS (токены light, read.css без зависимостей от шрифта: `font-family` со списком fallback, Plex Mono не встраивается), KaTeX — HTML+CSS KaTeX инлайн (минимальный набор классов — допустимо взять `katex.min.css` целиком, ~25 КБ, шрифты KaTeX не встраиваются → формулы могут выглядеть иначе; это принято), Mermaid — SVG, снятый из DOM, если диаграмма уже отрисована, иначе исходник, картинки — локальные как data URI (до 2 МБ каждая), внешние — как есть. Без JS.

## 2b. Окна `[v0.3]`

Решение владельца 2026-09-12 (по мотивам PR #3 от auslander969, переработан): окон может быть несколько, но только на время работы. `Ctrl+Shift+N` открывает новое окно на той же библиотеке, пустое, каскадом от текущего; `Ctrl+Shift+W` закрывает окно (в единственном окне = выход). Окно — свой webview и свой store; общее между окнами: настройки (запись в одном применяется во всех), список `recent` (файл, открытый или сохранённый под именем в любом окне, попадает в `recent` всех), правило «один файл — одно окно» (по каноническому пути; попытка открыть занятый файл выводит вперёд окно-держателя), маршрутизация путей извне (второй запуск, Finder — в сфокусированное окно). `state.json` пишет окно-писатель: сначала `main`, при его закрытии роль переходит к следующему окну; при выходе пишет писатель на момент выхода; сессия — содержимое последнего закрытого окна. Окна после перезапуска **не восстанавливаются** (владелец: «после ребута окна не нужны, есть recent»), позиции чтения и прочее состояние вторичных окон теряются. Выход (`exit`, `⌘Q`, Dock Quit) спрашивает каждое окно про своё несохранённое; отмена в одном окне оставляет уже закрывшиеся закрытыми. Черновики предлагает только `main` при старте. Спека волны — `review/waves/w13-windows-spec.md`.

## 3. Дизайн-система

Геометрия, типографика и токены — как в макетах (`research/00` — справочная выжимка, не норма; при расхождении с макетом или удобством побеждает удобство), с одной поправкой: **`--muted`** в макете (`#8a877f` light / `#7a776f` dark) даёт 3.3:1 и 4.1:1 — на 10–12px плохо читается. Принято: light `#6b6760`, dark `#8a877f`; исходные значения — `--muted-soft` для нетекстового (маркеры списков, рамки чекбоксов). `--faint` (`#c9c5bb` / `#3a3936`) — только декор.

Колонка read 560px по умолчанию (69 символов Plex Mono при 13.5px/1.75), edit = read + 80. Ширина меняется перетаскиванием любого края колонки (невидимая зона 12px по бокам, курсор `col-resize`, при drag — 1px линия `--muted`) в пределах 440–1400 и пишется в `appearance.contentWidth`; на экранах шире 1600 при первом запуске дефолт 720. H1 22px/600; H2 13.5px/600 `--muted` (проверить на живом тексте, иначе `--fg`); H3–H6 13.5px/600. Окно по умолчанию 1100×720, минимум 480×400. Title bar — **системный** в v0.1 (кастомный из макета — кандидат v0.2; если decorum не заработает за день — остаётся системный). Breadcrumbs `folder / file.md` — в левом краю полосы режимов.

Состояния: изменён — `•` в заголовке вкладки/окна и `●` в рейке, статус `unsaved`; сохранён — `saved`; тема — `◐ light` / `◑ dark` кликом; hover — `--fg` без фона; активный — фон `--surface`; фокус — `outline 1px --accent, offset 2px`. Экраны вне макетов (find, поиск по папке, конфликт, черновики, меню) — «в стиле библиотеки»: заголовок 22px/600, список с `border-top 1px --border`, текстовые контролы.

## 4. Интерфейс `[v0.1]`

- **Окно.** Системный title bar. Полоса режимов 44px: слева breadcrumbs, по центру `read · edit · rich` (активный — подчёркивание 1px), `Ctrl+/` переключает read↔edit, `Ctrl+Alt+1/2/3`. Статус-бар 30px: слева `ln 9, col 118` (edit) или пусто (read) и временные сообщения на 3 с; справа `utf-8` (кликабельно → `reopen as…`), `612 words`, `unsaved · saved · read-only · deleted on disk · large file`, `◐ light`.
- **Рейка** 232px по умолчанию, ширина 180–420 перетаскиванием правой границы (1px `--border`, на hover/drag — `--muted`, курсор `col-resize`), запоминается в сессии; кнопка сворачивания `◂` в футере рядом с `files · outline` и `Ctrl+\` (свёрнута → лейбл `▸ files` в полосе режимов): сверху всегда секция `open` (открытые файлы, активный — `--surface`, `●` у изменённых, клик — переключить, средняя кнопка / `Ctrl+W` — закрыть); ниже — `files` (дерево по папкам, секции uppercase 10px) или `outline` (заголовки текущего файла без `#`, отступ 18px на уровень, активный раздел подсвечен) — переключатель `files · outline` в футере. Дерево — обычный DOM; виртуализация — если станет тормозить. Контекстное меню файла: `open · rename · reveal in explorer · delete`; папки: `new file · new folder · reveal in explorer`. Rename здесь — просто переименование файла, без правки ссылок.
- **Вкладки** — это секция `open`; отдельной полосы вкладок нет. `Ctrl+Tab` — циклически по списку, без всплывающего окна.
- **Quick search `Ctrl+K`** (макет 1f): модал `min(520px, 100% − 32px)`, top 120px; пустой ввод — `recent`; ввод — файлы по пути (uFuzzy, совпавшие символы `--accent`); `>` — команды (cmdk). Подвал `↑↓ move · ↵ open · ctrl ↵ open in edit`.
- **Пустое состояние**: `open a file · open a library` и `recent`.
- **Меню** — собственная строка меню в дизайн-системе (Radix Menubar), 28px под системным title bar: пункты `file · edit · view · help` 11px `--muted` (hover/открытый — `--fg`), выпадающие списки — как quick search/контекстное меню: фон `--bg`, рамка 1px `--border`, строки 12px `padding 5px 14px`, хоткей справа 10.5px `--muted`, разделители 1px, отметка — глиф `●`; без скруглений и теней. Нативное меню Windows не используется (Segoe UI и капс ломают типографику). Состав: `file` (new · new window · open… · open library… · recent ▸ · save · save as… · reopen as ▸ · close · close window · exit), `edit` (undo · redo · find · replace · bold · italic · link… · list · heading ▸), `view` (read · edit · files · outline · line numbers · theme ▸ · always on top · fullscreen · zoom in/out/reset), `help` (settings… · about). Пункты дублируют команды палитры и хоткеи и берутся из одного реестра команд.
- **Диалоги** — модал 420px, текстовые действия, `Esc` = отмена. **Баннеры** (конфликт, ошибка записи) — 36px под полосой режимов, `--surface`, не крадут фокус. Тостов нет.

## 5. Режимы

**5.0. Общее.** Один буфер на файл — `EditorState` CodeMirror 6 со стандартной историей. Read — HTML из того же текста, строится при входе в read (не в фоне на каждый символ). При переключении сохраняются каретка/выделение (edit) и позиция скролла каждого режима; переход read → edit ставит скролл на тот же заголовок. При буфере: кодировка, BOM, доминирующий EOL, финальный `\n`, `baseHash` (хэш файла на диске, из которого загружен буфер).

**5.1. Read** `[v0.1]`
- `remark-parse` + `remark-gfm` + `remark-math` + `remark-frontmatter` + два собственных micromark-расширения (**wikilinks** `[[file]] [[file|alias]] [[file#Heading]]`, **callouts/alerts** `> [!note]`) + `==highlight==` через готовый `remark-flexible-markers` → `remark-rehype` → `rehype-raw` → `rehype-sanitize` (GitHub-схема) → `rehype-slug` → HTML. Заголовки несут `id` (slug) — этого достаточно для outline и перехода read → edit «на тот же заголовок».
- Над H1: `4 sep 2026 · 612 words · 3 min` (дата — front matter `date`, иначе mtime; слова — `Intl.Segmenter` без fenced code; время — слов / 200).
- Элементы: заголовки с якорем (hover `#` копирует ссылку); таблицы со скроллом; картинки `max-width: 100%` (клик — открыть системным просмотрщиком); code block с лейблом языка и `copy` на hover; сноски — обычные ссылки вниз; callouts без иконок (uppercase-лейбл, левая линия); `<details>`; `==mark==`; wikilink на отсутствующий файл — `--muted`, некликабелен.
- Чекбоксы некликабельны. Копирование — обычное браузерное.
- Ссылки: внутренние — переход с историей `Alt+←/→`, путь в статус-баре при hover, `Ctrl+клик` — в новой вкладке; внешние — во внешний браузер.
- Зум — встроенный WebView2 (`Ctrl+=/-/0`, `Ctrl+колесо`); ничего своего.
- `Ctrl+F` в read — свой find-бар по тексту рендера (CSS Custom Highlight API), без маппинга в исходник; `Ctrl+H` → edit.

**5.2. Edit** `[v0.1]`

Во время IME-композиции автозамен нет (CM6 делает это сам).

## 6. Файлы и папка `[v0.1]`

- **Открытие.** Файл — двойным кликом/аргументом/DnD на окно: сразу read, рейка свёрнута, без приветствий. При нескольких окнах (§2b) файл открывается в сфокусированном окне; файл, уже открытый в другом окне, второй раз не открывается — вперёд выходит то окно. Папка — `Ctrl+Alt+O`, `> open library`, DnD папки: рейка `files`. Последняя папка и открытые файлы восстанавливаются при старте без аргументов (`state.json`). Без папки работает всё, кроме дерева и поиска по папке.
- **Дерево.** `.md .markdown` (+ `.txt` через настройку); натуральная сортировка, папки первыми; скрыты dot-папки и `.git .obsidian node_modules`; симлинки не разворачиваются. Метаданные файлов (заголовок, слова) **не собираются** для всей папки — только для открытого файла.
- **Операции.** `new file` (`Ctrl+N`, `+ new`, контекстное меню папки) → файл `Untitled.md` (коллизии — `Untitled 2.md`) создаётся **сразу** и **сразу открывается в edit** с кареткой в пустом тексте; одновременно в дереве его имя стоит в inline-поле переименования с фокусом: набрал имя → `Enter` переименовывает и переносит фокус в текст, `Esc` оставляет `Untitled.md` и тоже уходит в текст. Без папки — безымянный буфер с устойчивым id, `Ctrl+S` = Save As. (Уточнение 2026-09-06 по замечанию владельца: раньше документ не открывался, пока имя не введено.) `rename` — переименование файла на диске (ссылки не трогаются, later). `delete` — системная корзина (`trash`). Удалённый извне открытый файл: буфер живёт, статус `deleted on disk`; `Ctrl+S` пересоздаёт, если в буфере есть правки (§8).
- **Watcher.** `notify` + debounce 150 мс по корню папки (игнорируемые папки не наблюдаются). По одному watcher на окно: окно получает события только по своим файлам и своей библиотеке (§2b). Событие по открытому файлу считается **собственным**, если хэш содержимого на диске равен хэшу последней собственной записи; иначе — внешним (§8). Событие по дереву — обновить дерево. Если папка лежит в OneDrive/сети и события не приходят — проверить лично (OQ-4); polling пока не делается.
- Приложение не создаёт в папке пользователя служебных постоянных файлов (никаких `.plain/`, индексов, кэшей); только то, что создал сам пользователь, и временный файл на миллисекунды записи.

## 7. Поиск по папке `[v0.1]`

`Ctrl+Shift+F` → экран в стиле библиотеки: поле, результаты по файлам (имя + путь + строки контекста с подсветкой). Движок — Rust-команда: обход через `ignore`, подстрока без учёта регистра (тумблер `Aa`) или regex (тумблер `.*`), параллельно через `rayon`; результат отдаётся одним ответом; ответ на устаревший запрос отбрасывается. Никакого языка запросов и индекса. Файлы > 2 МБ пропускаются с пометкой.

## 8. Сохранность `[v0.1]` — единственный раздел, где не экономим на корректности

- **Сохранение — ручное, `Ctrl+S`.** Автосохранение — кандидат v0.2 (одна настройка задержки). При закрытии с несохранённым — один диалог `save · don't save · cancel` со списком файлов.
- **Никакого автоформатирования** (§1.3). Чистый документ при `Ctrl+S` не записывается.
- **Атомарная запись.** Снимок текста буфера + его версия → Rust: temp-файл в той же папке → `FlushFileBuffers` → `ReplaceFileW` (сохраняет creation time и атрибуты); файла нет — `MoveFileExW`. Перед записью файл на диске хэшируется и сравнивается с `baseHash`: не совпал — не писать, баннер конфликта. **Файл отсутствует** (удалён извне) — отдельный случай: буфер с правками записывается без проверки хэша, статус `recreated`; чистый буфер без файла ничего не пишет. Записи одного документа выполняются последовательно. По завершении успешной записи `baseHash` **всегда** обновляется хэшем записанного снимка (иначе следующая запись поймает конфликт с собственным файлом); далее фронтенд сравнивает текущий текст со снимком: равен — `saved`, черновик удалён; не равен — остаётся `unsaved`, черновик остаётся (с новым `baseHash`). Ошибка — баннер `couldn't save — <причина> · retry · save as…`. Режима in-place записи нет.
- **`don't save`** при закрытии — явный отказ от правок: ожидающая запись отменяется, черновик удаляется, при следующем запуске ничего не восстанавливается.
- **Кодировки.** Чтение: BOM → UTF-8 → `chardetng`. Запись: в кодировке файла, если это UTF-8 или UTF-16 (BOM как был); legacy → при первом сохранении правок `convert to UTF-8 · save as… · cancel`. EOL — доминирующий стиль файла (новые — из `files.newFileEol`, по умолчанию CRLF); смешанный → нормализация с сообщением. `utf-8` в статус-баре кликабельно → `reopen as… (utf-8 · cp1251 · utf-16)`.
- **Внешние изменения.** Нет локальных правок → тихая перезагрузка, скролл на тот же заголовок, статус `reloaded from disk`, одна точка undo; текст, который был на экране, перед заменой уходит в историю версий (если отличался от прочитанного) — статус тогда `reloaded from disk · previous version kept in history`; снимок — best effort: неудача копии не мешает перезагрузке. Есть правки → баннер `file changed on disk · reload · save my copy as…` (`reload` — с подтверждением потери правок; diff — кандидат v0.2). Проверка внешней версии — по watcher и дополнительно при возврате фокуса окну.
- **Черновики.** Любое изменение буфера → `%APPDATA%\Plain\drafts\<id>.json` (id — хэш пути или id безымянного буфера): текст, путь, `baseHash`, кодировка, BOM, EOL, каретка. Debounce 500 мс, при непрерывном вводе — не реже раза в 2 с; запись temp+rename. Удаляется только после подтверждённого сохранения этого текста. Ошибка записи черновика — постоянный баннер `can't write recovery draft`. При старте с непустым `drafts/` — экран `unsaved work found`: `restore · discard` (discard — в корзину).
- **Сессия** — `state.json` (открытые файлы, активный, режимы, скролл/каретка, окно, рейка, последняя папка, недавние 20, позиции чтения — LRU 300) с debounce 2 с и при закрытии. Один снимок одного окна: при нескольких окнах его пишет окно-писатель (§2b); окна после перезапуска не восстанавливаются; `recent` общий для всех окон.
- **Большие файлы.** > 2 МБ — подсветка выключена, read по кнопке `render anyway`; статус `large file`. Ничего не обрезается молча.
- **Snapshots** `[v0.2]` — копия файла в `%APPDATA%\Plain\history\<id>\<ts>.md` при `Ctrl+S` не чаще раза в 5 мин, 30 дней; снимки, которые запрошены явно (перед `restore`, перед перезагрузкой после внешнего изменения), пишутся всегда — правило 5 минут на них не действует; `> version history` → список → `restore`.

## 9. Локальные картинки и ссылки `[v0.1]`

Локальные картинки — Tauri asset protocol; scope выдаётся динамически на папку библиотеки или папку открытого файла. Картинка вне scope (`../images/x.png` у одиночного файла) → плашка `outside folder · allow` (добавляет её папку в scope на сессию). Внешние картинки — плашка с хостом и `load`. Изменение картинки на диске не отслеживается (перерисовка — `F5`). Вставка картинок из буфера и DnD в текст — v0.2; пока — сохранить PNG в `assets/` руками и написать `![](assets/x.png)`.

## 10. Настройки `[v0.1]`

Файл `%APPDATA%\Plain\settings.json`, читается при запуске. Редактируется на **экране настроек** (`help → settings…`, `> settings`, `Ctrl+,`) — экран «в стиле библиотеки» (макет 1e): заголовок `settings`, список строк `ключ · значение` с текстовыми контролами (переключатели-слова, числа с `−/+`, выбор из вариантов), изменения применяются сразу и пишутся в файл; внизу ссылка `open settings.json` для ручной правки. Переключатель темы в статус-баре и `Ctrl+Shift+D` тоже записывают `appearance.theme`. Битый JSON при запуске — дефолты и баннер `settings.json is invalid`. Настройки едины для всех окон: запись в одном окне применяется в остальных (§2b). Ключей мало:

```
appearance.theme         "system" | "light" | "dark"   system
appearance.fontSize      11–20                         13.5
appearance.contentWidth  440–1400                      560
read.codeWrap            bool                          false
edit.lineNumbers         bool                          true
edit.indentUnit          "tab" | 2 | 4                 2      (отступы файла имеют приоритет)
files.newFileEol         "crlf" | "lf"                 crlf
library.extensions       string[]                      [".md", ".markdown"]
```

Всё остальное — константы в коде. Появится потребность — станет настройкой.

## 11. Синтаксис `[v0.1]`

CommonMark + GFM (таблицы, task lists `[ ]`/`[x]`, `~~strike~~`, autolinks, footnotes, alerts `> [!NOTE]`) + YAML front matter (не рендерится) + `$…$`/`$$…$$` (правила против валюты: нет пробела внутри границ, за закрывающим `$` не цифра) + `==highlight==` + wikilinks + callouts Obsidian (единая реализация с alerts) + ```` ```mermaid ```` + санитизированный HTML. Hard break — два пробела или `\`. Slug'и как у GitHub. Всё остальное (embeds, теги, комментарии `%% %%`, emoji, sup/sub, smart punctuation, definition lists) — нет. Read и edit используют разные парсеры (micromark и Lezer); в edit собственные конструкции не подсвечиваются специально, и это принято.

## 13. Windows `[v0.1]`

Single instance (`tauri-plugin-single-instance`): второй запуск передаёт путь в сфокусированное окно и фокусирует его — и перед передачей отдаёт первому экземпляру право выйти на передний план (`AllowSetForegroundWindow`), иначе Windows только мигает кнопкой в панели задач. Ассоциация `.md`/`.markdown` per-user (`HKCU` ProgID + `Capabilities`, чтобы появиться в «Открыть с помощью»); приложение не назначает себя по умолчанию — в `about` ссылка `ms-settings:defaultapps`. Аргумент командной строки — путь. Always on top `Ctrl+Shift+A`. Тема следует Windows; `prefers-reduced-motion` отключает мигание каретки. Сборка — папка с exe (zip); NSIS — если захочется. Exe подписан (v2.7): сертификат Certum Cloud Code Signing владельца, тот же, что у pii-shield — ключ в облаке Certum, подпись через SimplySign Desktop (сессия по токену с телефона, ~2 ч); `scripts/pack.ps1` проверяет сессию до сборки, подписывает копию exe signtool-ом (SHA-256, RFC 3161 timestamp `time.certum.pl`) и не делает zip без валидной подписи с меткой времени; `-Unsigned` — тестовая сборка с суффиксом в имени zip. Сертификат обычный (не EV), поэтому SmartScreen может спрашивать, пока не наберётся репутация — в README. WebView2 в Windows 11 предустановлен.

## 13a. macOS `[v0.2]`

Решение владельца 2026-09-05: порт на macOS сразу. Ограничение: у разработчика нет Mac — сборка и проверка «на бумаге» плюс CI; первая живая проверка — у владельца или знакомого с Mac. Принцип соразмерности сохраняется: минимум платформенных веток.

- **Сборка**: GitHub Actions, `macos-latest`, `tauri-apps/tauri-action`, цель `dmg` (universal — `aarch64-apple-darwin` + `x86_64-apple-darwin`, если укладывается в лимит минут; иначе только aarch64). Ad-hoc подпись без Developer ID и нотаризации; на macOS 15 (Sequoia) правый клик → Open больше не обходит Gatekeeper: путь — попытка запуска → System Settings → Privacy & Security → Open Anyway; вариант из терминала — адресное `xattr -dr com.apple.quarantine /Applications/Plain.app`. Артефакт публикуется в GitHub Release рядом с zip для Windows. Workflow также гоняет `cargo test` и `vitest` на macOS.
- **Rust**: `ReplaceFileW`/`MoveFileExW` — только `#[cfg(windows)]`; на unix атомарная запись — temp в той же папке → перенос mode (обязательно; ошибка — отказ от записи) и xattr (best effort, включая Finder tags) → `fsync` файла → `rename` (атомарен в POSIX) → `fsync` каталога. Файлы с `nlink > 1` — предупреждение при открытии (другие имена сохранят старый текст). `read_only` — по фактической возможности открыть на запись, не только по mode. `assoc.rs` (HKCU) — только Windows; на macOS ассоциация `.md` — через `bundle.fileAssociations` в `tauri.conf.json` (Info.plist `CFBundleDocumentTypes`), открытие файла из Finder — событие `RunEvent::Opened`/`tauri://open` (Tauri 2), кладётся в пакет сфокусированного окна (§2b). Файл, пришедший из Finder после того, как фронтенд уже забрал очередь путей (холодный запуск двойным кликом — Apple Event идёт в гонку с загрузкой страницы), ждёт конца старта и добавляется к восстановленной сессии активным документом, в отличие от argv-аргумента на Windows, который заменяет список открытых файлов сессии. `canonical`: срез `\?\` только на Windows. `read_only` — по режиму файла. Крейты `windows`, `winreg` — `[target.'cfg(windows)'.dependencies]`. `files.newFileEol` по умолчанию `lf` на macOS.
- **Клавиши**: на macOS `Ctrl` в описаниях сочетаний означает `⌘` (metaKey), `Alt` — `⌥`; матчинг по `KeyboardEvent.code` сохраняется. Отображение в меню/экране хоткеев — глифы `⌘ ⌥ ⇧ ⌃`. Исключения (конфликты с системой), одной таблицей `macOverrides` в реестре: история `Alt+←/→` → `⌘⌥←/→` (⌘[/⌘] занят отступом в редакторе, ⌥←/→ — движение по словам); `F11` fullscreen → `⌃⌘F`; `Ctrl+Tab` → буквальный `⌃Tab` (⌘Tab — системный); `Ctrl+H` replace → `⌘⌥F` (⌘H — Hide); zoom `⌘=`/`⌘-`/`⌘0` как настоящие чорды (WKWebView не имеет встроенного зума); `Ctrl+,` — `⌘,`. `pathKey` не приводит регистр на macOS (APFS может быть регистрозависимой).
- **Меню**: на macOS Tauri создаёт стандартное системное меню, но его Quit (`⌘Q`) завершает процесс мимо диалога несохранённых (§8), а Close Window (`⌘W`) и Hide (`⌘H`) перехватывают наши сочетания. Поэтому native-меню собирается своё, минимальное: App (About, Services, Hide, Hide Others, Show All, **свой** `Quit Plain ⌘Q` → сценарий закрытия документов с диалогом → `exit`), Edit (системные Undo/Redo/Cut/Copy/Paste/Select All — нужны WKWebView), Window (Minimize, Zoom; без Close Window). Dock → Quit идёт через `ExitRequested` → `prevent_exit` → тот же сценарий. При нескольких окнах каждое проходит свой сценарий закрытия; приложение завершается, когда закрылось последнее (§2b). Наше меню в дизайн-системе остаётся.
- **WebView (WKWebView)**: `requestIdleCallback` отсутствует в Safari — есть fallback на `setTimeout` (проверить, что везде через одну обёртку); CSS Custom Highlight API — Safari ≥ 17.2 (macOS 14+; минимальная ОС — macOS 13? тогда find в read деградирует до «без подсветки» с проверкой `CSS.highlights`); `::selection`, `Intl.Segmenter`, clipboard — ок. Скроллбары — системные overlay. Zoom — `setZoom` работает.
- **Пути и данные**: `app_data_dir()` → `~/Library/Application Support/Plain`; portable `data/` рядом с `.app` не поддерживается (бандл), пункт только для Windows. Корзина — `trash` крейт (Finder Trash). Watcher — FSEvents через `notify`. Пути в UI — `/`.
- **Не делаем**: подпись/нотаризацию, Touch Bar, Apple-специфичный title bar (traffic lights системные и так), Sparkle/updater, App Store.

## 14. Безопасность `[v0.1]` — четыре строки

`rehype-sanitize` с GitHub-схемой (без `script/style/iframe/object/embed/form`, `on*`, атрибута `style`; `javascript:`/`data:` в ссылках вырезаются, `data:image/*` в `<img>` разрешён кроме SVG). Внешние ссылки — во внешний браузер; webview не навигирует (`on_navigation` allowlist). Локальные файлы — только через asset protocol с динамическим scope (§9). CSP Tauri по умолчанию + `img-src https: data: blob: asset: http://asset.localhost`, без `unsafe-eval` и CDN. Файлы свои — этого достаточно.

## 16. Тесты `[v0.1]` — только то, что ломается тихо

- `cargo test`: атомарная запись + проверка хэша + последовательность записей; определение и запись кодировок (UTF-8/BOM, UTF-16, cp1251); поиск (подстрока, regex, пропуск больших файлов); черновик temp+rename.
- Vitest: корпус ~30 своих и чужих файлов с однородными EOL и в UTF-8/UTF-16 — **открыть → сохранить с одной правкой → диф затрагивает только правленые строки** (BOM, CRLF, trailing spaces, финальный `\n` сохранены); отдельные тесты двух разрешённых преобразований — файл со смешанными EOL получает доминирующий стиль, файл cp1251 после подтверждения становится UTF-8 с тем же текстом; word count; разрешение путей ссылок с кириллицей и `%20`; два micromark-расширения на своих примерах.
- Ручной чек-лист перед тем, как показать знакомым (~15 пунктов): двойной клик из Проводника, тёмная тема, DPI 150%, kill процесса → черновик восстановился, внешняя правка файла → баннер, файл 10 МБ, папка в OneDrive.

Playwright, CommonMark spec, сравнение AST двух парсеров — не делаются.

## 17. Порядок работы

1. Оболочка: Tauri + React, окно, тема, токены, шрифт, полоса режимов, статус-бар, аргумент-путь, single instance.

5. Папка: дерево, `open`, quick search, создание файла, корзина, поиск по папке. Параллельно: строка меню и экран настроек.
6. Ассоциация `.md`, чек-лист, zip.
7. Rich-режим и плавающая панель форматирования (панель — можно раньше, вместе с волной 5).

Спайков заранее нет. Единственная проверка перед началом — что WebView2 + CM6 стартуют за приемлемое время на своей машине (полдня).
