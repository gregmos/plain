## 1. Цель и позиционирование

**1.1. Что делаем.** Десктопное приложение для чтения и правки Markdown-файлов, живущих в обычных папках. Три поверхности одного документа: **Read** (рендер), **Edit** (исходник), **Rich** (live-preview в духе Typora: разметка видна только у каретки). Библиотека = папка. Ни базы, ни аккаунта, ни сети.

**1.2. Для кого.** Один пользователь-владелец (проект некоммерческий), затем — все, кому нужен «лёгкий читатель `.md` для Windows», которого нет (PowerToys #45267, боль №1 в `01`): разработчики с README, авторы заметок в Obsidian-совместимых vault'ах, люди, которым VS Code тяжёл, а Typora — платный и не открывает 4 МБ.

**1.3. Позиция в одну строку.** *Открыл `.md` — читаешь через 400 мс. Правишь — файл остаётся твоим файлом, байт в байт.*

**1.4. Три красные линии** (`01` §4, обязательны для каждой фичи):

1. **Файл — единственный источник истины.** Нет блочной модели, нет БД, нет своего формата. Байты, которые пользователь не редактировал, не меняются никогда: ни EOL, ни BOM, ни маркеры списков, ни trailing spaces (A-10, боль №3 MarkText #2189).
2. **Ноль сети в базовом сценарии.** Открыть, читать, искать, править, экспортировать — офлайн, без единого соединения. Сеть допускается ровно в двух случаях и только с согласия пользователя: (а) проверка/скачивание обновлений — первый запуск спрашивает «проверять обновления при старте?», ответ сохраняется в `updates.check` (`startup | manual | off`), (б) загрузка внешнего изображения по явному действию или сохранённому разрешению для хоста (§11). Телеметрии нет (NFR-030…031). Приёмочный тест: при `updates.check = off` и `security.remoteImages = block` исходящих соединений за сессию — 0.
3. **Быстрее, чем открыть в браузере.** Холодный старт ≤ 400 мс P50, RSS ≤ 150 МБ (NFR-001, NFR-015). Выше — продукт теряет смысл перед VS Code/Obsidian.

**1.5. Принципы дизайна** (из макетов): один шрифт (IBM Plex Mono) везде; один акцент (фиолетовый) только для каретки, выделения, индикатора изменений и активного элемента; без иконок, кроме глифов-лейблов; без скруглений и теней внутри окна; иерархия — расстоянием и 1px-линиями; микрокопия строчными.

**1.6. Что сознательно не делаем** (`01` §4, A-1…A-21): систему плагинов; свою синхронизацию/облако; свою БД/формат; граф связей; блочный drag-and-drop; AI-ассистента; real-time коллаборацию; тулбар с иконками по умолчанию; второй движок диаграмм помимо Mermaid; автоформатирование при сохранении; свой диалект markdown (читаем чужие, не изобретаем); обязательный vault при первом запуске; телеметрию и аккаунт; минимап; задачи/канбан/календарь; загрузку картинок на хостинг; публикацию сайтов; обещание macOS/Linux при Windows-first (архитектура кроссплатформенна, но релизы — только Windows до v1.0).

## 3. Термины

| Термин | Значение |
|---|---|
| **Библиотека (vault)** | папка, открытая как рабочее пространство; никаких служебных файлов в ней, кроме `.plain/` |
| **Режим (surface)** | read / edit / rich — три представления одного буфера |
| **Буфер** | текст файла в памяти (`EditorState.doc` CodeMirror 6) + свойства файла (кодировка, BOM, EOL) |
| **Рейка (rail)** | левая панель 232px с тремя состояниями: `files` / `outline` / `library` |
| **Quick search** | модал `Ctrl+K`: файлы, полнотекст, команды |
| **Raw-блок** | конструкция, которую rich показывает как исходник, потому что не может отобразить без потери байтов |
| **Round-trip** | гарантия, что parse→serialize возвращает те же байты |
| **Якорь чтения** | позиция в документе, устойчивая к правкам (заголовок + смещение + отпечаток блока), META-004 |

## 4. Дизайн-система

Источник — `00`. Ниже нормативные решения; полные таблицы токенов/типографики/геометрии — в `00` и `04` §2.10.

### 4.1. Цвета (после аудита контраста)

Аудит WCAG (`04` RND-027, `03` ACC-001) показал: `--muted` из макетов (`#8a877f` на light, `#7a776f` на dark) даёт 3.32:1 и 4.12:1 — ниже AA 4.5:1 для мелкого текста, которым он набран (статус-бар 10.5px, рейка 12px, мета 11px). **Решение:** дефолт — скорректированные значения; исходные доступны настройкой `appearance.a11yContrast = "mockup"` с пометкой «ниже WCAG AA».

| Токен | Light | Dark | Назначение |
|---|---|---|---|
| `--bg` | `#f7f6f3` | `#141413` | фон |
| `--bg-elevated` | `#fbfaf8` | `#1c1b19` | модалы, поповеры |
| `--fg` | `#1c1b19` | `#e8e6e1` | текст |

| `--scrim` | `rgba(28,27,25,.35)` | `rgba(0,0,0,.55)` | подложка модала |

Единственное допустимое отступление от «одного акцента» — hover кнопки закрытия окна `#c42b1c` с белым глифом (системная конвенция Win11, ACC-036).

Правило применения токенов к тексту: любой текст, несущий информацию (номера строк, синтаксические маркеры в edit, placeholder, лейблы, статус-бар), набирается `--muted` или темнее (≥4.5:1). `--muted-soft` — только нетекстовые элементы (рамка чекбокса, маркер списка `•`, разделитель `│`). `--faint` — только декор, который дублирует уже видимую структуру. CI-проверка (ACC-008) считает фактические пары «токен × фон» для всех состояний; режим `a11yContrast = mockup` из заявления о соответствии AA исключён.

Опция `appearance.accent`: `violet` (дефолт) · `orange` · `green` · `#rrggbb` — из «Try next» макета. При смене акцента `--accent-strong` и `--selection` пересчитываются автоматически с проверкой ≥4.5:1 (иначе затемняется).

### 4.2. Типографика и метрика

- Шрифт: `'IBM Plex Mono', 'Noto Sans Mono CJK SC', 'Cascadia Mono', ui-monospace, monospace`; веса 300/400/500/600, italic 400; самохостинг (`@fontsource/ibm-plex-mono`, OFL-1.1) с кириллицей. Advance width Plex Mono = 0.6em (измерено, RND-001).
- Контент read/rich: 13.5px / 1.75 / колонка **560px = 69 символов**. Edit: 13px / 1.75 / 640px (73 символа) с гуттером 40px + 24px.
- Заголовки: H1 22px/600/1.3/-.01em; H2 13.5px/600 `--muted`; H3–H6 13.5px/600 `--fg` с uppercase-лейблом уровня в поле (RND-003; инверсия цвета H2/H3 — открытый вопрос OQ-4, проверить визуально).
- Абзац margin 0 0 20px; blockquote: 1px левая линия `--fg`, padding-left 18px, italic, `--quote`; списки padding-left 22px, gap 6px; code block 12px/1.6 на `--surface`, padding 14px 16px, без рамки и скругления; ссылки: `--fg` + underline offset 3px цветом `--accent`.
- UI: базовый 13px; рейка 12px; заголовки секций 10px uppercase .12em `--muted`; статус-бар 10.5px; breadcrumbs 11px; quick search 12.5px; плавающий тулбар 11.5px.
- Опция `appearance.serifReading` (v0.2): контент — серифный шрифт (например, IBM Plex Serif, тоже OFL), UI остаётся моно.
- Полный набор CSS custom properties — `04` §2.10 (принимается целиком).

### 4.3. Геометрия

Окно по умолчанию 1100×720 DIP; **минимум 480×400** для всех окон, включая «reading window» (ACC-030: требование Snap Layouts ≤500 epx; UX-088 уточнён: 480×720). Title bar 36px (breadcrumbs слева с padding 16px, три кнопки окна 46×36 справа). Рейка 232px (настраивается 180–360), авто-скрытие при ширине окна < 900. Полоса режимов 44px. Статус-бар 30px. Контент padding-top 36px. Quick search: `width: min(520px, 100% − 32px)`, `max-height: 100% − 160px`, top 120px (при высоте окна < 560 — top 40px). Split view доступен при ширине ≥ 680 (2×320 + разделитель); при сужении окна ниже — split закрывается с сообщением в статус-баре, вторая панель уходит во вкладки. Скругления и тени внутри окна — 0; скругление рамки окна — системное (ACC-035). 1px-линии — ровно 1 физический пиксель на любом DPI (ACC-037).

### 4.4. Состояния и микрокопия

Из `00` §«Состояния»: unsaved = `•` accent в breadcrumbs + `●` в рейке + `unsaved` в статусе + бейдж `edited` в библиотеке; saved = `saved 2m ago`; тема = `◐ light` / `◑ dark` (кликабельно); прогресс = `reading · 38%`; каретка = `ln 9, col 118 · markdown`; выделение = `rich · 3 chars selected`. Hover — цвет `--fg` без фона; фон `--surface` — только у активного. Микрокопия — строчными латиницей; русская локализация сохраняет регистр (ACC-051). Фокус — `outline: 1px solid var(--accent); outline-offset: 2px` (в макетах отсутствует, обязательная добавка ACC-011).

### 4.5. Экраны, которых нет в макетах — проектируются «в стиле библиотеки»

Настройки (плоский список с секциями, SET-010…014), find-панель (SRCH-010…011), global search (SRCH-020…023), replace preview, диалог конфликта файла (баннер UX-060), восстановление черновиков (UX-054), контекстные меню (LIB-020), diff-вид (REL-031), history, split view, DnD-оверлей (UX-070), пустая библиотека (LIB-015), плашки «remote image · load», «file outside library», «large file». Правило: заголовок 22px/600, список с `border-top 1px --border`, текстовые контролы (`on · off`, значения через `·`), никаких вкладок и иконок.

## 5. Структура интерфейса

### 5.1. Окно и title bar `[MVP]`

- Кастомный title bar 36px поверх системного (overlay), с сохранением Snap Layouts, тени, resize-border и системного меню. Реализация: `tauri-plugin-decorum` **или** собственная обработка `WM_NCHITTEST → HTMAXBUTTON` + `WM_NCMOUSE*` (ACC-031, риск R-2). Определяется спайком S-5 (§21). Запасной вариант — `decorations: true` с системным title bar.
- Breadcrumbs: `vault / folder / file.md` (корень 600 только при открытой библиотеке; одиночный файл — `folder / file.md`; файл вне библиотеки — абсолютный путь курсивом, UX-069). Клик по корню — переключение библиотеки; по папке — раскрытие в рейке; по файлу — переименование (F2).
- Кнопки окна: `—` `▢` `✕` 10×10 svg stroke 1px; hover `—`/`▢` фон `--surface`, `✕` — `#c42b1c`.
- Mica/Acrylic — **не используются** (ACC-034). Per-Monitor DPI V2, положение окна проверяется на видимость при восстановлении (ACC-032…033).
- Заголовок окна (панель задач, Alt+Tab): `file.md — Plain`, при несохранённых правках `• file.md — Plain`; экран библиотеки — `<имя библиотеки> — Plain`.
- Пустое состояние (ничего не открыто, нет сессии): по центру контента 13.5px `--muted` — `open a file · open a library`, ниже список `recent` (до 10) в стиле quick search; рейка свёрнута (`01` L20).

### 5.2. Рейка `[MVP]`

Три состояния, цикл `Ctrl+Shift+\`, свёртывание `Ctrl+\`; в свёрнутом виде слева над контентом лейбл `▸ files` (макет 1c).

| Состояние | Содержимое | Футер |
|---|---|---|
| `files` | `⌕ search … ctrl k`; дерево: папки как секции uppercase, файлы 12px; активный — `--surface`; `●` у изменённых | `12 files · synced` / `indexing… 43%` / `12 files here · open as library` (UX-008) |
| `outline` | заголовки без `#`, отступ 18px/уровень, активный раздел `--surface`; секция `links here` (backlinks, v0.2) | переключатель `outline · files` |
| `library` | `folders` с счётчиками (`all 12`, …), `tags` (12 частых) | путь `~/Documents/plain` (+ ` · polling` на OneDrive/сети) |

Дерево: виртуализировано (10k файлов), `role="tree"`, DnD перемещения в папку (LIB-036), контекстные меню LIB-021…023, inline-переименование F2, правила сортировки/игнора LIB-001…009.

### 5.3. Полоса режимов `[MVP]`

`read · edit · rich` по центру, 11px, активный `--fg` + border-bottom 1px; `role="tablist"`. `Ctrl+/` цикл, `Ctrl+Alt+1/2/3` прямо. При ширине < 560 полоса скрывается (остаётся хоткей). В MVP вкладка `rich` несёт суффикс `· experimental` 10px `--muted` (снимается в v0.2). Для файлов > `rich.maxFileSizeKb` вкладка `rich` серая с tooltip `too large for rich`. Под полосой при `Ctrl+F` появляется find-панель 36px (SRCH-010).

### 5.4. Статус-бар `[MVP]`

Слева по режиму: `reading · 38%` (read/rich, META-003) · `ln 9, col 118 · markdown` (edit) · `rich · 3 chars selected` (rich); сюда же — путь при наведении на внутреннюю ссылку (EDT-084), временные сообщения 2–3 с (`reloaded from disk`, `saved assets/…`, `can't format inside a raw block`). Справа группа gap 16px: `utf-8` (кликабельно → reopen/save with encoding), `mixed eol`/`crlf`, `612 words` (tooltip `+240 in code`), `unsaved`/`saving…`/`saved 2m ago`/`read-only`/`deleted on disk`, `⌃` (always on top), `large file · rich off · no index`, `◐ light`. `role="status" aria-live="polite"`. Скрывается в focus mode.

### 5.5. Экран библиотеки `[MVP]`

Пустая библиотека — LIB-015. Клик по папке/тегу в рейке фильтрует список.

### 5.6. Quick search `[MVP]`

### 5.8. Прочие поверхности

Уведомления ОС — нет.

## 6. Режимы документа

### 6.0. Общая модель `[MVP]`

- **Один буфер — три представления.** Read, Edit и Rich работают над одним `EditorState` (CodeMirror 6). Edit ↔ Rich — смена `Compartment` с декорациями; Read — HTML-рендер из того же текста. Каретка, выделение, undo-история и якорь скролла переживают любое переключение (EDT-001, DOC-004, UX-024). Переключение ≤ 80 мс без мигания (NFR-007).
- **Ни один режим не сериализует документ целиком** (EDT-002, DOC-017). Все правки — точечные транзакции. Структурные операции пересериализуют один top-level-блок со стилем, выведенным из документа (DOC-018), и постпроцессором экранирования (DOC-019). CI-гейт идемпотентности (DOC-020): блок, который не проходит `splice(serialize(parse(block))) === block`, в rich становится raw-блоком.
- Undo: один стек на буфер, границы шагов по EDT-091, глубина ≥ 1000 шагов; внешняя перезагрузка — одна точка `reloaded from disk` (EDT-092).
- Свойства файла (кодировка, BOM, карта EOL, финальный перевод строки) хранятся при буфере и восстанавливаются побайтово (REL-020…024; DOC-021 переопределён — см. §12.3 и OQ-21).
- **Ревизии.** Каждая транзакция увеличивает `revision` буфера. Сохранение, черновик, индексация и IPC-пакеты семантики несут номер ревизии; ответ Rust на сохранение снимает `dirty` только если текущая ревизия равна сохранённой (§12.2).
- **Владение файлом между окнами (MVP).** Файл редактируется ровно в одном окне-владельце; попытка открыть его в другом окне фокусирует владельца (или, при `Shift+↵`, открывает read-only-вид, получающий ревизии владельца через IPC — v0.2). Общий undo между окнами не делается. Один буфер = один `EditorState` в одном WebView.

### 6.1. Read `[MVP]`

Назначение: чтение без каретки; текст выделяем, файл не меняется.

- Рендер: `remark-parse → remark-gfm / remark-math / remark-frontmatter / расширения → remark-rehype → rehype-raw → rehype-sanitize → гидратация (Shiki, KaTeX, Mermaid) → DOM` (SEC-002…003). Каждый top-level-блок несёт `data-s/data-e` (offset в исходнике) для sync-scroll, outline, прогресса и обратной связи (DOC-011). Блочный диф при обновлении: перерисовываются только изменённые блоки (DOC-013) — сохраняются скролл, lightbox, отрендеренные диаграммы.
- Над H1 мета-строка `4 sep 2026 · 612 words · 3 min` (`read.showMeta`). Word count по META-001: исключаются блоки кода, математика, адресная часть ссылок, front matter и комментарии; inline-code включается, autolink считается одним словом; CJK — посимвольно в отдельном счётчике `cjkChars` (не входит в `words`, чтобы не удваивать время); графемы через `Intl.Segmenter`. Reading time по META-002: `ceil(words/wpm + cjkChars/cjkCpm + imageSeconds/60)`, где `imageSeconds` = 3 с за первое изображение и по 1 с за каждое следующее (`read.countImages`, default `true`); 238 wpm en / 190 ru, настраиваемо. Прогресс — по последнему видимому блоку (META-003); при `words = 0` — доля скролла; документ короче экрана — 100%.
- Элементы: заголовки с якорем (hover → `#` копирует ссылку); таблицы в контейнере `overflow-x: auto` со sticky-заголовком (RND-009); изображения `max-width: 100%` + подпись из title/alt + lightbox (`medium-zoom`) + lazy; code block с лейблом языка и кнопкой `copy` (hover, 10px, `copied` 1.5 с — EDT-051), опция wrap кода (EDT-050); footnotes внизу + popover при hover (RND-018); callouts без иконок (лейбл uppercase, MD-021); `<details>` работает; KaTeX inline/display (display — горизонтальный скролл при переполнении); Mermaid lazy с серой темой и фолбэком на исходник при ошибке (MD-028, EDT-054); `==mark==`; теги как ссылки на поиск; wikilinks с классом `unresolved` для отсутствующих (MD-015).
- Чекбоксы: **некликабельны по умолчанию** (A-16, UX-093); `read.interactiveCheckboxes = true` включает клик → правка ровно одного символа по offset (DOC-016) с однократным подтверждением.
- Выделение → мини-тулбар `copy · copy as markdown` (EDT-082); `highlight` (пишет `==…==`) скрыт за `read.allowAnnotations`. `Ctrl+C` при выделении внутри контента перехватывается и кладёт `text/html` + `text/plain` + `text/markdown` (EDT-081) — через Rust (CF_HTML), так как многоформатная запись из WebView2 сломана (R-16). **Карта DOM → исходник:** при гидратации каждый текстовый узел получает **кусочно-линейное отображение** `segments: [(domOffset, srcOffset, length)]` — отрезки, внутри которых смещение в DOM и в исходнике идут синхронно; разрывы отрезков — раскрытые сущности (`&amp;` = 1 символ DOM / 5 исходника), экранирующие `\`, скрытые маркеры разметки, границы code span, шорткоды emoji. Частичное выделение внутри узла отображается точно через свой отрезок. Сгенерированные узлы (номера сносок, лейблы callout, кнопки, содержимое embeds — оно принадлежит другому файлу) имеют пустое отображение: если граница выделения попадает в такой узел, она сдвигается к ближайшей границе соседнего отображаемого узла (не к границе блока). Markdown-фрагмент = исходник от отображённого начала до отображённого конца выделения. `Ctrl+H` из read переносит в edit точный диапазон текущей ревизии. Карта версионируется ревизией документа и перестраивается блочным дифом (DOC-013).
- Ссылки: внешние — во внешний браузер с подтверждением (`security.openExternalLinks = "ask"`, NFR-032); внутренние — навигация с историей `Alt+←/→`, путь в статус-баре при hover; `Ctrl`+hover — превью 6 строк (v1.0, EDT-085). Двойной клик по блоку → Edit с кареткой в этом месте (`01` N12/L17).
- Sticky heading (v0.2, UX-018); подсветка активного раздела в outline (MVP).
- Zoom контента `Ctrl+=` / `Ctrl+-` / `Ctrl+0` 80–200% шагами 10%, сохраняется на окно (UX-021); реализуется приложением, так как зум WebView2 отключён (KEY-011).
- Печать (v0.2): печатается всегда Read, print-CSS чёрным на белом 11pt, `break-inside: avoid` для кода/таблиц, URL после текста ссылок (UX-075…077).

### 6.2. Edit `[MVP]`

Назначение: исходник целиком, подсветка, номера строк.

- CodeMirror 6 + `@lezer/markdown` (GFM + расширения; набор конструкций идентичен семантическому парсеру — DOC-014). Подсветка: маркеры (`#`, `>`, `-`, `1.`, `[`, `](`, `)`, `---`, `|`, `\`, `$`) — `--muted`, заголовки 600, цитаты italic, URL — `--accent` underline; setext-подчёркивание `---` подсвечивается как заголовок (MD-039); блок, распознанный как indented code, получает линт-подсказку «сделать fenced?» (MD-040).
- Гуттер: номера строк (`edit.lineNumbers`, `Ctrl+Shift+9`, цвет `--line-number` = `--muted`), маркеры фолдинга `▸/▾` на hover (EDT-078), indent-guides 1px `--faint` (MD-037). Синтаксические маркеры (`#`, `>`, `**`, `\`, `$`) — `--muted`, не `--faint`: это значимый текст.
- Soft wrap с учётом структуры: продолжение строки списка выравнивается по отступу текста пункта (EDT-075). Невидимые символы `Ctrl+Shift+8`: `·` пробел, `→` таб, `¬` EOL, `␣` NBSP (подсвечен), `∅` zero-width; trailing-пробелы hard break всегда видны глифом `⏎` цветом `--muted` (значимая информация, MD-032).
- Ввод: автопродолжение списков/чекбоксов/цитат с маркером **из документа** (EDT-010…014); `Tab`/`Shift+Tab` уровень (EDT-015…016); автопары и обёртка выделения (EDT-020…021); умные кавычки выкл. (EDT-022); автозавершение `[[`, `](`, `#` (EDT-023…025); вставка URL поверх выделения → ссылка (EDT-026); `Ctrl+Shift+V` — вставить как простой текст (MVP); конверсия HTML из буфера → markdown при обычном `Ctrl+V` (EDT-027, v0.2; до этого `Ctrl+V` вставляет `text/plain`); вставка изображения → `assets/` (§11); IME — никаких автозамен во время композиции (EDT-030, R-7).
- Орфография: MVP — встроенная проверка WebView2/Edge (атрибут `spellcheck` на редакторе, системные словари Windows), выключена по умолчанию (`edit.spellcheck = false`), подчёркивание — системное; собственный словарь библиотеки на `nspell` — `[later]` (`02` §K).
- Таблицы: `Tab` по ячейкам (EDT-040); выравнивание только по команде `> format table` для таблицы под кареткой, ширина по графемам с учётом East-Asian Width (EDT-041…042).
- Мультикурсор `Ctrl+Alt+↑/↓`, `Ctrl+D`, `Alt`+клик (EDT-079); move/duplicate line `Alt+↑/↓`, `Alt+Shift+↑/↓`; фолдинг по заголовкам `Ctrl+Shift+[` / `]`.
- Find/replace: SRCH-010…017 (regex JS, тумблеры `Aa` / `W` / `.*` текстовыми глифами, счётчик, подсветка ±200 строк, `replace all` = одна транзакция undo). Regex-поиск выполняется в завершаемом Web Worker с бюджетом 500 мс на проход: превышение → `terminate()`, счётчик `timeout`, UI не блокируется (защита от катастрофического бэктрекинга).
- Typewriter (`F9`, v0.2): строка каретки на 45% высоты. Focus (`F8`): скрыть рейку и статус-бар (MVP), затемнение вне активного абзаца (v0.2, UX-083).
- Vim-режим — `[later]` (`@replit/codemirror-vim` готов, но требует ревизии всей раскладки).

### 6.3. Rich `[MVP — экспериментальный · v0.2 — стабильный]`

Назначение: Typora-подобный live preview без собственного `contenteditable`. В MVP режим поставляется с пометкой `experimental` и **не входит в критерии приёмки** (§20): приёмка MVP — Read + Edit. Обязательные требования к rich уже в MVP — сохранность файла (красная линия 1) и отсутствие потери ввода; всё остальное допускается доводить в v0.2.

- **Архитектурное решение:** тот же `EditorState`, дополнительный compartment с `Decoration.replace` (скрыть `**`, `[[`, `> [!note]` …), `Decoration.widget` (изображения, формулы, чекбоксы, emoji) и блочными виджетами (таблица, mermaid, display-math, HTML, front matter). Модель Obsidian Live Preview; референс — `@atomic-editor/editor` 0.6.2 (как зависимость или как образец примитивов `inlinePreview` / `tables` / `wikiLinks`). Milkdown и Tiptap **отклонены** для режима документа (DOC-025: каждое переключение = полная пересериализация, нарушение красной линии 1); ProseMirror допустим только как отдельный «table editor» на конкретной таблице (v0.2, если CM6-виджет окажется недостаточным).
- Раскрытие синтаксиса у каретки (EDT-060…062): инлайн-конструкции — по диапазону, включая границы (каретка справа от закрывающего `**` — внутри, EDT-061); блочные — целиком по блоку. Настройка `rich.revealSyntax = caret-token | caret-line`. Высота строки при раскрытии не меняется (EDT-064). **Два класса декораций:** инлайновые (`Decoration.mark/replace` без изменения вертикальной структуры) строятся `ViewPlugin`-ом только для `view.visibleRanges`; блочные (виджеты таблиц, диаграмм, display-math, HTML, front matter, `block: true`) живут в `StateField` и передаются в `EditorView.decorations` напрямую для всего документа — иначе CM6 не сможет корректно вычислить viewport (ограничение CodeMirror). Декорации не перестраиваются во время IME-композиции (R-7, DOC-027.3).
- Маркеры блоков в левом поле (`#`, `##`, `>`) — `--faint`, 11px, left −40px (макет 1d, EDT-063; допустимо: дублируют видимую иерархию). Placeholder на пустой строке — `Type / for a block, or just keep writing.` цветом `--muted` (информационный текст).
- Плавающий тулбар при выделении: `B I S` `` ` `` `│ link quote`, 30px, `--toolbar-bg`, top −38px (EDT-069). Slash-меню `/` на пустой строке (v0.2, EDT-029): `heading 1–3 · list · numbered · task · quote · code · table · divider · image · math`.
- **Raw-блоки** (EDT-065…066): блочный HTML, `<script>/<style>`, шаблонные `{{ }}` / `{% %}`, JSX в `.mdx`, незакрытые конструкции, всё непонятное — моноширинный блок 12px на `--surface` с лейблом (`raw html`, `front matter`, `mdx`, `unknown`); редактируется как текст, никогда не парсится и не переписывается.
- Front matter: свёрнутая строка `--- 4 keys ---`; клик → raw YAML; таблица key/value — v1.0 (EDT-067, MD-008). YAML сохраняется побайтово, если поля не менялись.
- Таблицы: **MVP** — таблица в rich показывается как исходник (raw-блок с подсветкой `|`) с Tab-навигацией; **v0.2** — виджет-сетка с редактируемыми ячейками и панелью `+row +col · del row · del col · ← ↔ →` (EDT-043; вопрос 6 из `04` прил. A). Вставка TSV/CSV/HTML-таблицы → markdown-таблица (v0.2, EDT-044).
- Изображения: инлайн-рендер; клик выделяет виджет, `Enter`/`F2` — редактирование alt/пути (v0.2, EDT-057). Ресайз мышью — нет (невыразимо в чистом markdown); `![[img|300]]` и `![alt|300](…)` поддерживаются (MD-020); оговорка EDT-057 про режим `raw` снята вместе с самим режимом (§18).
- Формулы и Mermaid инлайн (v0.2, EDT-053…054): двухслойное представление — превью + исходник при каретке внутри.
- Literal-autolinks, reference-links, emoji-шорткоды, `^id`, `%% %%` — **никогда не переписываются** rich-режимом (MD-005, MD-042, MD-024, MD-044, MD-026).
- `rich.maxFileSizeKb = 512`: выше — rich недоступен, предлагается edit.

### 6.4. Split view `[v0.2]`

`Ctrl+Alt+→`: вертикальный split 50/50 внутри одного окна, разделитель 1px `--border`, min 320px на панель (окно ≥ 680); у каждой половины свой режим и скролл; один и тот же файл слева в read и справа в edit смотрит в один буфер и один `EditorState` (UX-049…051) — это возможно только в пределах одного WebView, между окнами буфер не разделяется (§6.0). Sync-scroll выключен по умолчанию (UX-053); при включении — кусочно-линейная интерполяция по якорям блоков (DOC-011). MVP-альтернатива — второе окно `Ctrl+Shift+N` (UX-052).

## 7. Библиотека и файлы

### 7.1. Открытие `[MVP]`

- Одиночный файл (двойной клик, DnD, CLI): сразу read, рейка свёрнута, никаких экранов приветствия и предложений создать vault (UX-001…005, A-12). Второй файл — в тот же процесс (single instance, ACC-040).
- Папка как библиотека: `Ctrl+Alt+O`, `> open library`, DnD папки, клик по корню breadcrumbs (UX-009…010). Индексация фоновая, дерево доступно сразу (UX-011). Последняя библиотека и файл восстанавливаются при старте без аргументов (UX-012). Библиотека > 25k файлов — предупреждение, не блокировка (v0.2).
- Multi-vault (v0.2, LIB-070…072): `vaults.json`, переключение по клику на корень; библиотека — на окно.
- Без библиотеки работает всё, кроме дерева, global search, тегов и backlinks (UX-067…069).

### 7.2. Дерево и правила `[MVP]`

LIB-001…009: расширения `.md .markdown` (+ `.mdown .mkd .mdx .txt .qmd` опционально; `.txt` без markdown-рендера); натуральная сортировка по локали, папки первыми; скрытые и dot-файлы скрыты; жёсткий игнор `.git .obsidian .plain .vscode .idea node_modules … $RECYCLE.BIN`; `.gitignore` / `.plainignore` (v0.2); симлинки не разворачиваются; счётчики у папок; футеры по состояниям.

### 7.3. Файловые операции `[MVP]`

- Создание: `+ new` / `Ctrl+N` → `Untitled.md` с inline-переименованием; файл на диске появляется после `Enter` или первого символа (LIB-030…032); коллизии `Untitled 2.md`; валидация имён Windows (LIB-033…035); Unicode-имена без нормализации на диск. **Без библиотеки и без открытого файла** (`Ctrl+N` на пустом экране) создаётся виртуальный `Untitled` с устойчивым id черновика; первое сохранение или первая вставка вложения вызывает `Save As`; отмена диалога сохраняет буфер в памяти и черновике, вложение не создаётся.
- Переименование `F2` инлайн; **обновление ссылок** с диалогом `update 14 links in 6 files? · update · skip` (дефолт `prompt`, UX-034; охват: `[](rel)`, `![](rel)`, `[[wiki]]`, reference-definitions, `href/src` в inline-HTML); стиль ссылки сохраняется (`%20`, `<…>`, относительность — UX-036); `> undo link update` (UX-035). Переименование заголовка обновляет `#anchor`-ссылки (v0.2, UX-037).
- **Журнал массовых операций `[MVP]`** (переименование/перемещение с обновлением ссылок, позже — replace across files и восстановление из истории): `%APPDATA%\Plain\ops\<op-id>\` содержит манифест (список файлов, стадия, ревизии), копии исходных версий всех затрагиваемых файлов и результат. Порядок: (1) файлы с несохранёнными правками — либо сохранить перед операцией, либо исключить (диалог); (2) записать копии исходных версий и манифест со стадией `planned` (для каждого файла — путь, `originalHash`, ожидаемый `resultHash`, путь backup; манифест пишется атомарно temp+rename и переписывается при каждой смене стадии); (3) стадия `applying`: файлы меняются по одному атомарной записью §12.2 (переименование самого файла — `MoveFileExW`); (4) стадия `done`. **Восстановление при старте** (манифест не в `done`): для каждого файла текущий хэш сравнивается с `originalHash` и `resultHash` — равен original → не применён; равен result → применён; иначе → изменён третьей стороной. Экран `interrupted operation` с `finish` (доприменить только «не применённые», «изменённые третьей стороной» пропустить и перечислить) и `roll back` (восстановить из backup только «применённые»; «изменённые третьей стороной» — пропустить и перечислить). Сбой между записью файла и фиксацией стадии безопасен: состояние выводится из хэшей, а не из манифеста. Ретенция — 7 дней или 50 операций **только для операций в стадии `done`**; незавершённые не удаляются автоматически.
- Перемещение DnD в папку (только в папку; порядок задаёт сортировка), тот же механизм ссылок и тот же журнал (LIB-036…037, боль №8). DnD внутри дерева реализуется на **Pointer Events** (`@dnd-kit/core`), а не на HTML5 DnD: при `dragDropEnabled: true` Tauri перехватывает HTML5 `dragover`/`drop` на Windows (R-17), поэтому pragmatic-drag-and-drop (HTML5 DnD) **не используется**.
- Удаление → **системная корзина** (`IFileOperation` + `FOF_ALLOWUNDO`); `Shift+Delete` — безвозвратно с подтверждением; на сетевых дисках без корзины — `.plain/trash/<дата>/` (LIB-039). Удаление открытого файла — буфер остаётся (LIB-040, UX-065).
- Контекстные меню файла/папки/пустой области — LIB-020…024 (текстовые, без иконок; `open with…` = системный `SHOpenWithDialog`).
- Шаблоны `<vault>/.plain/templates/*.md` с `{{title}} {{date:…}} {{time:…}} {{uuid}} {{cursor}}` (v0.2, LIB-038). Pinned (в quick search и библиотеке), недавние (20 глобально).
- Служебные файлы приложения в библиотеке — **только `.plain/`**, никаких `.lock`-папок (UX-108, боль №13).

### 7.4. Метаданные и связи `[MVP]`

- Заголовок документа: первый H1 (в первых 3 блоках) → front matter `title` → имя файла (META-007). Excerpt для библиотеки — META-008. Агрегаты `12 files · 9,240 words` из кэша (META-009).
- `created`: front matter `created/date` → NTFS birth time → mtime; `modified`: front matter → mtime (META-005, LIB-056…057; `ReplaceFileW` сохраняет creation time).
- Теги: inline `#tag` (правила MD-025: не в code/URL/math/HTML, обязательна буква, кириллица ок, `/` — иерархия) + front matter `tags`; один индекс, регистронезависимо (LIB-050…053).
- Outline: из mdast; заголовки внутри code/front matter/HTML исключены, внутри цитат — помечены `nested` (META-006); без литеральных `#` (боль №26).
- Backlinks `links here` (v0.2, META-010, LIB-054): wikilinks, embeds, md-ссылки на `.md` (в т.ч. без расширения), ссылки во front matter; контекст строкой. Unlinked mentions — v1.0 (LIB-055). Разрешение путей — META-011 (точное → `+.md` → уникальный basename → регистронезависимо с предупреждением; URL-decode и NFC обязательны).

### 7.5. Наблюдение за ФС `[MVP]`

`notify` (`ReadDirectoryChangesW`) + debouncer 150 мс, рекурсивно по корню, без игнорируемых директорий (LIB-060, LIB-064). Каждое событие проверяется по хэшу содержимого (BLAKE3/xxHash), не по mtime (UX-062, REL-030) — защита от ложных срабатываний OneDrive (боль №52). Собственные записи маркируются write-token'ом на 2 с (UX-063). На `DRIVE_REMOTE` / `IO_REPARSE_TAG_CLOUD` — polling 3 с / 30 с и футер ` · polling` (LIB-061…062, UX-106; MVP — детекция и polling, v0.2 — полная политика записи для облачных папок). Переполнение буфера драйвера → фоновая переиндексация.

## 8. Поиск

### 8.1. Quick search `Ctrl+K` `[MVP]` — см. §5.6

Движок: `uFuzzy` по путям (бонусы за начало сегмента, имя файла, недавнее открытие — SRCH-005); `in text` — 5 совпадений из полнотекстового индекса; открытие ≤ 30 мс, первый список ≤ 30 мс на 10k файлов (NFR-009).

### 8.2. Поиск в файле `Ctrl+F` / `Ctrl+H` `[MVP]` — SRCH-010…018

Работает одинаково в read/edit/rich. В read поиск идёт по видимому тексту рендера с подсветкой через карту DOM → исходник (§6.1); `Ctrl+H` в read переключает в edit с переносом текущего совпадения (замена в read не выполняется). Поиск только в выделении — v0.2.

### 8.3. Поиск по библиотеке `Ctrl+Shift+F` `[MVP]`

- Экран в стиле библиотеки: группировка по файлам, до 5 строк контекста с `+ N more`, футер `38 results in 12 files · 84 ms` (SRCH-020…023). Результаты потоково, первые ≤ 100 мс, новый ввод отменяет предыдущий (SRCH-026, NFR-027).
- Синтаксис — модель Obsidian (SRCH-024). **MVP:** слова (AND), `"фраза"`, `OR`, `-`, `( )`, `path:`, `file:`, `ext:`, `tag:`, `match-case:`/`ignore-case:`, `/regex/`. **v0.2:** структурные операторы `line:()`, `section:()`, `block:()`, `task:`/`task-todo:`/`task-done:`, `content:` — они требуют индексной схемы с полями блоков и задач. `?` показывает справку.
- Движок: **Tantivy** на Rust-стороне (BM25, русский стеммер, индекс на диске `%APPDATA%\Plain\index\<vault-id>\`, схема версионирована, NFC+casefold — SRCH-040…045). **Контракт индексации:** семантический разбор (mdast) выполняется в фоновом JS Worker и для неоткрытых файлов; результат — версионированный IPC-пакет `{fileId, revision, contentHash, blocks[], headings[], tags[], tasks[], links[], words}` — уходит в Rust, который ведёт очередь, карту `path → (mtime, size, hash)` и индекс. Собственный парсер запросов (JS) транслирует синтаксис в булево дерево Tantivy-запросов по полям `body`, `path`, `tags`, `blocks`; точные совпадения и подсветка проверяются по исходнику файла (Rust читает файл, возвращает строки с offset'ами). Индексация 10k файлов ≤ 25 с в фоне, инкремент 100 КБ ≤ 50 мс (NFR-025…026). Файлы > 5 МБ не индексируются, ищутся линейно по запросу (SRCH-044).

### 8.4. Замена по библиотеке `Ctrl+Shift+H` `[v0.2]`

Обязательный `replace preview` с чекбоксами файлов и построчным `−/+` диффом; снапшоты перед записью; `> undo replace across files`; файлы с несохранёнными правками — `skipped (unsaved)`; лимит 500 файлов без явного подтверждения (SRCH-030…033, боль №4).

## 9. Синтаксис: профиль «Plain Markdown flavor»

Нормативная спецификация — `04` §1 (MD-001…047). Здесь — решения по умолчанию.

**Базис:** CommonMark 0.31.2 (652 спек-теста прогоняются на чистом парсере без расширений и санитизации) + GFM-спека: tables, task lists (`[ ]` / `[x]` + произвольный однобуквенный маркер сохраняется), strikethrough `~~` (одинарная `~` отдана под sub), autolinks (never rewritten), disallowed raw HTML; + расширения github.com вне GFM-спеки: footnotes (поведение cmark-gfm/`remark-gfm`), alerts. Профиль `plain` и безопасный DOM проверяются отдельным эталонным корпусом (§20).

**Расширения — включены:** YAML front matter (только с первой строки, безопасный YAML, лимиты — MD-008, SEC-011); math `$…$` / `$$…$$` с правилами против валюты (MD-009: 9 правил + откат числовых «формул») и тумблером `flavor.math = inline+display | display-only | off`; ```` ```math ````; `==highlight==`; `^sup^` и `~sub~` (в профиле `github` выкл.); wikilinks `[[file]] [[file|alias]] [[file#Heading]] [[file#^id]]` и embeds `![[…]]` (глубина ≤ 4, детекция циклов) с размером `|300`; block id `^id`; callouts Obsidian `> [!type]±` **и** GitHub Alerts одной реализацией (MD-021, без иконок); `#tag`; `%% %%` и `<!-- -->` (в rich — свёрнутая метка, не прячется молча); ```` ```mermaid ````; inline/block HTML — sanitized (§18); emoji `:smile:` — только render-time; hard breaks — все три формы, стиль вставки `hardBreakStyle = two-spaces`; heading slugs — совместимы с `github-slugger` (кириллица сохраняется, MD-035); setext и indented code — парсятся всегда, не генерируются никогда; tabs по CommonMark, `tab-size 4`, ввод — 2 пробела, существующие табы не конвертируются; `[toc]`-маркер — render-time оглавление (`01` S28; уточнение ТЗ к `04`).

**Выключены по умолчанию (опция):** definition lists, abbreviations, TOML/JSON front matter, `renderSoftBreaks = br` (Enter = `<br>`), smart punctuation (только render-time, исходник не трогается — MD-034).

**Профили и приоритет:** `flavor.profile = plain | github | obsidian` — предустановленный набор значений тумблеров; порядок применения — дефолты → профиль → явные переопределения пользователя (явно заданный `flavor.*` всегда сильнее профиля). Линт в edit предупреждает о конструкциях, которые в целевом профиле рендерятся иначе (`~sub~` на GitHub, `\`-переносы в Obsidian). Indented code **не отключается** (тумблер `flavor.indentedCode` из `04` MD-040 не вводится: это нарушило бы CommonMark-совместимость чтения чужих файлов; линт-подсказка остаётся).

## 11. Изображения и вложения

- `[MVP]` Локальные изображения — через Tauri asset protocol с **динамическим scope** на открытую библиотеку (или папку одиночного файла), `convertFileSrc`, канонизация пути и проверка `starts_with(vault_root)`; вне библиотеки — плашка «файл вне библиотеки · разрешить этот файл» (SEC-010, R-6, `tauri-plugin-persisted-scope`).
- `[MVP]` Внешние изображения **не загружаются без действия пользователя**. `security.remoteImages`: `ask` (**default**) — вместо картинки плашка с именем хоста и кнопками `load` (разовое разрешение до закрытия документа) и `always allow host` (добавляет хост в глобальный `security.remoteImageHosts`; хосты из списка далее грузятся автоматически); `block` — загрузка невозможна, плашка показывает только имя хоста и подсказку `remote images are blocked in settings`, кнопок нет; `allow-listed` — как `ask`, но без кнопки `always allow host` (список правится только в настройках); `allow` — грузятся все `https`-хосты без плашек. Приоритет: `block` сильнее списка хостов. Любая загрузка — через Rust с лимитами и защитой от SSRF, результат — `blob:` (SEC-005). Следствие: в CSP нет `https:`.

Локальные SVG-файлы рендерятся только как `<img src="asset:…">` (в `<img>` скрипты не исполняются), inline-SVG и `data:image/svg+xml` запрещены (SEC-004); видео/аудио — `<video>/<audio>` для локальных файлов (`01` I10, v0.2).
- `[later]` Дедупликация вставок по хэшу, очистка неиспользуемых вложений с предпросмотром (`01` I6, I14).

## 12. Надёжность и данные

### 12.1. Сохранение `[MVP]`
- Autosave `files.autosave.mode = afterDelay`, 1500 мс; также `onFocusChange`, `onWindowChange`, `off`. Не пишет во время IME-композиции, при внешнем конфликте, для read-only (REL-001…002). Индикатор — только статус-бар (REL-003). `files.saveOnClose = always | ask | never`; один диалог со списком при нескольких несохранённых (REL-004…005).
- **Никакого автоформатирования**: trailing whitespace, финальный `\n`, маркеры, нумерация, отступы таблиц — как были (UX-027, DOC-023, REL-024). Форматирование — только явными командами с предпросмотром диффа.
- Ошибка записи — баннер `couldn't save — <причина> · retry · save as…`, никогда молча (UX-028, боль №51); read-only → `read-only · save as… · make writable` (REL-025).

### 12.2. Атомарная запись и ревизии `[MVP]`
- Алгоритм: temp-файл **в той же директории** → `FlushFileBuffers` → `ReplaceFileW` (сохраняет creation time, DACL, ADS, сжатие); при отсутствии цели — `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`; коды 1175–1177 обрабатываются с внятными сообщениями (данные уже на диске под временным именем) (REL-010…015). На `DRIVE_REMOTE` и в облачных папках — `files.writeMode = inPlace`, потому что `ReplaceFileW` меняет file ID и плодит конфликты у sync-клиентов (REL-012, UX-107; v0.2).
- **Защита от гонок.** Запрос на сохранение несёт `revision` буфера и `baseHash` — хэш содержимого диска, на котором основан буфер (обновляется при загрузке, тихой перезагрузке и успешном сохранении). Rust сериализует записи по документу (очередь на путь). Протокол: (1) прочитать и хэшировать текущий файл; хэш ≠ `baseHash` → запись **не выполняется**, документ переходит в конфликт (баннер §12.4), даже если watcher событие ещё не доставил; (2) `ReplaceFileW(target, tmp, backup)` с **параметром `lpBackupFileName`** = `.<имя>.displaced-<pid>` в той же директории — Windows атомарно сохраняет вытесняемую версию; (3) Rust хэширует backup: хэш = `baseHash` → backup удаляется (штатный случай); хэш ≠ `baseHash` → внешняя запись попала в окно между шагами (1) и (2) — backup переносится в `%APPDATA%\Plain\displaced\<doc-id>-<ts>.md`, документ переходит в конфликт с вариантом `compare` против вытесненной версии. Таким образом чужие байты **не теряются ни при каком порядке событий**; цена — лишний хэш на запись. На носителях с `writeMode = inPlace` (§12.2) шаг (2) заменяется на `ReadFile → сравнить → WriteFile` под `LockFileEx`, вытесняемая версия копируется перед записью. Детерминированный тест: внешний процесс пишет файл по сигналу между шагами (1) и (2) (тестовый хук) — ожидается конфликт и наличие обеих версий.
- Ответ Rust содержит сохранённую `revision`; фронтенд снимает `dirty`, только если текущая ревизия ей равна; правки, сделанные во время записи, оставляют документ `unsaved` и планируют следующую запись.

### 12.3. Кодировки и байты `[MVP]`
- Детекция: BOM → валидация UTF-8 → `chardetng` (CP1251/CP866/CP1252) с показом в статус-баре; `utf-8` кликабельно (`reopen with… / save with…`). Декодирование — `encoding_rs`; **кодирование при сохранении:** UTF-8 — напрямую; UTF-16LE/BE — собственная запись (`encode_utf16` + порядок байт + BOM как был), так как `encoding_rs` не даёт UTF-16-энкодеров; legacy-кодировки — режим **без замены**: непредставимый символ → сохранение отменяется, баннер `character not representable in cp1251 · save as UTF-8 · cancel` (никаких `&#…;` и `?` в файле).
- BOM сохраняется как был; никогда не добавляется и не удаляется без явного действия (REL-022).
- **EOL.** Буфер CM6 хранит текст с LF (позиции CM6 считают любой перевод строки одной единицей; парсеры получают LF-текст). Рядом с буфером живёт `eolMap` — для каждой строки исходный разделитель (`\n`, `\r\n`, `\r`) в компактном виде (доминирующий стиль + список исключений). Транзакции отображают карту через `ChangeSet.mapPos`; новые строки получают доминирующий стиль файла (новый файл — `crlf`, настраивается); undo/redo восстанавливает карту вместе с текстом (она хранится как поле состояния); карта сохраняется в черновике. При записи текст собирается по карте побайтово, статус показывает `mixed eol`. Это переопределяет DOC-021 (`04` предлагал нормализацию к доминирующему стилю) — OQ-21. Преобразование смещений «буфер → байты диска» учитывает `eolMap`, BOM и кодировку (нужно для поиска и подсветки из Rust).
- Длинные пути: манифест `longPathAware` + проверка `LongPathsEnabled` на старте + префикс `\\?\` при длине > 240; относительные пути внутри приложения не используются (REL-026…027).

### 12.4. Внешние изменения `[MVP]`
Нет локальных правок → тихая перезагрузка, позиция по якорю, статус `reloaded from disk` (UX-059). Есть правки → немодальный баннер `file changed on disk · reload · keep mine · compare` (UX-060), `keep mine` не пишет до `Ctrl+S` с подтверждением `overwrite newer version?` (UX-061). Сравнение по хэшу (REL-030); diff-вид двумя колонками в геометрии edit, без цветной заливки (REL-031); `take mine / take theirs` построчно — v0.2. Файл удалён извне → буфер живёт, `Ctrl+S` пересоздаёт (UX-065); переименован извне → путь обновляется молча (UX-066). Автоскролл к внешней правке — v0.2 (UX-064).

### 12.5. Черновики и восстановление `[MVP]`
- Журнал `%APPDATA%\Plain\drafts\<doc-id>.draft`: полный текст + метаданные (путь, `baseHash`, `revision`, `eolMap`, кодировка, каретка/скролл). Расписание: debounce 400 мс **с предельной задержкой 1000 мс** — непрерывный ввод не откладывает запись; гарантия «≤ 1 с от нажатия до завершения записи» едина для файлов любого размера (REL-040…041); запись выполняет фоновый поток Rust, UI не блокируется. Черновик пишется **атомарно** (temp + rename в каталоге drafts), предыдущая подтверждённая версия существует до завершения новой — сбой посреди записи не портит единственную копию.
- Черновик удаляется только после подтверждённого сохранения соответствующей ревизии. При старте — экран `unsaved work found` в стиле библиотеки с `restore · compare · discard` (UX-054…057); `discard` — в корзину.
- Лимит каталога 200 МБ распространяется только на черновики уже сохранённых документов (мусор); черновики несохранённых документов **не удаляются никогда**. При невозможности записать черновик (нет места, нет прав) — постоянный баннер `can't write recovery draft · save as…`, autosave не считается заменой.

### 12.6. Локальная история версий `[v1.0]`
`%APPDATA%\Plain\history\<vault-id>\<file-id>\`: первый снапшот полностью + дельты, zstd; триггеры — явное сохранение (не чаще `history.snapshotIntervalMin = 5`), перед массовыми операциями, перед перезагрузкой при локальных правках; ретенция 30 дней / 100 снапшотов / 200 МБ с прореживанием; переживает переименование; хранится вне библиотеки (опция `vault` → `.plain/history/`) (REL-050…054). UI: `> version history` → список `2026-09-05 14:12 · +42 −7 · 1,204 w` → diff → `restore · copy version · export version as…` (UX-095…097).

### 12.7. Сессия и большие файлы `[MVP]`
`state.json`: открытые файлы, режимы, каретка/скролл, окно, рейка, зум, always-on-top; запись с debounce 2 с и на `WM_CLOSE`/`WM_ENDSESSION` (REL-060…061). Позиция чтения на файл — по умолчанию `%APPDATA%\Plain\workspace\<vault-id-or-global>.json` по устойчивому id документа (LRU 500 на библиотеку + 200 для одиночных файлов); `.plain/workspace.json` в библиотеке — опция `library.workspaceLocation = appdata | vault` (SET-003 уточнён). Чтение файла никогда не создаёт каталогов рядом с ним; `.plain/` появляется только при явных действиях (шаблоны, per-vault настройки, корзина на сетевом диске). Восстановление каскадом META-004 (хэш → отпечаток блока → заголовок → индекс → доля скролла).

**Единая таблица порогов размера файла** (все остальные разделы ссылаются сюда):

| Порог | Поведение |
|---|---|
| ≤ 512 КиБ (`rich.maxFileSizeKb`) | все режимы |
| > 512 КиБ | rich недоступен (`too large for rich`), read и edit полные |
| > 5 МиБ (`files.largeFileThresholdMb`) | large file mode: подсветка off, полнотекстовый индекс off, семантика в Worker с idle-приоритетом; статус `large file · rich off · no index` |
| > 50 МиБ (`files.veryLargeFileThresholdMb`) | только просмотр (read с потоковым рендером), редактирование запрещено с сообщением; DOC-015 «> 20 МБ read-only» переопределён |
| любой | **никогда не обрезать молча** (REL-062…063, UX-098…100) |

## 17. Модель документа и round-trip

Нормативно — `04` §4 (DOC-001…027). Ключевые инварианты, которые проверяются в CI:

1. **DOC-001 (уточнён)** Первичное состояние документа = `Text` CM6 **плюс файловые метаданные**: кодировка, наличие BOM, `eolMap`, признак финального перевода строки, `baseHash`, `revision`. Только эта совокупность восстанавливает байты диска. Всё остальное — mdast, HTML, outline, счётчики, карта DOM → исходник, индексы — производные, которые можно выбросить и пересчитать. Никакая операция не пишет в файл результат сериализации производных без явной правки пользователя.
2. **DOC-002** Offset — UTF-16 code units в JS; на границе с Rust — конверсия в UTF-8 байты через таблицу; никогда не смешивать (кириллица/эмодзи).
3. **DOC-003** mdast с `position` + `data.raw` для небезопасных узлов; массив `blocks[] {start,end,type,hash,words}` — рабочая единица рендера, счётчиков, диффа.
4. **DOC-011/016** Read ↔ исходник: `data-s/data-e` на блоках, интерполяция по якорям; клик по чекбоксу (если включён) = транзакция на 1 символ.
5. **DOC-012/015** Инкрементальность: Lezer в редакторе (встроенная); семантический слой — **полный переразбор документа в Worker — базовая и всегда корректная реализация** (main thread допускается < 256 КБ с debounce 120 мс; Worker 256 КБ–4 МБ, 400 мс; Worker+idle > 4 МБ, 800 мс; > 50 МиБ — потоковый read-only рендер по таблице порогов §12.7). Локальный переразбор одного блока — **оптимизация, разрешённая только при доказанном отсутствии межблочных зависимостей**: изменение не содержит и не затрагивает link/footnote reference definitions, открытие/закрытие fence, setext-подчёркивание, границы контейнеров (списки, цитаты), front matter, HTML-блоки. Кэш рендера блока инвалидируется не только по хэшу его исходника, но и по версиям глобальных зависимостей: таблицы definitions, набора сносок, embeds, профиля `flavor`, темы.
6. **DOC-017…020** Минимально-инвазивная сериализация: 85% операций — текстовые транзакции без сериализатора; структурные — один блок, `inferStyle` из документа (bullet, emphasis, strong, listItemIndent, incrementListMarker, fence, setext, closeAtx, table padding/align, stringLength по ширине в ячейках), постпроцессор лишних `\`, CI-гейт идемпотентности → иначе raw-блок.
7. **DOC-014** Lezer и micromark распознают одно множество конструкций; CI сравнивает границы блоков на корпусе.
8. **DOC-021 (переопределён §12.3) / DOC-023** Свойства файла сохраняются побайтово через `eolMap`; автоформатирования нет.
9. Undo: раздельных стеков нет — стек один, потому что модель одна (в отличие от R-14 в `02`, который предполагал ProseMirror).

## 18. Безопасность

Нормативно — `04` §6 (SEC-001…015) и `03` NFR-030…038. Markdown-файл — **недоверенный ввод**; XSS в WebView2 с доступом к Tauri IPC = доступ к файловой системе, поэтому санитизация — граница безопасности.

- Санитизация: `rehype-sanitize` (GitHub-схема с правками: без `style`, без `div`/`input` в схеме — генерируем сами; `data-s/data-e` разрешены) → второй рубеж **DOMPurify** перед вставкой в DOM; KaTeX/Shiki/Mermaid гидратируются **после** санитизации в созданные нами узлы; SVG Mermaid — через DOMPurify svg-профиль без `foreignObject/script/use/animate` (SEC-002…003).
- URL: запрещены `javascript: vbscript: data:` (кроме `img[src]` с `data:image/(png|jpeg|gif|webp|avif);base64` ≤ 4 МБ — **`svg+xml` запрещён**) `blob:` в href, `about: chrome: ms-*: search-ms: ms-msdt:`; проверка после нормализации через `new URL()` (SEC-004).
- Внешние изображения не грузятся; при разрешении — через Rust с лимитами 10 МБ/15 с/3 редиректа, только https, отказ приватным IP (SSRF) → `blob:` (SEC-005). Iframes/object/embed — вырезаются всегда (SEC-006).
- Лимиты DoS: KaTeX `maxExpand 500`, глубина блоков ≤ 100, узлов ≤ 500k, сносок ≤ 10k, front matter ≤ 256 КБ (SEC-007). **Прерываемость:** regex-поиск и семантический разбор выполняются в завершаемых Web Worker с бюджетом времени (regex 500 мс, разбор — по DOC-015); превышение → `Worker.terminate()`, UI остаётся отзывчивым. **Mermaid** требует DOM и в Web Worker не работает; поэтому: (а) рендер на главном потоке допускается только при входе ≤ 100 КБ и ≤ 2000 узлов диаграммы (предварительный подсчёт по тексту), иначе — исходник с пометкой `diagram too large`; (б) диаграммы рендерятся по одной, лениво при попадании во viewport, с `requestIdleCallback`; (в) спайк **S-8** проверяет рендер Mermaid в скрытом изолированном Tauri-webview (отдельный процесс WebView2, можно уничтожить по таймауту 3 с, результат — SVG-строка через IPC); если S-8 успешен — это основной путь и таймаут гарантирован, если нет — остаются лимиты (а)–(б) без временной гарантии, что фиксируется в OQ-31. DOM clobbering — `user-content-` префикс (SEC-008). HTML-комментарии — только парсером (SEC-009).
- **Tauri capabilities (IPC-права).** Санитизация HTML не ограничивает команды IPC, поэтому права задаются явно, per-window: основное окно — `fs:read/write` только через собственные команды `doc_open / doc_save / doc_read_asset`, принимающие **зарегистрированный `docId`** или путь, прошедший канонизацию и проверку принадлежности открытой библиотеке / папке открытого файла; `plugin-fs` напрямую из фронтенда **не разрешён**; `opener` — только `open_url(https|mailto)` и `reveal_item_in_dir(validated path)`; `http` — только Rust-команда `fetch_remote_image` с allowlist §11; `dialog`, `clipboard`, `window-state`, `store` — по необходимости, без wildcard-scope. Обязательны отрицательные тесты: попытка прочитать/записать путь вне выданных разрешений из webview → отказ.
- **`flavor.html`:** режима `raw` не существует; при `off` HTML показывается как экранированный текст, при `sanitized` — через два рубежа санитизации. Никакая настройка не отключает вырезание `script/style/iframe/object/embed/form/on*/srcdoc`.
- Asset protocol: scope в конфиге **пуст**, директория выдаётся динамически на открытую библиотеку; канонизация, запрет UNC, ADS, зарезервированных имён (SEC-010).
- YAML — безопасная схема, лимиты, значения в DOM только как текст (SEC-011).
- Навигация: webview никогда не уходит на внешний URL (`on_navigation` allowlist); внешние ссылки — системный браузер с подтверждением; `file://` — только «показать в папке»; исполняемые расширения не открываются; `rel="noopener noreferrer nofollow"` (SEC-012).
- CSP: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' asset: http://asset.localhost blob: data:; font-src 'self' asset: http://asset.localhost; media-src …; connect-src ipc: http://ipc.localhost; frame-src 'none'; object-src 'none'; worker-src 'self' blob:; form-action 'none'; base-uri 'self'` — без `unsafe-eval`, без CDN, всё бандлится локально (SEC-013). Сеть — только через `tauri-plugin-http`/Rust, не браузерный `fetch` (R-15).
- WebView2: DevTools off в релизе, свайп/пинч off, автозаполнение off, SmartScreen off (`IsReputationCheckingRequired = false`), `AllowExternalDrop` off с собственной обработкой drop (SEC-013, KEY-010…017).
- Логи без содержимого документов и путей (SEC-015). Плагинов нет → нет класса уязвимостей плагинов (NFR-038). Релизы подписаны, SBOM публикуется (v0.2, NFR-039).

## 19. Нефункциональные требования

Референсная машина: Windows 11 24H2, Ryzen 5 5600 / i5-12400, 16 ГБ, NVMe, 1920×1080 @100%; P50/P95 по 20 прогонам (`03` §9).

**Протокол измерений (обязателен для воспроизводимости):** версионированный бенчмарк-корпус в репозитории (`tests/bench/`): файлы 200 КБ / **512 КиБ** / 1 МБ / 5 МБ / 10 МБ / 50 МБ; состав каждого — 70% прозы (ru/en 50/50), 15% code blocks (5 языков), 8% таблиц, 4% списков с чекбоксами, 2% формул, 1% ссылок/сносок, 10 локальных изображений на 1 МБ; библиотека 1k и 10k файлов общим объёмом 12 и 120 МБ; фиксируется версия WebView2 Runtime и приложения. **Память** — везде в этом ТЗ под «RSS» понимается **сумма Private Working Set всех процессов приложения**, включая дочерние `msedgewebview2.exe`. **Границы операций:** старт — от `CreateProcess` до события `first-content-paint` (первый кадр с текстом документа, пишется в лог); открытие файла — от команды открытия до `first-content-paint` («первый кадр») и до события `render-complete` («полный»); NFR-004 измеряет первый кадр в read; переключение режима — от нажатия до `mode-switched`; сохранение — от `Ctrl+S` до ответа Rust. Тёплый кэш ОС, WebView2 user data folder уже создан (кроме метрики «первый запуск»); «CPU в покое» — среднее за 60 с при неактивном окне ≤ 0.5%; crash-free — доля сессий без падений на автоматизированном прогоне всех e2e-сценариев × 200 запусков (не «в поле»).

## 20. Тестирование и приёмка

- **Unit (Vitest):** CommonMark 0.31.2 spec (652) — на чистом парсере без расширений и санитизации; GFM spec — с включённым GFM-набором; профиль `plain` и безопасный DOM — собственный эталонный корпус снапшотов; тест-корпус TST-001…066 из `04` §5 (структурные ловушки, `$`-валюта, BOM/CRLF/cp1251, RTL, ZWJ-эмодзи, пути с кириллицей/пробелами/`../`/`file://`, кириллические якоря, цикл embeds, 5000 заголовков, бинарный `.md`) + инварианты на каждом файле корпуса: идемпотентность поблочной сериализации (DOC-020), no-crash, бюджет времени, санитизация, корректность offset'ов, совпадение границ блоков Lezer/micromark (DOC-014), word count против эталона.
- **Round-trip корпус:** 50+ реальных файлов (Obsidian vault, GitHub README, Typora-документы, Hugo с front matter); для каждого — набор правок в rich (bold, список, заголовок, таблица) → diff с оригиналом должен затрагивать только правленые строки.
- **E2E — три уровня исполнения:** (а) **Playwright через CDP к реальному WebView2** — всё, что внутри DOM: открытие библиотеки, чтение README, правка/сохранение, поиск, переименование с обновлением ссылок, клавиатурный обход, задачи, большие файлы, смена темы; (б) **Windows-harness (PowerShell/Rust-тест-раннер)** — то, что снаружи WebView: запуск двойным кликом/аргументом, single instance, внешнее изменение файла (git checkout при открытом файле), аварийное завершение — `TerminateProcess` главного процесса `plain.exe` (и отдельно всех `msedgewebview2.exe` дочерних) через 300 мс после последнего смоделированного нажатия; ожидаемый результат — при следующем старте черновик содержит ревизию не старше 1 с до завершения, экран `unsaved work found`; DnD из Проводника, always on top при 480px, DPI 150%; (в) **ручной чек-лист** — Win+Shift+S и вставка PNG с альфой, NVDA/Narrator, Snap Layouts. У каждого сценария указан исполнитель и проверяемый результат; сценарии UX-001…UX-108 распределены по релизам.
- **Приёмка Rich в MVP** — только два теста: байтовая целостность (ниже) и отсутствие потери ввода при IME-композиции; остальное — v0.2.
- **Контраст в CI:** все текстовые пары токенов ≥ 4.5:1 (ACC-008). **axe-core** на каждом экране. NVDA/Narrator — ручной прогон 4 сценариев (ACC-018).
- **Производительность в CI:** бенчмарк-сьют по NFR-001…029 на референсной конфигурации; регрессия > 15% блокирует релиз. В гейт MVP входят только метрики обязательных поверхностей (матрица ниже).
- **Сеть — два теста (NFR-030):** (1) базовый: `updates.check = off`, `remoteImages = block`, сетевой мониторинг процесса (ETW/`netsh trace` или фильтр WFP) — за сценарий «открыть библиотеку, читать, править, искать, экспортировать» **попыток** соединения 0 (не только успешных); (2) разрешённый: `updates.check = startup`, документ с внешней картинкой и нажатием `load` — попытки соединения только к заявленному хосту обновлений и к хосту картинки, ничего больше.
- **Байтовая целостность:** для каждого файла корпуса открыть → переключить все доступные для его размера режимы (по таблице §12.7) → сохранить без правок → байты идентичны (включая BOM, смешанные EOL, trailing spaces, финальный `\n`). Для файлов > 50 МиБ сохранение недоступно — проверяется только отсутствие изменений на диске после открытия.

**Матрица приёмки MVP** (релиз × режим × размер × обязательный тест):

| Поверхность / функция | Статус в MVP | Обязательные тесты MVP |
|---|---|---|
| Read | обязательна | все e2e Read, NFR-001…004/006/008, байтовая целостность, безопасность, a11y |
| Edit | обязательна | все e2e Edit, NFR-005/007/010, веха сохранности целиком (гонка записи, черновики, конфликт, EOL/кодировки) |
| Rich | экспериментальная | только байтовая целостность на файлах ≤ 512 КиБ и отсутствие потери ввода при IME; NFR-003(rich) — информационно, не гейт |
| Библиотека, quick search, global search (базовый синтаксис) | обязательны | e2e, NFR-009/025…028 |
| Replace across files, split, экспорт, печать, backlinks | v0.2 | не входят в гейт MVP |
| Файлы > 5 МиБ | large file mode | NFR-004 (read, первый кадр), отсутствие обрезания |
| Файлы > 50 МиБ | только просмотр | открытие ≤ 4 с, запрет редактирования с сообщением |
- **Отрицательные тесты безопасности:** попытка чтения/записи вне разрешённых путей через IPC, `javascript:`/`data:svg` в ссылках, `<script>` в HTML-блоке, внешние изображения при `block`, навигация webview на внешний URL — всё должно быть отклонено.
- **Приёмка релиза MVP:** все `[MVP]`-требования по Read, Edit, библиотеке, поиску и надёжности закрыты тестами (Rich — по сокращённому набору выше); чек-лист сценариев пройден на Windows 11 24H2 и Windows 10 22H2; NFR в допуске по протоколу §19; 0 известных дефектов с потерей данных.
